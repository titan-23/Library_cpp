# 日本語の基準

## 全体の基準

基準は次の 3 点である。

- 業務の仕様書や技術文書で普通に使用される書き言葉にする。
- 意味が一通りに伝わる表現にする。
- 内容を加えない文は記載しない。

書き言葉では硬すぎる表現と柔らかすぎる表現のどちらも避けるようにする。

| 区分 | 内容 | 例 |
|---|---|---|
| 柔らかすぎる表現 | 話し言葉、子ども向けの言い回し | 使う、直す |
| 適切な表現 | 漢語の動詞、定着した用語 | 使用する、修正する |
| 硬すぎる表現 | 造語、直訳、見慣れない言い回し | 正確評価する、検査点 |

判断に迷う場合は、公式ドキュメントの日本語版、Wikipedia、業務の仕様書でその表現が使用されているかを確認する。

以下の表と項目はこれまでに指摘を受けた表現の例である。表を参照するときは次の点に注意する。

- 表にない語も同じ原因に該当する場合は避ける。
- 表の語でも「箇条書き」「誤り確率」のように別の語の一部である場合や定着した表現である場合は、そのまま使用する。
- 表の語を避けるために、より硬い語や見慣れない語を使用しないようにする。「推奨表現」に適する語がない場合は文の構成を変更する。

## 不自然な表現の原因

### 英語の専門用語の直訳

英語の用語を 1 語ずつ和語や漢語に訳すと、日本語の技術文書では使用されない語になる。
その分野の日本語の文書で定着した語を使用する。定着したカタカナ語は日本語として扱い、そのまま使用する。

| 非推奨表現 | 推奨表現 |
|---|---|
| 費用、〜代 | コスト、〜のコスト |
| 罰、罰則 | ペナルティ、コスト |
| 整列 | ソート |
| 種 | シード |
| 窓 | ウィンドウ、区間、範囲 |
| 時計 | 時刻、経過時間、タイマー |
| 位相 | フェーズ、段階 |
| 指紋 | ハッシュ値、フィンガープリント |
| 採点 | スコアの計算、評価 |
| 抽選 | ランダムな選択 |
| 手 (近傍の手など) | 操作、近傍操作 |
| 枝 | 分岐、場合 |
| 入口、出口 | 開始、終了。何の開始と終了かを具体的に示す |
| 正本 | 原本、基準とするファイル |
| 要求 | 条件、制約 |
| 約束 | 保証、条件、仕様 |
| 証拠 | 根拠 |
| 検査 | 確認、判定、チェック |
| 無視 | 考慮しない、対象外とする、スキップする |
| 釣合い | バランス、均衡 |
| 飛び越す | スキップする |
| 割り引く | 減算する、小さくする |
| ビーム探索 | ビームサーチ |
| 検査点 | チェックポイント |
| ポインタ機械模型 | ポインタマシン |
| 入るとき、出るとき (木の走査) | 行きがけ、帰りがけ |
| 問い合わせ | クエリ |

### 造語

作業中に付けた呼び名や、助詞を省いて漢語を連結した語は、初めての読み手に意味が伝わらない。
概念の名前は基本的に原著や教科書にある語を使用する。該当する語がない場合は名前を付けず、助詞を補った句で説明する。

- 指摘された例：距離場、既定長、近傍殻、親順序領域、時刻枠、近傍抽選、支持要求
- 助詞を省いた例：「正確評価する」→「正確に評価する」
- 一般名詞を単独で用語にしない。修飾を付けるか、中身が伝わる名前にする。
  - 「対象」→「〜の対象」
  - 「情報」→ 何の情報かが伝わる名前
- 既存の語を一般の意味と異なる意味で使用しない。
  - 一般の意味が定着している語 (代入、逆算) を別の処理の名前にした場合

### 比喩

物や人の様子を表す語を、処理やデータの説明に比喩として使用せず、実際に何が発生するかを具体的に示す。

| 非推奨表現 | 推奨表現 |
|---|---|
| 静かに | 通知せずに、エラーを出力せずに |
| 壊れる | 不正な状態になる、成り立たなくなる、動作しなくなる |
| 効く | 有効である、効果がある、効果的である、影響する |
| 完走 | 最後まで実行する、実行が完了する |
| 正体 | 原因、内容 |

### 話し言葉と短い和語の動詞

短い和語の動詞と可能動詞は話し言葉に近く、技術文書には適さない。「追加する」のような漢語の動詞と「〜することができる」を使用する。

| 非推奨表現 | 推奨表現 |
|---|---|
| 変わる | 変化する、変更する |
| 足す | 加える、追加する |
| 挿す | 挿入する |
| 借りた | 借用した |
| 書き出す | 出力する、作成する |
| 書く | 記載する、出力する、更新する |
| 読む | 参照する、読み込む |
| 写す | コピーする、転記する |
| 集める | 収集する、集計する |
| 測る | 計測する、評価する |
| 数える | 集計する、個数を求める |
| 要る | 必要である、使用する |
| 誤る | 誤りが生じる、誤って〜する |
| 見ない | 参照しない、確認しない |
| 見落とす | 検出できない |
| 整う | そろう、条件を満たす |
| 就く | 担当する、割り当てられる |
| 試せる | 試すことができる |
| 減らせる | 減らすことができる |
| 守れる | 満たすことができる、維持できる |
| 作れる | 作成できる、作ることができる |
| 読めない | 読み取ることができない |
| 着ける | 到達することができる |
| 決まる | 定まる、求まる |
| 作り直す | 再構築する、再作成する |
| 分け直す | 再分割する |
| 置いていく | 配置する、挿入する |
| 書き込む | 記載する、設定する |
| 上書きする | 置き換える |
| 直す | 修正する。「求め直す」は使用してよい |
| 持つ、保つ | 保持する |
| 使う | 使用する |
| 比べる | 比較する |

示す、避ける、添える、補うのように書き言葉で定着した和語の動詞はそのまま使用する。

「〜る。」で終わる動詞が多いと不自然になる。ある程度は許容するが、続く場合は文末を見直す。

### 不自然な言い回し

個々の語は普通でも、組み合わせると日本語の文書では使用されない言い回しになる場合がある。

| 非推奨表現 | 推奨表現 |
|---|---|
| 〜だと分かる。 | 〜と判明する、〜を確認できる |
| 〜があると知る。 | 〜があることを確認する |
| 〜が決定になる。 | 〜が確定する、〜に決定する |
| 〜へ変えている。 | 〜に変更している |
| 自動で保つ | 自動的に維持する |
| 〜で仕上げる。 | 最後に〜する、〜を完成させる |
| 〜が並ぶ | 〜が続く、〜を列挙する |
| 処理の「経路」 | 処理、アルゴリズム |
| 行を〜する | 対象を具体的に示す。表の行を指す場合は使用してよい |
| 最後のもの | 最も新しいもの、末尾のもの。何の順で最後かを示す |
| 前後 (図や表を指す文) | 左右、上下 |
| 始め、終わり | 先頭、末尾、何番目か、〜の直前 |
| その場で | いつ、何を行うかを示す |
| すぐに分かる | 必要な時間や手段を示す |
| 〜を行った答え | 〜の答え |
| 複数の値の和、累積 | 総和、累積和 |

- 主語と述語を対応させる。
  - 「変化するのは A だけで、B が変化するとき」→「変化し得るのは A だけで、それも B が変化するときのみ」
- 補足を文から独立した断片として並べない。記号の説明は 1 文で完結させる。
  - 「$x$：条件を満たす値　なければ $x = \infty$」→「$x$：条件を満たす値で、なければ $\infty$ とする」
- 方針を述べる文を動詞の辞書形で言い切ると唐突になる。「〜ようにする」を補うか、対象を主題にする。操作や形式の指定は辞書形のままでよい。
  - 「A では B を避ける。」→「A では B を避けるようにする。」

### 不要な文とキャッチコピー

- 「〜ない。」で終わる文は不要な場合が多い。必要な文かを確認する。必要な場合も表現を適切に変更できないか検討する。
- スローガンやキャッチコピーに類する表現は一切不要である。
- 次の文と見出しも避ける。
  - 問いかけの形の見出し。見出しは内容を表す名詞句にする。「〜の流れ」「〜するもの」のような曖昧な語も避ける。
  - 要素を列挙して「〜でつなぐ」「〜を結ぶ」の形でまとめる文
  - 体言止めで言い切る文。述語まで記載する。
    - 「A に必要なのは、B」→「A を行うには B が必要である」
  - 予告だけの文
  - 作成者の事情を説明する文 (出典の節、作成の経緯)
  - 指摘に備えた断り書き

## 言い切りの強さ

言い切りの強さは根拠に応じて定める。根拠のある内容を弱めることも、例外のある内容を言い切ることも避けるようにする。

| 内容 | 扱い | 例 |
|---|---|---|
| 定義、証明した性質、仕様、確認した事実、規則 | 言い切る | 「A の計算量は $O(\log n)$ と考えられる。」→「A の計算量は $O(\log n)$ である。」 |
| 条件付きで成り立つ内容 | 条件や範囲を示して言い切る | 「A は B より高速である。」→「$n \le k$ の場合は A が B より高速である。」 |
| 人の受け取り方、効果、傾向についての一般化 | 程度を示す | 「読み手は A を覚えていない。」→「読み手は A を覚えているとは限らない。」 |

- 程度は「〜されやすい」「〜にくい」「〜とは限らない」「〜場合が多い」で示す。
  - 「A は B と受け取られる。」→「A は B と受け取られやすい。」
- 推測と未確認の内容は「〜と考えられる」のように推測であることを示す。
- 例外のある方針は「〜を基本にする」とする。

## 読点

読点は文の切れ目やかかり方を示すときだけ打つ。読点がなくても誤解が生じない箇所には打たない。

打つ箇所
- 2 つの述語の区切り
- 3 つ以上の並び
- 長い主題や条件の後
- 打たないと、かかり方が別の意味に解釈されるとき
- 「を」が 2 つ続くとき

打たない箇所
- 短い主題、条件、目的語の後
  - 「A を並べる場合は、B で区切る。」→「A を並べる場合は B で区切る。」
- 「と」でつないだ 2 つの名詞の間
- 名詞を修飾する句の途中

## 箇条書き

- 並列の項目は 1 つの文につなげずに箇条書きにする。
- 分かりやすくなる場合は箇条書きを使用する。箇条書きの比率だけを理由に地の文に戻さない。

## 括弧書き

括弧書きの補足は基本的に避ける。括弧にしてよいのは直前の語に短い語句や式を添える場合だけである。それ以外の内容は必要であれば本文の文か独立した行として記載し、不要であれば削除する。

| 扱い | 該当する内容 | 例 |
|---|---|---|
| 括弧のままにする | 別の表記、短い例、値や範囲、参照先 | 「挿入 (insert)」「定着している語 (A, B)」「整数 $k$ ($1 \le k \le n$)」 |
| 本文に記載する | 定義、前提、理由、例外 | 「$x$ を求める ($x$ は条件を満たす最小の値)」→「条件を満たす最小の値 $x$ を求める」 |
| 削除する | 言い換え、断り、作成の経緯 | 「A を更新する (つまり再構築する)」→「A を再構築する」 |

- 括弧の中に述語のある文を入れない。
- 判断に迷う場合は括弧にせず、修飾語か独立した文にする。

## 表記

- コードのコメントと docstring には句点を付けない。複数の文は行を分ける。
- 数字と英語の前後には半角スペースを入れる。
- 数式とインラインコードの前後にも半角スペースを入れる。
- 丸括弧は半角にする。日本語の文中では括弧の前後に半角スペースを入れる。
  - 「挿入(insert)」→「挿入 (insert)」
- 文字列や文字の記号を並べる場合はカンマで区切る。中黒は連結に受け取られる。
  - 「$u$・$v$」→「$u, v$」
- 記号には種類を添える。
  - 「$t$」→「時刻 $t$」

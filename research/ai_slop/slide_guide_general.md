# スライド作成のガイド

研究や技術の内容を説明するスライドを作成するときの手順と基準を示す。
日本語の表現は [memo.md](memo.md) の基準にしたがう。

## 1. 前提

スライドの分かりやすさは体裁よりも次の 5 点に左右される。
体裁が同じでも、この 5 点が不適切な資料は内容の薄い資料や AI が生成した資料と受け取られやすい。

- 説明の順序
- 記載する内容の選別
- 用語と記号
- 図と例
- 枠や色などの部品の役割

この文書の基準は次の 3 つの前提にもとづく。

- 聞き手は前のページの内容を覚えているとは限らない。各ページはそのページだけで意味が伝わるように作成する。
- 1 ページの内容が多いと、聞き手は要点を把握しにくくなる。1 ページで伝えることは 1 つを基本にする。
- スライドに記載するのは聞き手が理解に使用する内容である。作成者の事情や、指摘に備えた説明は記載しない。

各章の表は例である。表にない表現も同じ原因に該当する場合は避ける。

## 2. 作成の手順

ページの作成は手順 5 までを文章で終えてから開始する。
用語や説明の順序を後から変更すると全ページの修正になるので、手順 3 と手順 5 の一覧は依頼者に提示して同意を得る。

### 手順 1：聞き手と前提の確認

- 聞き手は誰か。すでに知っている内容は何か。
- 発表時間とページ数に制約はあるか。
- 口頭で補う内容と、スライドに記載する内容をどう区別するか。
- 目次、発表者ノート、補足のページは必要か。
- 手本にする資料はあるか。

### 手順 2：主張と説明の順序の決定

根拠の文書 (論文、証明、仕様) から次の内容を 1〜2 文ずつで記述する。

- 主張とその条件
- 主張を成立させる仕組みの全体
- 結論がその値や性質になる理由

続いて、聞き手に生じる疑問を列挙し、回答を用意する。回答は該当するページの本文に記載する。

- 何が与えられていて、何を求めるのか。
- なぜその方法にするのか。より単純な方法では何が不足するのか。
- なぜその結論になるのか。極端な場合にも成立するのか。

この段階で依頼者に内容を説明し、質問を受ける。依頼者の質問は聞き手に生じる疑問の候補になる。

### 手順 3：用語と記号の一覧の作成

次の形式の一覧を作成する。

| 用語・記号 | 意味 | 出所 | 初出のページ |
|---|---|---|---|

- 出所は原著、教科書、依頼者の既存の資料のいずれかにする。出所のない語は一覧に加えず、説明の句で代替する。
- 記号は複数のページで繰り返し参照するものに限定する。

### 手順 4：例の決定

- 資料全体で使用する例を 1 つ決定する。
- 構造を示す部分には構造を確認することができる規模の図を用意する。
- 数値は主張を一目で確認できるものにする。
- 例の各状態を手で計算し、根拠の文書と照合する。

### 手順 5：ページの一覧の作成

次の形式の一覧を作成する。

| ページ | 題 | 伝えること (1 文) | 最初の行 | 図 | 初出の用語・記号 |
|---|---|---|---|---|---|

一覧の段階で次の点を確認する。

- 各部の最初のページで主張と全体の動きを示している。
- 題と本文で使用する用語と記号はすべてそのページまでに定義してある。
- 手順の番号ごとに、説明するページか場所がある。
- 各ページの「伝えること」が 1 文である。2 文になるページは分割する。

### 手順 6：ページの作成

- 第 4 章のページの型と第 9 章の書式にしたがう。
- 文の幅を計測してから、枠の幅と改行の位置を決定する。

### 手順 7：提示前の確認

- 第 12 章の項目を全ページで確認する。
- 描画した画像を全ページで確認する。表示の方法が複数ある場合はそれぞれで確認する。

### 手順 8：指摘の反映

指摘の反映は第 11 章にしたがう。

## 3. 構成

### 3.1 説明の順序

- 各部の最初のページで主張と全体の動きを示す。部品は必要になったページで説明する。部品を順に説明する構成では、各部品を何に使用するのかが後のページまで不明なままになる。
- 「何があれば目的を達成できるか」を先に示し、「それをどのように用意し、維持するか」を後に示す。
- 仕組みが保持する情報や構成要素は最初のページですべて示す。新しい要素が後のページで順に追加される構成では、全体の把握が難しくなる。
- 複数の部がある資料は各部を同じ形にする。聞き手は 2 つ目の部で説明のどの段階にいるかを判断しやすくなる。

### 3.2 定義と例の位置

- 定義は名前を示した直後のページで一度だけ行う。
- 定義していない語は題、本文、要点のどれにも使用しない。
- 仮定と前提は主張の前に配置する。
- 主張、定義、式を先に配置し、例はその後に配置する。分かりにくい場合も例を先にせず、式の直下に例を配置して補う。
- 例は状況、発生すること、具体的な数値の順に導入する。

### 3.3 手順の示し方

- 手順の一覧を先に示す。各手順のページは一覧と同じ文で始める。
- 一覧の前に、何を求めるための手順かを述べる。
- 手順の文は同じ形に統一する。
- どの番号にも説明するページか場所を用意する。

### 3.4 概念と道具の導入

- 新しい概念はその概念がない場合に発生する問題を示してから定義する。
- 道具を導入したら、より単純な方法では不足する理由を示す。
- 問題提起だけのページは作成しない。別の方法と比較して理由を示すページにする。
- 説明の中心になる構造は方針のページで定義する。実現に使用する道具は理由とともに名前を示し、直後のページで定義する。説明していない仕組みの名前だけを並べることは避ける。

### 3.5 全体像

- 個々の手順を説明する前に、全体を 1 ページの図で示す。
- 図は構成要素とその関係だけにする。個別の要素の詳細は別のページに記載する。
- 実行例には全体像と同じ配置の図を使用する。

### 3.6 ページの分割と統合

- 定義、規則、例、評価は、役割ごとにページを分ける。
- 理解しにくい説明は分割する。1 ページに収めるために説明を省略しない。
- 新しい説明を作成したら、同じ内容の古いページを削除する。ページを追加したら、前後のページに残る同じ内容の要約を削除する。
- 同じ内容を示す例のページは 1 つにする。

### 3.7 冒頭・まとめ・補足

- 資料で示す結果は冒頭に表か 1 文で示す。
- 各部の最後に同じ形のまとめを配置する。まとめには本編と同じ文を使用する。
- 本筋から外れる比較と、保証の細かい仮定は、補足のページに移す。補足のページは題で補足であることを示す。
- 質疑に備えた補足は、依頼者が求めた場合に作成する。

## 4. 1 ページの組み立て

### 4.1 伝えること

- 1 ページで伝えることを 1 文に決定する。その 1 文に使用しない内容は別のページか口頭に移す。
- 規則を説明するページには規則だけを記載する。実現の方法と性能はそれを主題とするページで扱う。

### 4.2 最初の行

最初の行でそのページの目的を述べる。手順の文を並べただけのページでは、何のための手順かが伝わらない。

| ページの種類 | 最初の行で述べること |
|---|---|
| 手順、処理 | 何のために何をするか |
| 入力から出力を求める処理 | 何から何を求めるか |
| 定義 | 定義する対象が必要になる理由 |
| 説明の途中のページ | ここまでに求まっているものと、次に調べるもの |

### 4.3 本文と図の分担

- 本文には目的、理由、方針を記載する。手順の細部は図で示す。
- その手順にする理由を本文に記載する。操作を列挙するだけでは、なぜその操作にするのかが伝わらない。
- 加えた文から新しい疑問が発生する場合は同じページで回答する。

### 4.4 ページの型

題の下の部品は次の順に配置し、該当しない部品は省略する。

| 型 | 上から順に配置する部品 |
|---|---|
| 方針 | 主張 → 何が求まればよいか → 中心になる構造の定義と図 → 性質 → 結論 |
| 定義 | 動機の 1 行 → 定義 → 使用方法の 1 行 → 図 |
| 手順 | 手順の文 → 前のページの記号の確認 → 何から何を求めるか → 理由 → 手順 → 図 → 要点 |
| 理由 | 問題になる点 → 別の方法と比較する図 → 要点 |
| 実行例 | 全体像と同じ図 → 手順の文と例での動作 |
| 部のまとめ | 主張 → 構成要素 → 手順 |

### 4.5 要点の行

- 最後の行にそのページの要点を 1 行で示す。理由と結論を 1 文で述べる。
- 予告、言い換え、問題提起、一般的な標語は要点にしない。
- 要点の行は最後の本文の行の直後に配置する。
- 定義だけのページには配置しなくてよい。

### 4.6 題

- 題は内容を表す名詞句にする。問いかけ、曖昧な語、文の形は避ける。
- 何についてのページかを題に含める。
- 部の名前を前に配置する。
- 手順のページの題は手順の文に対応させる。

## 5. 記載する内容の選別

### 5.1 判断の方法

各行について次の 5 点を確認する。1 つでも該当する行は削除する。

1. そのページで伝える 1 文に使用しない。
2. 図、定義、前の行から分かる内容の言い換えである。
3. 作成者の事情の説明である。
4. 指摘や誤解に備えた断り書きである。
5. 口頭で補えば足りる細部である。

次の内容が欠けている場合は加える。

- 目的と、何から何を求めるか
- その手順にする理由
- 結論の根拠になる前提
- そのページで使用する記号の意味

判断に迷う補足は省略する。理由があって残した補足も聞き手には不要である場合が多い。

### 5.2 記載しない内容

| 原因 | 例 |
|---|---|
| 図や本文の言い換え | 図の内容を文で繰り返す一文、定義を言い換えただけの行、同じ内容の 2 行 |
| 図の読み方の説明 | 色の凡例、図で省略したものの注記、枠や行の意味の説明 |
| 作成者の事情の説明 | 出典の節や表の番号、原著との対応、作成の経緯、ページ番号による参照、補題の番号 |
| 断り書き | 主張に使用しない留保、否定形の補足 |
| 自明な内容 | 名前から意味が分かる語の定義、結果が自明な例と計算 |
| 証明と実装の細部 | 導出の途中の式、実装上の処理、準備の時間 |
| 本筋から外れる補足 | そのページで使用していない文献、関連する別の結果への言及 |
| キャッチコピーに類する表現 | 問いかけの題、末尾の一般的な標語、予告の文、体言止めの言い切り、読点の多い文 |
| 役割を決定していない装飾 | 意味のない色付け、要点ではない語の強調、項目を囲む枠、副題、灰色の小さい文字 |

色と枠の意味は図と本文から分かるようにする。説明がないと伝わらない図は修正する。
原著との照合の結果と出典の節は資料の README に記録する。

### 5.3 記載する内容

- 目的と、何から何を求めるか
- その手順にする理由
- 結論の根拠になる前提。何をいつ用意しているかを含む。
- 結論が成立する理由。極端な場合にも成立することを示す。
- 誤解を防ぐ 1 文
- 既知の道具の名前と文献
- 規則に対応する小さい表や図

### 5.4 口頭と補足へ移す内容

| 移す先 | 内容 |
|---|---|
| 口頭 | 簡単な証明、個数の導出、伝わりにくい理由の補足 |
| 補足のページ | 先行手法との比較、保証の仮定 |
| 表の下の 1 行 | 記号の意味、保証の種類 |

## 6. 用語・記号・定義

### 6.1 用語

- 概念に独自の名前を付けない。原著、教科書、依頼者の既存の資料にある語を使用する。該当する語がない場合は名前を付けず、作り方と使用方法を句で説明する。
- 用語は聞き手にとって自然かどうかで決定する。ほかの文書との整合は不自然な語を残す理由にならない。
- 定義の行を追加しないと使用できない語は、定義済みの語で代替する。
- ほとんど使用しない用語は定義を省略する。

| 避ける名前 | 対応 |
|---|---|
| 作成中に付けた呼び名、直訳の語 | 文献にある語にする。なければ句で説明する |
| 単独の一般名詞 (対象、組、情報) | 修飾を付けるか、固有の名前にする |
| 中身が分からない名前 (補助情報) | 中身や位置が伝わる名前にする |
| 内部の表現の語 | 聞き手が考えている対象の語にする |
| 分野の俗称 | 書誌の名前にする |

### 6.2 定義

- 定義、定理、補題は、枠の中に正確に記載する。定義する語は強調し、英語は原著の用語だけを補う。
- 対象を先に述べる。定義の中では定義済みの語だけを使用する。
- 概念は本来の作り方で定義する。性質による言い換えは定義の後に添える。
- 存在が自明でない対象は作成の手順で示す。
- 何を記録し、何を表すかから定義する。形式だけの定義は記憶に残りにくい。
- 定義は常に成立する形にする。作成した直後にだけ成立する性質は定義と手順に分ける。
- 定義の前に動機を、後に使用方法を配置する。

### 6.3 記号

- 記号は繰り返し参照するものに限定する。1 か所でだけ使用する記号は言葉にする。
- 記号は名前と対応する文字にする。同じ種類の値は同じ形の記号にする。
- 別のものには別の文字を使用する。
- 記号には種類を添える (時刻 $t$、文字列 $u, v$)。
- 記号の説明は 1 文で完結させる。

### 6.4 前のページの内容の再掲

- 前のページで定義した記号を使用するページでは、その意味を確認用の枠に記載する。新しい定義と区別するため、本文とは別の枠にする。
- 例の前提は使用するページごとに再掲する。
- 前のページの番号や手順の番号だけで参照しない。内容を記載する。
- まとめのページでも、使用する記号の意味を記載する。

### 6.5 種類と粒度の統一

- 1 列に並べた箱と表の 1 列には同じ種類の値だけを記載する。
- 並列の要素は同じ粒度にする。1 つの要素にだけ詳細を記載しない。
- 列挙の順は定義のページの順に統一する。

### 6.6 用語の変更

- 決定した用語や提案していた案を変更する場合は理由を説明する。
- 変更は全ページに適用し、派生する語も変更する。

## 7. 文

語の基準は [memo.md](memo.md) にある。スライドでは次の点も確認する。

### 7.1 主語と対象

- 何が何をするかを確認する。動作の主体にならないものを主語にしない。
- 「1 回」「1 個」は何の個数かを示す。
- 枠に収めるために、必要な語を削らない。理由を示す語は文字を小さくしてでも残す。
- 指す対象を具体的に示す。「など」で省略しない。
- 向きや順序を表す語は図と一致させる。二通りに解釈できる語は避ける。
- 曖昧な評価 (すぐに、簡単に) は時間や回数で示す。

### 7.2 改行と読点

- 改行は文と句の切れ目だけにする。折り返しは自動に任せ、位置は枠の幅で調整する。
- 2 行に分ける場合は各行を完結した文にする。
- 並列の項目は箇条書きにする。まとめは 1 項目を 1 行にする。
- 読点は文の切れ目とかかり方を示す場合だけにする。短い主題、条件、目的語の後には打たない。
- スライドの本文では句点を省略する。

### 7.3 例の説明と表記

- 例の説明は規則の条件と同じ表現にし、結論の直接の理由を示す。
- 記号を並べる場合はカンマで区切る。中黒は別の演算に受け取られる場合がある。
- 括弧書きの補足は基本的に避ける。別の表記、短い例、値や範囲、参照先のように直前の語に短い語句や式を添える場合だけ括弧にしてよい。
- 定義、前提、理由、例外は本文の文か独立した行として記載する。言い換え、断り、作成の経緯は削除する。
- 括弧の中に述語のある文を入れない。判断に迷う場合は括弧にせず、修飾語か独立した文にする。

### 7.4 言い切りの強さ

- 言い切りの強さは根拠に応じて定める。
- 定義、証明した性質、仕様、確認した事実は言い切る。「〜と考えられる」のような語で弱めない。
- 条件付きで成り立つ内容は条件や範囲を示して言い切る。「高々」「最悪」「高確率で」のような限定の語で示す。
- 聞き手の受け取り方や説明の効果についての一般化は、「〜されやすい」「〜にくい」「〜とは限らない」で程度を示す。
- 推測と未確認の内容は推測であることを示す。例外のある方針は「〜を基本にする」とする。

## 8. 図・表・例

### 8.1 図と表の使い分け

- 動きと規則は図で示す。
- 場合分けの表は規則 1 つと例に置き換えることができないかを検討する。
- 処理の順序は、左から右、または上から下に配置した図で示す。
- 表は比較と一覧が主題のページで使用する。

### 8.2 例

- 構造を示す例は構造を確認することができる規模にする。小さすぎる例では、区切りや繰り返しの構造が伝わらない。
- 小さい例で足りる部分と規模が必要な部分を区別する。規模が必要な部分は中身を省略した図にする。
- 数値は主張を一目で確認できるものにする。
- 資料全体で同じ例を使用する。
- 示したい現象が発生する例にする。
- 場合分けと例を 1 対 1 に対応させる。
- 同じ内容を示す例と、手順を順に確認するだけの例は省略する。
- 実行例は 1 つの操作を手順のとおりに示す。

### 8.3 図の統一

- 軸の向きを資料全体で統一する。
- 同じ図を複数のページで使用する。要素の大きさと間隔も統一する。
- 図が実際と異なる構造に受け取られる場合は、図の下に何の図かを記載する。
- 1 つの図の矢印は 1 つの意味にする。
- 例の図は本文の手順のどの段階の状態かを統一する。

### 8.4 色と吹き出し

- 色の意味を資料全体で固定する。
- 吹き出しは図や表の一部を指す補足だけに使用する。ページの主題にあたる説明は本文に記載する。
- 吹き出しには枠線を付ける。幅は文の幅に合わせ、先端は短くする。指す先が遠い場合は指す先を吹き出しの近くへ移動する。
- 理由が伝わりにくい吹き出しは削除し、口頭で補う。

### 8.5 表

- 表の中の式は 1 行に収める。
- すべての列が同じ値になる行は表の下の 1 行にする。
- 前提の異なる値は列を分ける。
- 行の順は定義のページの順にする。

## 9. 書式

### 9.1 部品の役割

枠と色の役割は 1 つずつに固定する。既存の資料は次の割り当てを使用している。新しい資料でも理由がなければ同じ割り当てにする。

| 部品 | 役割 |
|---|---|
| 淡い緑の枠 | 定義、定理、補題、仮定 |
| 灰色の箱 | そのページが説明する手順 |
| 薄い水色の枠 | 前のページの定義、記号、結論の確認 |
| 吹き出し | 図や表の一部を指す補足 |
| 赤の太字 | 要点の 1 行と初出の用語 |
| 青緑の太字 | 項目名、ページ内の小見出し |
| 黒の太字 | 定義の中で注意が必要な条件 |

### 9.2 文字の大きさ

| 大きさ | 用途 |
|---|---|
| 36 pt | 題 |
| 20 pt | 本文、箇条書きの第 1 段 |
| 18 pt | 箇条書きの第 2 段、確認用の枠、吹き出し、図のラベル |
| 16 pt | 箇条書きの第 3 段、表の下の補足 |
| 14 pt | 図の注記 |
| 12 pt | 書誌 |

- 箇条書きは段ごとに 2 pt 小さくする。文の形で示す文字の下限は 16 pt である。
- 同じ種類の文字はページの中で同じ大きさにする。収まらない場合は文を短くするか、同じ種類の文字をまとめて小さくする。
- 対になるページは同じ大きさにする。

### 9.3 強調と色

- 強調は要点の 1 行と初出の用語に限定する。1 ページに 1〜2 か所を目安にする。
- 文字に灰色を使用しない。補足は文字を小さくし、重要な内容は黒にする。

### 9.4 行頭と配置

- 「項目：本文」の本文が 2 行以上になる場合は、2 行目以降もコロンの後の位置から始める。
- 下位の行は字下げする。
- 書誌は全ページで同じ高さに配置する。
- 補足は図の横などの空いている場所に配置する。

## 10. 正確さと出典

- 強調した文は特に正確に記載する。「高々」「最悪」などの限定の語を確認する。
- 数と項目を一致させる。
- 結論は理由とともに示す。
- 保証を表す語は根拠の文書にある範囲で使用する。根拠にない保証は根拠の文書に加えるか、仮定を示す。
- 例は手で計算して照合する。
- ページごとの根拠の節は資料の README に記録する。
- 既知の概念と技法には文献を示す。文献は原著で確認し、確認した範囲を記録する。仕組みが同じではない場合はその差が分かる表現にする。
- 未完成の文書を根拠にしない。
- 別の視点のレビューを受ける。指摘は根拠の文書と照合し、採否は依頼者が決定する。

## 11. 作業の進め方

- 構成、用語、文言の変更は、案を提示して同意を得てから成果物に反映する。
- 質問には回答だけを返す。成果物の修正は指示を受けてから行う。
- 判断を質問された場合は理由を付けた見解と代替案を返す。
- 修正は依頼された成果物に限定する。書式は依頼された箇所だけを変更する。
- 依頼者の文案はそのまま採用することを基本にする。語を変更する場合は理由を同時に示す。
- 1 件の指摘は規則として扱い、同種の箇所すべてに適用する。適用した範囲を報告する。
- 前のページを変更したら、後続のページの前提を確認する。再構成の後は元の内容がすべて含まれているかを確認する。
- 大きな変更は既存のページを残して別のページに試作する。比較した後で置き換える。
- 提示の前に作成者が全ページを確認する。初めて聞く人がそのページだけで理解できるかを基準にする。
- 決定は理由とともに資料の README に記録する。不要とされたものは、「使用しない」という注記も含めて削除する。
- 確認の進め方は依頼者が決定する。次のページへ進むことを作成者から促さない。

## 12. 提示前の確認項目

### 12.1 資料全体

1. 各部の最初のページで主張と全体の動きを示している。
2. 用語と記号が手順 3 の一覧と一致している。1 つの概念の呼び名は 1 つである。
3. 題、本文、要点で使用する用語と記号は、すべてそのページまでに定義してある。
4. 手順の一覧の文と、各ページの手順の文、まとめの文が同じである。
5. 同じ内容のページと役割の重なるページを削除してある。
6. 枠、色、文字の大きさ、引用の形式が全ページで同じ規則にしたがっている。

### 12.2 各ページ

1. 伝えることを 1 文で述べることができる。
2. 最初の行が目的を述べている。
3. 使用する記号と用語の意味をそのページの中で確認することができる。
4. 各行が第 5.1 節の判断を満たしている。
5. 強調が要点の 1 行と初出の用語だけである。
6. 題が内容を表す名詞句である。

### 12.3 文と図

1. [memo.md](memo.md) の基準を満たしている。
2. 改行の位置が文と句の切れ目である。
3. 軸の向き、色の意味、箱の中身の種類が全ページで同じである。
4. 例の数値から主張を一目で確認できる。
5. 色の凡例、図の読み方の説明、省略したものの注記を削除してある。

### 12.4 書式と根拠

1. 同じ種類の文字がページの中で同じ大きさである。
2. 描画した画像で、文字の欠け、領域の超過、重なりがない。
3. 主張、数値、強調した文が根拠の文書と一致している。
4. 例の状態を手で計算した結果と図が一致している。
5. 引用した文献を原著で確認している。

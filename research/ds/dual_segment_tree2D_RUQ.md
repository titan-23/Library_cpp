# dual_segment_tree2D_RUQ.cpp

## 計算量

- 元のコメントは空間計算量を O(hw) としていました。既定の実装は apply のたびに値を data へ 1 つ追加するため、apply の回数を q とすると空間計算量は O(hw + q) です。
- LARGE_QUERY を定義した実装は各ノードに時刻と値の組を保持し、空間計算量は O(hw) です。
- get と apply の時間計算量は O(log(h)log(w)) です。
- 空間の見積もりとして、元のコメントには `4hw*sizeof(int)*sizeof(T)` と記載されていました。

## 高速化の余地

- クエリが少ない場合はタイムスタンプの型を short などにする方法があります。
- LARGE_QUERY を定義すると、各ノードに時刻と値の組を保持する実装に切り替わります。クエリの数が n より十分大きい場合は、有効にすると高速になる可能性があります。この定義はコード中でコメントアウトしています。

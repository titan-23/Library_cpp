# dual_segment_tree2D_RUQ.cpp

## 計算量

- 元のコメントは空間を O(hw) としていた。既定の実装は apply のたびに値を data へ 1 つ追加するため、apply の回数を q として空間は O(hw + q) である。
- LARGE_QUERY を定義した実装は各ノードに時刻と値の組を持ち、空間は O(hw) である。
- get と apply の時間は O(log(h)log(w)) である。
- 空間の見積もりとして、元のコメントには `4hw*sizeof(int)*sizeof(T)` と書かれていた。

## 速くする余地

- クエリが少ないときは、タイムスタンプの型を short などにする手がある。
- LARGE_QUERY を定義すると、各ノードに時刻と値の組を持つ実装に切り替わる。クエリの数が n より十分大きいときは、有効にすると速いかもしれない。この定義はコード中でコメントアウトしてある。

# dynamic_lazy_segment_tree.cpp

## 前提

- 管理範囲は [0,N) です。値が一様な区間の境界を Patricia 木で管理します。
- composition(f,g) は g の後に f を適用する作用です。
- pow(x,k) は x を k 個結合した値を返し、pow(x,0)==e() を満たします。
- T の等値比較は不要です。値が等しくなった隣接区間は自動的には結合しません。

## 計算量の前提

- N は列の長さ、M は保持しているノード数、M_other はコピー元またはムーブ元のノード数を表します。
- T と F の演算、コピー、ムーブ、破棄と、pow、述語の評価は O(1) とします。
- ノードの追加を含む計算量は償却計算量です。

## ノード数

- 区間数 B に対してノード数は 2B-1 個です。B=0 の場合のノード数は 0 個です。
- 同じ境界への更新と問い合わせではノードを追加しません。
- 保持するノード数の上限は 2^31-1 個です。

## ノードの表現

- 葉と分岐ノードを別々のプールに保持します。葉が保持するのは 1 要素の値と区間長だけです。
- 分岐ノードの右端は保存せず、下降時に親から引き継ぎます。
- 型のアライメント要件に応じて、分岐ノードのメンバーの配置のうちサイズが小さくなるものを選択します。サイズを増やさずに格納できる場合は分岐ビットも保持します。
- ノード番号は 0 がノードのない状態、奇数が葉、正の偶数が分岐ノードを表します。右の子の番号の最上位ビットは遅延フラグとして使用します。

## inner_prod の実装

- l と r が別の子に分かれた後は、左端側と右端側の経路を同じループで下り、2 つの経路の読み出しを並行して行います。
- inner_prod が呼び出し元のループにインライン展開されると、測定では 5% ほど遅くなりました。そのため `[[gnu::noinline]]` でインライン展開を抑止しています。

## 探索スタック

- max_right と min_left の探索スタックは、添字型のビット幅と同じ個数の探索状態を格納できる領域を確保します。
- 同時に存在する探索状態は最大 O(logN) 個です。
- SearchStack は F のデフォルトコンストラクタを必要とせず、使用する探索状態だけを構築します。
- SearchStack の破棄にかかる O(P) の P は、保存している探索状態の数です。

# hungarian.cpp

## 方式

- 最短増加路を使う方式で解く。左の頂点を 1 個ずつ加え、Dijkstra 法で空いている右の頂点までの最短路を探して割当を増やす。
- 左の頂点は行と列のうち少ない方で、右の頂点は多い方である。行が列より多いときは費用行列を転置して持つ。
- 費用行列はコンストラクタで連続した配列に写す。一時オブジェクトから作っても、参照先を失わない。

## 双対の更新を遅らせる

- 一般的な実装は、Dijkstra 法の 1 段ごとに全ての右の頂点の距離を減らし、木に入った頂点のポテンシャルを更新する。
- ここでは段ごとの最短距離の累積 D を持ち、key[j] に「距離 + D」を入れる。全要素を減らす処理がなくなり、1 段は 1 回の走査で済む。
- 右の頂点が木に入ったときの D を記録し、増加路が見つかった時点で、木に入った頂点だけポテンシャルを直す。
- 走査は 1 行を読み、key と way を更新しながら最小の key と番号を求める。この走査を SimdVec で行う。
- 木に入った右の頂点は key を INF にし、active のマスクで更新から外す。整数でも浮動小数点でも同じ形で書ける。

## 初期化と同点の扱い

- 各行の最小値を行のポテンシャルにし、最小値の列のうち空いている列に貪欲に割り当てる。
- 最小の key を持つ列が複数あるとき、番号の小さい列が割当済みだと、空いている列があっても探索が続く。費用が 0〜9 の行列では、これで変更前より 2.4 倍遅くなった。
- 最小の key を持つ空いている列があればそちらで終える。空いている列の一覧を見る手間が走査に近くなるので、空いている列が列数の 4 分の 1 以下のときだけ見る。

## SIMD

- 既定ビルドでは int, float, double を SSE2 で処理する。long long は SSE2 に 64 bit の比較がないので逐次になる。
- 更新がある組だけ書き戻す形と、浮動小数点で木に入った列の key を NaN にして active を読まない形も試した。前者は分岐予測の失敗で 10〜30% 遅く、後者は差がなかった。

## 計測 (2026-11-13)

- CPU は AMD Ryzen Threadripper 3990X (Zen 2)、コンパイラは GCC 12.3.0、`-std=c++20 -O2 -DNDEBUG`。

- 変更前の時間の約 40% は、等号で判定する辺の表を増加路ごとに作り直す処理だった。候補の更新だけを SIMD にしても効果が小さいので、方式を変えた。
- 逐次のままの新方式でも、1000×1000 の ll は 35 ms で、変更前の 17 倍速い。SIMD の効果は native で 2.3〜4 倍、既定ビルドの int と double で 1.7〜2.2 倍である。
- 最適な割当が複数あるとき、返す割当は変更前と異なることがある。費用は同じである。

## 検証

- [test/graph/hungarian_random.cpp](../../test/graph/hungarian_random.cpp) で、9×9 以下の行列を部分集合 DP の総当たりと比べる。long long, int, unsigned long long, long double, double, float を含む。
- 既定ビルド、x86-64-v2、native、SIMD なし、AddressSanitizer と UndefinedBehaviorSanitizer 付きの既定ビルドと native の 6 構成で通った。
- 誤りを 9 通り入れ、それぞれが通る経路を持つ構成でテストが失敗することを確かめた。active のマスクを外す、ポテンシャルの符号を誤る、詰め物の列を有効にする、増加路の付け替えを誤る、転置時の総費用の添字を誤る、key を戻さない、累積距離を落とす、などである。

# hungarian.cpp

## 方式

- 最短増加路を使用する方式で解きます。左の頂点を 1 個ずつ追加し、未割当の右の頂点までの最短路を Dijkstra 法で求めて割当を増やします。
- 左の頂点は行と列のうち少ない方、右の頂点は多い方です。行が列より多い場合はコスト行列を転置して保持します。
- コスト行列はコンストラクタで連続した配列にコピーします。一時オブジェクトから作成しても参照先は無効になりません。

## 双対の更新の遅延

- 一般的な実装は Dijkstra 法の 1 ステップごとに全ての右の頂点の距離を減らし、木に入った頂点のポテンシャルを更新します。
- ここではステップごとの最短距離の累積和 D を保持し、key[j] に「距離 + D」を格納します。全要素の値を減らす処理が不要になり、1 ステップは 1 回の走査で完了します。
- 右の頂点が木に入ったときの D を記録し、増加路が見つかった時点で、木に入った頂点だけポテンシャルを更新します。
- 走査ではコスト行列の 1 行を参照し、key と way を更新しながら最小の key とその番号を求めます。この走査を SimdVec で実行します。
- 木に入った右の頂点は key を INF にし、active のマスクで更新の対象から除外します。この処理は整数でも浮動小数点でも同じ形で記述できます。

## 初期化と同点の扱い

- 各行の最小値をその行のポテンシャルにし、最小値の列のうち未割当の列に貪欲に割り当てます。
- key が最小の列が複数あり、番号の小さい列が割当済みである場合は、未割当の列があっても探索が続きます。コストが 0〜9 の行列では、これが原因で変更前より 2.4 倍遅くなりました。
- key が最小である未割当の列があれば、その列で探索を終了します。未割当の列の一覧を確認する処理量が走査の処理量に近くなるため、未割当の列が列数の 4 分の 1 以下の場合だけ確認します。

## SIMD

- 既定のビルドでは int, float, double を SSE2 で処理します。long long は、SSE2 に 64 bit の比較がないため逐次処理になります。
- 更新のある組だけを配列に格納する方法と、浮動小数点で木に入った列の key を NaN にして active を参照しない方法も試しました。前者は分岐予測の失敗により 10〜30% 遅く、後者は差がありませんでした。

## 計測 (2026-11-13)

- 変更前の実行時間の約 40% は、等号で判定する辺の表を増加路ごとに再作成する処理が占めていました。候補の更新だけを SIMD で処理しても効果が小さいため、方式を変更しました。
- 新方式は逐次処理のままでも 1000×1000 の ll が 35 ms であり、変更前の 17 倍高速です。SIMD の効果は native で 2.3〜4 倍、既定のビルドの int と double で 1.7〜2.2 倍です。
- 最適な割当が複数ある場合、返す割当は変更前と異なることがあります。コストは同じです。

## 検証

- [test/graph/hungarian_random.cpp](../../test/graph/hungarian_random.cpp) で、9×9 以下の行列について部分集合 DP による総当たりの結果と比較します。テストには long long, int, unsigned long long, long double, double, float の各型を含みます。
- 既定のビルド、x86-64-v2、native、SIMD なし、AddressSanitizer と UndefinedBehaviorSanitizer 付きの既定のビルドと native の 6 構成でテストに合格しました。
- 誤りを 9 通り埋め込み、誤りのある処理が実行される構成でそれぞれテストが失敗することを確認しました。埋め込んだ誤りには次のものがあります。
  - active のマスクを外す
  - ポテンシャルの符号に誤りを入れる
  - パディングの列を有効にする
  - 増加路の付け替えに誤りを入れる
  - 転置時の総コストの添字に誤りを入れる
  - key を戻さない
  - 累積距離を省く

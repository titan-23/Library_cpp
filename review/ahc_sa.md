### 正しさに関する問題

- `sa/sa.cpp:151-176,216-231`: `sa_multi_run` は `NUM_STARTS<=0` の場合に、時間配分のゼロ除算、初期化されていない最良状態と最良結果の参照、または負値による不正な処理を起こします。
- `sa/sa.cpp:343-380`: `replica_run(...,NUM_REPLICAS<=0)` では、空の `vector` に対する `states[0]` / `scores[0]` の参照、または負値に起因する巨大な領域の確保が発生します。
- `sa/sa_state.cpp:31-35,63-67` の配布用の雛形は、`TYPE_CNT=0` であり、`changed.type` が未初期化で、`modify` が空です。`sa.cpp:48,78-86,234,258-267,370-374,431-444` は `type` を統計配列の添字に使用するため、雛形のままでは未定義動作になります。雛形の遷移の種類を 1 つ以上にし、実行側でも `type` の範囲を確認する必要があります。
- `tsp/examples/sa_tsp.cpp:78-90,217-221` は `N<=3` のとき `valid=false` だけを設定するため、上記の種類別の統計で未初期化の値を参照します。

- `sa_run` と `sa_multi_run` は `END_TEMP<=0` を `1e-9` に丸めますが、正でない、または有限でない `START_TEMP` と、NaN または正の無限大の `END_TEMP` はそのまま残ります。`replica_run` の `:320-353,502-510` は開始温度と終了温度を丸めないため、正でない値や有限でない値では比や交換確率が不正な値になります。
- `tsp/examples/sa_tsp.cpp:462-466` は `ll` の 4 辺の距離の差を `int diff_d` に縮小変換するため、改善の判定と距離の更新に誤りが生じます。

### 文書との不一致

`titan_cpplib/ahc/README.md:47` と `tsp/tsp_design.md:427,456` は、状態の生成関数またはラムダ式を `sa_run`, `sa_multi_run`, `replica_run` に渡すことができると説明しています。しかし `sa/sa.cpp:29-30,133-156,319-327` には、その引数を受け取る関数定義がありません。実装を追加するか、デフォルト構築の後に `init(seed)` を呼び出す現在の公開関数に合わせて文書を修正する必要があります。

### 定数倍高速化

- `sa.cpp:46-48,80,82,84-86,90` と複数の開始点で実行する版の `:233-234,260,263,265-267,271` は、`verbose=false` でも表示専用の回数表を確保して更新します。`replica_run` にも `:370-374,436,443-444` の種類別の統計が残っています。`State::modify` に渡す `iter` は探索の入力であるため維持し、表示専用の値だけをコンパイル時または実行時の分岐で省略するようにします。
- 時刻と進捗の取得を 16〜32 反復ごとに間引く案は、高頻度の反復処理に効果がある可能性が高いです。ただし取得しない反復では進捗と温度が同じ値になり、制限時間を超過する幅も増えます。この案は、同じ乱数のシードでも結果が変化する高速化用の明示的な設定として扱うようにします。

## sa.cpp

### replica_run

- **[バグ] `iter` 配列の範囲外アクセスが発生します**。`vector<int64_t> iter(max_threads, 0)` のようにスレッド数の長さしか確保していませんが、レプリカ番号 r (0 ≤ r < NUM_REPLICAS) を添字にして `iter[r]` でアクセスしています。既定の NUM_REPLICAS=32 に対して物理スレッドが 32 未満の環境ではヒープ破壊が発生します。NUM_REPLICAS の長さで確保すべきです。
- **[注意] thread_local の乱数のシードが全スレッドで同一です**。関数内の `thread_local titan23::Random sa_rnd` は各スレッドで既定のシードによって初期化されるため、閾値の計算に使用する乱数列がスレッド間で同一になります。State 側の sarnd はレプリカごとに異なるシード (1000+i) であるため探索自体はレプリカごとに異なりますが、受理の判定には相関が生じます。tid に応じて異なるシードにするのが安全です。
- レプリカ交換の受理式を確認しました。Δ = (E1−E2)(1/T1−1/T2)、受理確率 min(1, e^Δ)、`LOG_TABLE[..] < Δ` による判定は正しいです。偶奇のオフセットを使用した隣接ペアの交換も標準的な方法のとおりです。
- 並列化による競合の有無を確認しました。rep_idx は置換であり、1 レプリカを 1 スレッドが担当するため、states に対する競合は発生しません。統計配列は tid ごとに分離し、swap は直列区間で行っており、どちらも正しいです。
- **[軽微]** シードを外部から渡すことができず、1000+i に固定されています。関数に seed 引数がありません。
- **[軽微]** `progress` はブロックの開始時刻を基準にしており、ブロック内の SWAP_ITER_INTERVAL 回は同じ値になります。実害は小さいです。

### sa_run

- Metropolis 判定を確認しました。threshold = score − T·log(u) としたときの受理条件 new ≤ threshold は exp(−Δ/T) ≥ u と等価であり、正しいです。LOG_TABLE の (i+0.5)/N も log(0) を回避しており、正しいです。
- **[注意] TYPE_CNT=0 で範囲外アクセスが発生します**。統計配列を `state.changed.TYPE_CNT` の長さで確保するため、雛形 (sa_state.cpp) の既定値 0 のまま使用すると `modify[state.changed.type]++` が範囲外アクセスになります。replica_run は `max(1, TYPE_CNT)` で防いでいますが、sa_run と sa_multi_run にはガードがありません。
- **[軽微]** `now_time = sa_timer.elapsed()` をイテレーションごとに呼び出しています。呼び出しを間引く版 (`iter & 31`) がコメントアウトされた状態で残っており、軽量な modify では時刻の取得が定数倍に影響します。
- **[軽微]** 線形冷却用の `TEMP_VAL` が未使用のまま残っています。
- **[軽微]** ScoreType が整数型の場合は threshold への代入で小数部が切り捨てられ、わずかに受理されにくくなります。実害は小さいです。
- **[軽微]** `LOG_TABLE` は static でないグローバル定義であり、複数の TU から include するとリンクエラーになります。単一の TU を前提にする場合は実害がありません。
- **[軽微]** `<omp.h>` を無条件に include しています。sa_run だけを使用する提出でも -fopenmp を指定しない g++ でコンパイルできますが、環境への依存が増えます。

### sa_multi_run

- **[注意] フェーズ間の温度スケジュールが整合していません**。第 1 フェーズでは、各開始点の探索で progress 0→1 の間に START_TEMP から END_TEMP まで完全に冷却します。一方、第 2 フェーズは「全体スケジュールの FIRST_PHASE_RATIO 時点の温度」から再開します。第 1 フェーズを途中の温度 (phase2_start_temp) までの冷却にするか、設計の意図をコメントに記載すべきです。
- **[注意] State のコピーが発生します**。`best_local_state = state` はローカルの最良値を更新するたびに実行されます。how_to_use_sa.md は「探索ループ内で State 自体のコピーは発生しません」と保証しており、実装と矛盾しています。State のコピーに時間がかかる場合は性能も低下します。
- **[注意]** sa_run と同様に、TYPE_CNT=0 に対するガードがありません。
- **[軽微]** how_to_use_sa.md に sa_multi_run の記載がありません (後述)。
- **[軽微]** 第 2 フェーズの開始時の `score = state.get_score()` は、best_local_state のスコアと一致するため正しいです。

## sa_state.cpp

- **[注意] `TYPE_CNT = 0` が既定値です**。このまま sa_run に渡すと統計配列が空になり、範囲外アクセスになります。雛形の既定値は 1 にすべきです。how_to_use_sa.md 内のテンプレートは 1 になっており、雛形と一致していません。
- **[軽微]** `sa_init()` はローカル変数の Random を作成して破棄するだけであり、効果がありません。
- **[軽微]** `changed.type` が未初期化です。TODO のまま modify を空の実装で実行すると、未初期化の値を添字にして配列を参照します。雛形では 0 で初期化しておくと安全です。
- threshold と等しい場合の遷移、rollback で score の復元が不要であること、advance で遅延させた更新を確定することについてのコメントは、ライブラリの実装と一致しており適切です。

## sa_tsp.cpp (使用例)

mTSP の実装例です。近傍の差分計算はすべて検証しました。

- 次の処理はいずれも整合しています。
  - 2-opt (type 0) の辺の差分と advance の reverse
  - Or-opt/反転 Or-opt (type 1,2) の rotate と辺の差分
  - Double Bridge (type 3) のセグメントの再構成
  - Block Shift/Swap (type 4,5) の erase/insert と pos の更新
- 盤面の更新を advance だけで行う遅延評価も仕様どおりです。
- **[注意] `init(seed)` が `sarnd.set_seed(seed)` を呼び出していません**。ガイドはこの呼び出しを必須としています。replica_run で使用すると、全レプリカの sarnd が同一のシードになります。
- **[注意] `sa_run<sa::State>(100000, true)` の第 2 引数は seed です**。verbose を意図したと考えられる true が seed=1 として渡されています。
- **[注意] type 6 (周期的な 2-opt 局所探索) は modify 内で盤面を直接変更します**。改善する場合だけ適用するため、改善であれば必ず受理する threshold 判定と整合しており、問題なく動作します。ただし rollback できない遷移であることは、コメントに明記することが望ましいです。
- **[軽微]** type 6 内の `int diff_d` は ll の DIST の差を int に代入しており、座標が大きい場合はオーバーフローする可能性があります。
- **[軽微]** `P` は N×N の double の配列であり、N が大きい場合 (例: fnl4461) は約 160 MB になります。
- **[軽微]** type 6 内でサイズ N の route, best_route, route_pos を毎回確保しています。頻度は 1e6 イテレーションに 1 回であるため、実害はありません。
- **[軽微]** DIST などのグローバル変数は init の後は読み取り専用であるため、replica_run でも競合しません。ガイドの禁止事項とは形式上矛盾しますが、安全です。

## km.cpp (使用例)

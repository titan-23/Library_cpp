# `titan_cpplib/alg` 理論レビュー

レビュー日: 2026-08-12
対象: `.cpp` 12ファイル

## 結論

テスト・コンパイル・実行は行わず、数式、列挙境界、遷移先、乱数区間、生成物の不変条件、計算量を静的に追った。通常規模で中心となる処理が成立している実装は多いが、`DoubleSigma`の不要なオーバーフロー、`nCr`の中間積、`Mo`の未初期化な既定状態、乱数関数の区間算術と重み検査に確定問題がある。

| 重要度 | 対象 | 要点 |
|---|---|---|
| 重要 | `double_sigma.cpp` | 答えが0でも中間演算が符号付き整数のオーバーフローを起こす。未使用変数の更新だけでも未定義動作 |
| 重要 | `itertools.cpp::nCr` | 最終値が`long long`に収まっても中間積と`2*r`がオーバーフロー |
| 重大 | `mo.cpp` | 既定オブジェクトの`q,max_n`が未初期化 |
| 重要 | `random.cpp`, `random_mt.cpp` | 区間幅・循環加算、負の個数、累積確率・重みの検査不足 |
| 重要 | `traveling_salesman_problem.cpp` | ビット移動、行列形状、経路和の範囲 |
| 重要 | `tree_generator.cpp` | 全ラベル付き木の個数と各種`int`式のオーバーフロー、ライブラリ内の`exit(1)` |

## 1. 数式・遷移

### `double_sigma.cpp`

各公式の係数は、全ての組`l<r`に対する絶対差・差・最小値・最大値として整合する。ただし部分和、積、答えを全て要素型`T`で計算するため、数学的答えが収まる場合にも不要な符号付き整数のオーバーフローが起こる。

`sigma_abs<int>({INT_MIN,INT_MIN})`の答えは0だが、事前整列版は途中で`ans -= INT_MIN`を行う。逐次版も2要素目の`sum += INT_MIN`でオーバーフローする。`sigma_min_online`の`s`は結果に一度も使われないのに更新され、同じ未定義動作を起こす。

要素型と集約型`Acc`を分け、乗算・加減算より前に`Acc`へ変換する必要がある。逐次版が使う`MultisetSum`も同じ集約型を保持しなければならない。

### `doubling.cpp`, `doubling_monoid.cpp`

遷移の合成と非可換モノイド積の順序は正しい。必要な契約は次である。

- `LIM>=0`。
- 全ての`A[i]`が番兵`-1`または`[0,n)`。
- モノイド版は`B.size()==A.size()`。

`Doubling(2,{1})`は表の構築中に`db[0][1]`を範囲外参照し、モノイド版の`A={-1},B={}`も`B[0]`を読む。問い合わせ時でなく、コンストラクタ入口で全遷移を検査すべきである。

### `itertools.cpp::nCr`

`nCr(LLONG_MAX,LLONG_MAX)`の答えは1だが、対称化判定`r*2>n`自体がオーバーフローする。`r>n-r`なら安全に比較できる。

また`C(66,33)=7219428434016265740`は`long long`に収まるが、逐次式の最終段で`C(65,32)*66`を除算前に作るためオーバーフローする。`__int128`または各段の最大公約数による約分を用い、最終値が収まることも検査する必要がある。

組合せ、順列、直積、整数分割、部分集合列挙の通常境界は整合する。`grouping_pair`の`2*n`と連長圧縮の連続数などは、`int`に収まることを暗黙に要求する。

### `lis.cpp`

狭義増加版の`lower_bound`、広義増加版の`upper_bound`、復元用の直前位置はいずれも整合する。`vector<T>(n)`により、本来は比較と複製だけで足りる`T`へ、既定構築可能という追加条件を課す。長さと添字は`int`に収まる必要がある。

## 2. `Mo`

`Mo()`は`n=0`だけを初期化し、`q`と`max_n`を不定のまま残す。既定オブジェクトで`run_*`を呼ぶと、不定な`q`を配列長に使い、未定義動作となる。有効な空状態へ委譲するか、既定コンストラクタを削除すべきである。

Hilbert順と区間を伸縮する呼出し関数の順は整合する。ただし現在の`O(n sqrt(q))`という説明だけでは、問い合わせの評価、`O(q log q)`の整列、`q`回の出力を表せない。`n=0`へ空区間の問い合わせを大量追加しても`Θ(q log q)`を要する。区間端点の移動量と整列・出力を分けて示す必要がある。

## 3. 乱数関数

### `random.cpp`

#### 区間算術

`randrange(INT_MIN,INT_MAX)`は`end-begin`を`int`で評価してオーバーフローする。64ビット版の全域、`rand_pair`の`end-begin`、`u+offset`も同様である。区間幅は符号なしまたはより広い型で作り、結果が範囲内であることを確認してから符号付き型へ戻す必要がある。

`randint(begin,end)`は広い負区間で符号なし算術と、処理系依存の符号付き変換に頼る。上位積を使う現在の方法は高速だが、乱数空間の大きさが区間幅で割り切れなければ厳密な一様分布ではない。厳密な一様性を保証するなら、余りを捨てて再抽選する必要がある。

#### 実数の端点

`random()`は`UINT32_MAX`で割るため、乱数生成器の出力が最大値なら厳密に1を返す。したがって`randdouble(begin,end)`も、半開区間という説明に反して`end`を返し得る。`2^32`で割るか、閉区間を返す関数として定義すべきである。`begin==end`を許す検査も半開区間とは一致しない。

#### 個数・重み

`rand_vec`は`cnt`を検査せず、`-1`で`begin()-1`、要素数超過で不正な反復子を作る。`choices(a,-1)`は上限検査を通って、巨大な配列を確保しようとする。

重み付き`choice`は、累積確率版で非空・同じ長さ・有限値・非減少・末尾値を検査しない。整数重みも負値`{2,-1}`から非単調な累積列を作る。全ての重みが非負、総和が正、累積確率なら`[0,1]`内の非減少列であることを要求する必要がある。

### `random_mt.cpp`

標準分布を使う単一区間の処理は契約どおりだが、`rand_pair`は幅と`u+offset`を`int`で行い、広い負区間でオーバーフローする。`rand_vec`は`cnt<=n`しか検査せず、負値で不正な反復子になる。

整数重み版は負値を拒否せず、累積確率版は値の妥当性を検査しない。累積確率`[0,1]`で乱数が0のとき`lower_bound`を使うと、重み0の先頭要素を選ぶ。半開区間の一様乱数に対して重み0を飛ばすには`upper_bound`が必要である。

両乱数クラスの`choices`は`vector<T>(k)`を作ってから代入するため、`T`へ不要な既定構築可能条件を課す。

## 4. 木の生成器

### `random_tree.cpp`

Prüfer列から次数1の最小頂点を順に除く復号と、頂点の置換からパスを作る処理は整合する。`gen_path`は無作為な並べ替えと1回の走査だけなので`O(n)`である。メンバー`n`は利用されない。

### `tree_generator.cpp`

通常の想定規模では、無作為木、一様木、星、パス、ほぼパス、複数の一様部分木、次数制約、Prüfer列の符号化・復号、中心固定の並べ替え、全ラベル付き木生成について不変条件を追跡した。

確定する境界・公開操作の問題は次である。

- `generate_all_labeled`の`N^(N-2)`を`long long`で作る。`N=18`で`18^16>LLONG_MAX`となる。説明上の小さい目安を実際に検査すべきである。
- `N*9`, `2*i`, `root+len`, `len+=2`などを`int`で行い、公開引数の上限がない。
- 内部検査失敗時に`exit(1)`し、ライブラリ呼び出しが利用側の処理全体を終了する。失敗を戻り値、例外、または`assert`で表すべきである。
- 検査対象の頂点数を`edges.size()+1`から推測するため、要求された`N`と空・不足辺を独立に検査できない。
- 不正な`TreeType`の処理を`assert`に頼り、`NDEBUG`指定時には空の辺集合を返し得る。`generate_1indexed`は続けて不足した配列を読む。
- 負の`N`を空木として受理する経路があるため、`N>=0`を共通入口で検査すべきである。

## 5. 巡回セールスマン問題・座標圧縮

### `traveling_salesman_problem.cpp`

Held--Karp法の漸化式は、`n>0`、正方行列`dist`、安全な加算の下で正しい。`1<<n`は`n>=31`で符号付き整数のビット移動が未定義となり、実用上のメモリ限界より先に言語上の問題が出る。`size_t(1)<<n`を用い、型のビット幅と確保量を事前に検査すべきである。

各行が`n`要素か検査せず、経路和と閉路を閉じる加算もオーバーフローし得る。`INF`は全ての有効な経路和より大きく、かつ中間加算が型に収まる必要がある。

### `zaatsu.cpp`

整列・重複除去と`lower_bound`の核は整合する。`add`後は`build`まで問い合わせ不能という利用順を`assert`だけで表すため、`NDEBUG`指定時には古い`n`と未整列の配列を使う。利用順を常に検査するか、自動で再構築すべきである。

`to_zaatsu(v)`は未登録値にも挿入順位を返し、最大値より大きければ`n`を返す。登録値の変換なのか、順位を求める関数なのかを名称と契約で明確にする必要がある。

## 6. 複数の翻訳単位からの利用

`itertools.cpp`のテンプレートでない自由関数群は非`inline`であり、ヘッダー相当のこのファイルを複数の翻訳単位から読み込むと一意定義規則に違反する。単一ファイルへの展開専用でなければ、`inline`化するか宣言と実装を分離する必要がある。

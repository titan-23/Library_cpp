## 1. 数式・遷移

### `double_sigma.cpp`

各公式の係数は、全ての組 `l<r` に対する絶対差、差、最小値、最大値として整合しています。ただし部分和、積、答えを全て要素型 `T` で計算するため、数学的な答えが型の範囲に収まる場合にも、不要な符号付き整数のオーバーフローが発生します。

`sigma_abs<int>({INT_MIN,INT_MIN})` の答えは 0 ですが、事前にソートする版は途中で `ans -= INT_MIN` を実行します。逐次版も 2 要素目の `sum += INT_MIN` でオーバーフローします。`sigma_min_online` の `s` は結果に一度も使用されないにもかかわらず更新され、同じ未定義動作を起こします。

要素型と集約値の型 `Acc` を分け、乗算と加減算より前に `Acc` へ変換する必要があります。逐次版が使用する `MultisetSum` も同じ型で集約値を保持しなければなりません。

### `doubling.cpp`, `doubling_monoid.cpp`

遷移の合成と非可換なモノイドの積の順序は正しいです。必要な事前条件は次のとおりです。

- `LIM>=0` であること
- 全ての `A[i]` が番兵 `-1` または `[0,n)` の値であること
- モノイド版では `B.size()==A.size()` であること

`Doubling(2,{1})` は表の構築中に `db[0][1]` を範囲外参照し、モノイド版の `A={-1},B={}` も `B[0]` を参照します。問い合わせ時ではなく、コンストラクタの開始時に全ての遷移を確認すべきです。

### `itertools.cpp::nCr`

`nCr(LLONG_MAX,LLONG_MAX)` の答えは 1 ですが、対称性を利用するための判定 `r*2>n` 自体がオーバーフローします。`r>n-r` の形であれば安全に比較できます。

また `C(66,33)=7219428434016265740` は `long long` に収まりますが、逐次計算の式の最終段で `C(65,32)*66` を除算の前に計算するためオーバーフローします。`__int128` または各段の最大公約数による約分を使用し、最終値が収まることも確認する必要があります。

組合せ、順列、直積、整数分割、部分集合の列挙は、通常の境界では整合しています。`grouping_pair` の `2*n` と連長圧縮の連続数などは、`int` に収まることを暗黙の前提にしています。

### `lis.cpp`

狭義増加の版の `lower_bound`、広義増加の版の `upper_bound`、復元用の直前の位置はいずれも整合しています。`vector<T>(n)` を使用しているため、本来は比較と複製だけで十分な `T` に対して、デフォルト構築可能という追加の条件を課しています。長さと添字は `int` に収まる必要があります。

## 2. `Mo`

`Mo()` は `n=0` だけを初期化し、`q` と `max_n` を不定値のまま残します。デフォルト構築したオブジェクトで `run_*` を呼び出すと、不定値の `q` を配列長に使用するため未定義動作になります。有効な空の状態を構築するコンストラクタへ委譲するか、デフォルトコンストラクタを削除すべきです。

Hilbert 順と、区間を伸縮する関数の呼び出し順は整合しています。ただし現在の `O(n sqrt(q))` という説明だけでは、問い合わせの評価、`O(q log q)` のソート、`q` 回の出力を表すことができません。`n=0` に対して空区間の問い合わせを大量に追加した場合も `Θ(q log q)` の時間が必要です。区間の端点の移動量と、ソートおよび出力を分けて示す必要があります。

## 3. 乱数関数

### `random.cpp`

#### 区間の計算

`randrange(INT_MIN,INT_MAX)` は `end-begin` を `int` で評価するためオーバーフローします。64 ビット版の全域、`rand_pair` の `end-begin`、`u+offset` も同様です。区間幅は符号なしの型またはより広い型で計算し、結果が範囲内であることを確認してから符号付きの型へ戻す必要があります。

`randint(begin,end)` は、負の値を含む広い区間では、符号なしの演算と処理系依存の符号付きへの変換に依存します。積の上位ビットを使用する現在の方法は高速ですが、乱数の値域の大きさが区間幅で割り切れない場合は厳密な一様分布になりません。厳密な一様性を保証する場合は、余りの部分を棄却して乱数を再度生成する必要があります。

#### 実数の端点

`random()` は `UINT32_MAX` で割るため、乱数生成器の出力が最大値の場合は厳密に 1 を返します。したがって `randdouble(begin,end)` も、半開区間という説明に反して `end` を返す可能性があります。`2^32` で割るか、閉区間を返す関数として定義すべきです。`begin==end` を許可するチェックも半開区間とは一致しません。

#### 個数・重み

`rand_vec` は `cnt` を確認しないため、`-1` の場合は `begin()-1` を、要素数を超える場合は不正な反復子を作成します。`choices(a,-1)` は上限のチェックを通過し、巨大な配列を確保しようとします。

重み付きの `choice` の累積確率版は、空でないこと、同じ長さであること、有限値であること、非減少であること、末尾の値を確認していません。整数の重みの版も、負値 `{2,-1}` から単調でない累積列を作成します。全ての重みが非負であること、総和が正であること、累積確率の場合は `[0,1]` 内の非減少列であることを条件にする必要があります。

### `random_mt.cpp`

標準ライブラリの分布を使用する単一区間の処理は仕様どおりですが、`rand_pair` は幅と `u+offset` を `int` で計算するため、負の値を含む広い区間でオーバーフローします。`rand_vec` は `cnt<=n` しか確認しないため、負値の場合は不正な反復子になります。

整数の重みの版は負値を拒否せず、累積確率版は値の妥当性を確認しません。累積確率 `[0,1]` で乱数が 0 のときに `lower_bound` を使用すると、重み 0 の先頭要素を選択します。半開区間の一様乱数に対して重み 0 の要素をスキップするには `upper_bound` が必要です。

両方の乱数クラスの `choices` は `vector<T>(k)` を作成してから代入するため、`T` に対してデフォルト構築可能という不要な条件を課しています。

## 4. 木の生成器

### `random_tree.cpp`

Prüfer 列から次数 1 の最小の頂点を順に取り除く復号と、頂点の置換からパスを作成する処理は整合しています。`gen_path` は無作為な並べ替えと 1 回の走査だけであるため `O(n)` です。メンバー `n` は使用されていません。

### `tree_generator.cpp`

通常想定する規模では、無作為木、一様木、スター、パス、ほぼパス、複数の一様部分木、次数制約、Prüfer 列の符号化と復号、中心を固定した並べ替え、全ラベル付き木の生成について不変条件を確認しました。

境界と公開操作について確定した問題は次のとおりです。

- `generate_all_labeled` は `N^(N-2)` を `long long` で計算します。`N=18` で `18^16>LLONG_MAX` となります。説明に記載された小さい目安を実際にチェックすべきです。
- `N*9`, `2*i`, `root+len`, `len+=2` などを `int` で計算しており、公開関数の引数に上限がありません。
- 内部のチェックに失敗したときに `exit(1)` を実行するため、ライブラリの呼び出しが利用側の処理全体を終了させます。失敗は戻り値、例外、または `assert` で表すべきです。
- チェックの対象の頂点数を `edges.size()+1` から推測するため、指定された `N` と、辺が空または不足していることを独立に確認できません。
- 不正な `TreeType` の処理を `assert` に依存しており、`NDEBUG` の指定時には空の辺集合を返す可能性があります。`generate_1indexed` は、続けて要素の不足した配列を参照します。
- 負の `N` を空の木として受理する場合があるため、`N>=0` を共通の処理の開始時に確認すべきです。

## 5. 巡回セールスマン問題・座標圧縮

### `traveling_salesman_problem.cpp`

Held--Karp 法の漸化式は、`n>0`、正方行列 `dist`、安全な加算という条件の下で正しいです。`1<<n` は `n>=31` で符号付き整数のビットシフトが未定義となり、実用上のメモリの限界より先に言語仕様上の問題が発生します。`size_t(1)<<n` を使用し、型のビット幅と確保量を事前に確認すべきです。

各行が `n` 要素であるかを確認しておらず、経路の距離の和と、閉路を閉じるときの加算もオーバーフローする可能性があります。`INF` は全ての有効な経路の距離の和より大きく、かつ途中の加算の結果が型に収まる値である必要があります。

### `zaatsu.cpp`

中心となるソート、重複の除去、`lower_bound` の処理は整合しています。`add` の後は `build` を呼び出すまで問い合わせができないという利用順を `assert` だけで表しているため、`NDEBUG` の指定時には古い `n` とソートされていない配列を使用します。利用順を常に確認するか、自動的に再構築すべきです。

`to_zaatsu(v)` は未登録の値に対しても挿入位置の順位を返し、最大値より大きい場合は `n` を返します。登録済みの値を変換する関数であるのか、順位を求める関数であるのかを、名称と仕様で明確にする必要があります。

## 6. 複数の翻訳単位からの利用

`itertools.cpp` のテンプレートでない自由関数群は `inline` ではないため、ヘッダーに相当するこのファイルを複数の翻訳単位から読み込むと一意定義規則に違反します。単一ファイルへの展開専用でない場合は、`inline` にするか、宣言と実装を分離する必要があります。

# `titan_cpplib/graph/dycone.cpp` の計算量解析

対象は `OfflineDynamicConnectivity<T>` です。正しさの説明に必要な範囲でアルゴリズムも記述しますが、主な目的は実装されている各ループの計算量を証明することです。

## 1. 記号と計算モデル

- `n`: 頂点数です。
- `q`: コンストラクタに渡すクエリの容量です。配列 `S` は最初から長さ `q` で確保され、初期化されます。
- `m`: 実際に登録したクエリ数 `t = Q.size()` です。常に `m <= q` が成り立ちます。
- `D(x)`: その時点の親ポインタの森 `P` における、`x` から根までの**未圧縮の**頂点数です。`x` 自身も含めます。

次の内容を仮定します。

1. `rd` は頂点集合上の一様ランダムな順列です。
2. 登録されるクエリ列は `rd` と独立です。実行時間などを観測して次のクエリを選ぶ適応的な敵対者は対象外とします。
3. `unordered_map` の 1 回の操作は期待 O(1) とします。
4. `T` のコピー、加算、減算は O(1) とします。
5. 自己ループ、多重辺、存在しない辺の削除などについては、この実装が正しく動作する入力の範囲を対象とします。

この確率モデルでは、後で証明する期待値はすべて `rd` について取ったものです。ハッシュに関する期待値は、これとは別の仮定 3 に基づきます。

## 2. 結論

構築から `run()` の終了までの期待計算量は

```text
O(n + q + m log(n + 1))
```

です。通常の `m = q` の場合は

```text
O(n + q log(n + 1))
```

であり、緩く `O((n + q) log(n + 1))` と表すこともできます。`run()` だけの場合は期待 `O(m log(n + 1))` です。対数因子は 1 個であり、この上界は入力列によっては漸近的にタイトになります。

データ構造本体の最悪計算量は 1 回の操作で O(n)、`run()` 全体で O(mn) です。ハッシュ表の衝突が最悪の場合まで含めると、全工程の決定論的な上界は

```text
O(n + q + m n + m^2)
```

です。空間計算量は Θ(n + q) です。`disconnect` 1 回の再帰の深さの期待値は O(log(n + 1)) ですが、補助スタックは最悪の場合 O(n) になります。

## 3. アルゴリズムの構造

追加された辺 `e` の削除時刻を `d(e)` とします。削除されない辺については `d(e) = +∞` とみなし、実装は辺の重み

```text
w(e) = -d(e)
```

を `S` に記録します。削除されない辺の番兵は `-INT_MAX` です。

`run()` はクエリを先頭から順に処理し、現在存在する辺の最小全域森を維持します。辺を追加して閉路ができた場合は、閉路上で重みが最大の辺が新しい辺より重いときに、その辺を新しい辺に差し替えます。時刻 `t` に削除される辺の重みは `-t` です。その時点で存在する他の辺の削除時刻は `t` より後であるため、それらの重みは `-t` より小さくなります。したがって、削除される森の辺を切断したときに代替の辺を探す必要はありません。

この最小全域森は辺そのものとしては保持せず、次のレベル付きの親ポインタの森で表します。

- `P[x]`: `x` の親です。根では `P[x] = x` です。
- `W[x]`: `x` のクラスタが `P[x]` のクラスタに併合される重みのレベルです。根では番兵の `1` です。
- `rd[x]`: ランダムな優先度です。

新しい親へのリンクを作成する箇所は `sub_add` だけであり、そこでは必ず優先度の小さい代表を優先度の大きい代表の子にします。このため常に

```text
x != P[x] なら rd[x] < rd[P[x]]                       (H)
```

が成り立ちます。`P[x] = P[P[x]]` という短絡でも (H) は維持され、切断はリンクを削除するだけです。したがって (H) は実行全体を通じた不変条件です。

## 4. 抽象的なクラスタ鎖と親ポインタの経路

計算量の証明で最も重要な点は、重みの単調性が成り立たない未圧縮のリンクも含めて `D(x)` を評価することです。そのために、まず実装が暗黙に保持する抽象的なクラスタ鎖を定義します。

### 4.1 クラスタ鎖

頂点 `x` に対するクラスタ鎖とは、`x` を含む頂点集合の狭義の包含列

```text
C_0 ⊊ C_1 ⊊ ... ⊊ C_k,    x ∈ C_0
```

のことです。各クラスタの代表を

```text
r_i = argmax { rd[v] | v ∈ C_i }
```

とします。包含列であるため、代表が `a` からより優先度の高い `b` に一度変化すると、後で `a` に戻ることはありません。

列 `(r_0, ..., r_k)` で連続する同じ値を 1 個に縮約した列を、このクラスタ鎖の **record 列** と呼びます。

### 4.2 経路の表現に関する補題

**補題 1 (未圧縮の経路の record 列による表現)**

登録された各クエリの処理を開始する時点で、任意の固定された頂点 `x` の `P` 上の未圧縮の経路は、`rd` と独立に定まるクラスタ鎖の record 列の部分列です。`sub_add` の実行途中に走査される 2 本の鎖についても同じ性質が成り立ちます。

**証明。** クエリ列に関する帰納法で示します。

初期状態では各頂点が単独のクラスタ `{x}` であるため成立します。

`disconnect` は `sum, sz` を先祖から減算するだけで、`P, W` を変更しません。`connect` も `sum, sz` を加算しながら既存の `P` をたどるだけです。よって、どちらも record 列による表現を変更しません。

`find` と `sub_del` の内側にある

```cpp
P[u] = P[P[u]];
```

は、`u` の record 列から現在の親を 1 個削除する操作です。`u` の部分木にある頂点の経路も、`u` 以降で同じ親が 1 個なくなるだけであり、それ以外の経路は変化しません。したがって、すべての経路が以前の record 列の部分列となり、補題は引き続き成り立ちます。

`sub_del` の

```cpp
P[u] = u;
W[u] = 1;
```

は 1 本の鎖をその位置で 2 本に切断します。切断後の各経路は切断前の経路の連続する部分であり、それぞれ対応するクラスタ鎖の一部で表すことができます。辺の差し替え中の切断は、直後の `sub_add` と合わせると、以下で説明する鎖のマージになります。

残る操作は `sub_add` による親へのリンクの作成です。途中の `find(u) == find(v)` が真の場合は新しいリンクを作成せず、短絡済みの鎖に `connect` を適用するだけであるため、すでに扱った場合に帰着します。以下では 2 つの成分を実際に併合する場合を考えます。

`sub_add` の開始時に存在する 2 本のクラスタ鎖を考えます。各包含 `C_i ⊊ C_{i+1}` には、その包含が生じた重みのレベルを付記します。このレベル付きのクラスタ鎖も帰納的に端点と辺の重みだけから定まり、`rd` に依存しません。短絡によって実際の経路から削除された record は、抽象的なクラスタ鎖に残して構いません。コードがその record を走査しなくても、最終的な実際の経路が完全な record 列の部分列になるだけであるためです。新しい重み `w` で両側のクラスタを併合した集合も同様に `rd` と独立です。

`sub_add` のループ不変条件を次のように定めます。

1. すでに処理した下位の部分は、2 本のレベル付きのクラスタ鎖を重みの順にマージした結果の record を表します。
2. `u`, `v` は両方の鎖の未処理部分の現在の代表です。
3. 変数 `w` は次に処理する包含または併合のレベルです。

ループの開始時にはまだ何もマージしていないため、不変条件は成立します。

ループの先頭の

```cpp
u = connect(u, w);
v = connect(v, w);
```

は、両方の鎖を「次に重み `w` で併合すべきクラスタ」まで単調に進めます。その後に

```cpp
if (rd[u] < rd[v]) swap(u, v);
P[v] = u;
W[v] = w;
```

を実行します。併合前の 2 つのクラスタを `A, B` とすると、`u, v` はそれぞれ `argmax_rd A`, `argmax_rd B` です。比較後の `u` は

```text
argmax_rd(A ∪ B)
```

です。優先度の小さい代表 `v` から優先度の大きい代表 `u` へのリンクを作成することは、クラスタ鎖に `A ∪ B` を追加したときに生じる record の変化をちょうど 1 個表します。

この操作でレベル `w` の和集合が処理済みになり、ループ不変条件 1 が 1 段階進みます。さらに、更新前の

```cpp
np = P[v];
nw = W[v];
```

を保存しておき、反復の末尾で `u = np, w = nw` とします。したがって次の反復は、優先度の小さかった代表が元々属していた鎖の未処理部分から、その次の包含のレベル `nw` を処理します。優先度の大きかった代表は和集合の代表としてそのまま残ります。このためループ不変条件 2, 3 も維持されます。

このように、ループ全体は 2 本のレベル付きのクラスタ鎖を重みの順に安定にマージし、和集合のクラスタの代表が変化する箇所だけをリンクとして出力します。マージされる集合とその順序は端点と重みの列だけで定まり、優先度の比較は各和集合にどの頂点の名前を付けるかだけを決定します。

親を更新した代表 `v` の下にある既存の分岐の頂点 `y` も確認します。`y` の鎖で `v` が代表となるクラスタを `A_y`、その包含のレベルを `W[y]` とします。新しい併合のレベル `w` が `W[y]` 以上の場合、併合される和集合はその時点ですでに `A_y` 全体を含んでいます。

`w < W[y]` の場合は、`v` の新しい親の側でレベル `w` 以後に現れるクラスタを包含の順に `B_0 ⊊ B_1 ⊊ ...` とします。`y` に対する抽象的なクラスタ鎖には

```text
A_y ⊊ A_y ∪ B_0 ⊆ A_y ∪ B_1 ⊆ ...
```

を追加し、等しい集合は除きます。この列は入れ子になっており、既存のレベル付きの鎖と新しい辺だけから定まるため `rd` と独立です。`v` は `A_y` の中で優先度が最大の頂点です。`v` より優先度の高い record が親の側に現れるたびに、その頂点は対応する `A_y ∪ B_i` の中で優先度が最大の頂点になります。したがって、実際の経路 `... -> y -> ... -> v -> u -> ...` はこの和集合の列の record です。

これは、コード上で `W[y] >= W[v]` という stale リンクとして現れる場合に当たります。ここでは、実際の重みの閾値で定まるクラスタではない集合を抽象的なクラスタ鎖に追加しています。しかし、計算量の証明に必要な性質は、集合の列が `rd` と独立で入れ子になっていることです。各集合が現在のグラフの閾値で定まる連結成分である必要はありません。後の短絡はこの record 列から要素を削除するだけです。

以上より、`sub_add` の後もすべての頂点の経路について `rd` と独立なクラスタ鎖が存在します。また、ループはその 2 本の record 列を先頭から順に消費しているため、実行途中に走査される鎖にも同じ性質があります。帰納法により補題が示されました。∎

この補題で重要な点は、「現在の重みの閾値で定まる成分だけからなる正規化済みの経路」ではなく、stale リンクを含む未圧縮の経路を評価していることです。したがって、stale リンクが作成される総数を別のポテンシャルで償却する必要はありません。

## 5. 未圧縮の経路長の期待値

**補題 2 (record の個数)**

`rd` と独立な任意のクラスタ鎖

```text
C_0 ⊊ C_1 ⊊ ... ⊊ C_k
```

の record 列の長さを `L` とすると、

```text
E[L] <= 1 + ln n
```

が成り立ちます。

**証明。** `s_i = |C_i|` と置きます。`C_{i-1}` から `C_i` へ拡大したときに代表が変化するのは、`C_i \ C_{i-1}` のいずれかの頂点の優先度が `C_i` 全体で最大である場合に限ります。また、その場合は必ず変化します。一様ランダムな順列の対称性から次の式が成り立ちます。

```text
Pr[r_i != r_{i-1}]
  = (s_i - s_{i-1}) / s_i
  = 1 - s_{i-1} / s_i.
```

`0 < z <= 1` に対する `1 - z <= ln(1/z)` を使用すると、期待値の線形性より次の評価が得られます。

```text
E[L]
  = 1 + sum_{i=1}^k Pr[r_i != r_{i-1}]
  <= 1 + sum_{i=1}^k ln(s_i / s_{i-1})
  = 1 + ln(s_k / s_0)
  <= 1 + ln n.
```

この証明では各事象の独立性を使用していません。必要な性質は各 `C_i` が `rd` と独立であることだけです。∎

補題 1 より `P` 上の未圧縮の経路は record 列の部分列であるため、直ちに次の定理が得られます。

**定理 3 (未圧縮の経路長)**

任意のクエリ列について、クエリの処理の境界となる任意の時点と、そのクエリ列によって固定された任意の頂点 `x` に対して次の式が成り立ちます。

```text
E[D(x)] <= 1 + ln n = O(log(n + 1)).
```

これは償却による評価ではなく、各時点の各固定頂点に対する期待値の評価です。

## 6. 各内部処理の決定論的コスト

ここでは、乱数についての平均を取る前に、1 つの固定された `P` の状態で各処理がアクセスするノード数を評価します。

### `find(u)`

外側のループは `u` を親へ進めます。内側のループの 1 回の反復は `P[u]` をその祖父へ進めます。どちらも開始時の `u` から根までの経路上を根の方向にだけ進み、新しいノードを経路へ挿入しません。したがって `O(D(u))` です。

### `disconnect(u)` と `connect(u, w)`

どちらも `u` から根までの経路、またはその先頭部分を 1 回たどるため `O(D(u))` です。`disconnect` の再帰の深さも `D(u)` です。

### `max_edge(u, v)`

最初の 2 回の `find` と、その後の合流点までの走査は、`u, v` から根までの 2 本の経路だけを根の方向にたどります。したがって `O(D(u) + D(v))` です。

### `sub_add(u, v, w)`

最初の 2 回の `disconnect` は `O(D(u) + D(v))` です。マージのループでは、各反復で走査中の 2 本の鎖の少なくとも一方の record を 1 個消費します。`connect` が 1 回で複数のノードを通過しても、それらのノードが以後同じ入力の鎖から再び消費されることはありません。したがって、全反復を合計した `connect` の走査回数と親の付け替え回数は `O(D(u) + D(v))` です。最後の `connect(u)` を含めても同じ上界が成り立ちます。

### `sub_del(u, v, w)`

対象の重みを探す走査、単調性に違反する箇所の短絡、切断後に `sum, sz` をすべての先祖から減算する走査は、いずれも `u` から根までの経路上で行われます。末尾の `find(u)`, `find(v)` まで含めて `O(D(u) + D(v))` です。対象の辺が森にない場合は、探索が対象を見つけないまま根に到達するだけであるため、同じ上界が成り立ちます。

### `inner_add_point(u, value)`

短絡せずに `u` から根までを 1 回たどるため、正確に Θ(`D(u)`) です。圧縮しないことは最悪計算量には影響します。しかし定理 3 は未圧縮の経路を評価しているため、期待計算量の証明に不備は生じません。

### 乱数に依存する内部の頂点についての注意

`max_edge` が返す `p` は `rd` に依存するため、「固定頂点 `p` に対する定理 3」をそのまま適用することはできません。しかし `p` と、差し替え時に `sub_del` がたどる経路は、直前に走査した固定端点 `u, v` の 2 本の経路の一部です。したがって、そのコストは決定論的に `D(u) + D(v)` に含めて評価することができます。内部で選ばれた乱数に依存する頂点に、深さの期待値の定理を適用する必要はありません。

以上から、登録されたクエリ 1 個の処理時間は次のとおりです。

| クエリ | 決定論的コスト | 期待コスト |
|---|---:|---:|
| `ADD` | O(`D(u) + D(v)`) | O(log(n + 1)) |
| `DEL` | O(`D(u) + D(v)`) | O(log(n + 1)) |
| `ADD_POINT` | Θ(`D(u)`) | O(log(n + 1)) |
| `GET_SUM` | O(`D(u)`) | O(log(n + 1)) |
| `GET_SIZE` | O(`D(u)`) | O(log(n + 1)) |
| `IS_SAME` | O(`D(u) + D(v)`) | O(log(n + 1)) |
| `GET_COUNT` | Θ(1) | Θ(1) |

したがって、期待値の線形性から `run()` 全体は期待 `O(m log(n + 1))` です。経路長について操作列全体で償却する必要はありません。

## 7. 前処理、総計、空間

コンストラクタは長さ `n` の配列の初期化とシャッフル、長さ `q` の `S` の初期化を行うため Θ(n + q) です。クエリの登録は、`vector` の償却と仮定 3 のハッシュの期待値のもとで 1 回あたり期待償却 O(1)、合計で期待 O(m) です。`run()` で結果の配列を構築する処理は Θ(m) です。よって全体の期待計算量は次のとおりです。

```text
O(n + q + m log(n + 1)).
```

配列 `P, W, rd, sz, sum` は Θ(n)、`S` は Θ(q)、`Q`, `res`, `mp` は O(m) であり、`m <= q` であるため空間計算量は Θ(n + q) です。再帰スタックの O(n) もこの漸近的な上界に含まれます。

## 8. 上界のタイトさと最悪計算量

### 期待 Θ(log n) が必要な操作列

具体的には頂点を `0, 1, ..., n-1` とし、まず辺

```text
(0,1), (1,2), ..., (n-2,n-1)
```

をこの順に追加します。次に頂点 `x = 0` への `add_point` を必要な回数だけ登録し、最後に上の辺を追加した順の逆順で削除します。辺 `(i-1,i)` は `i` が大きいほど早く削除されるため、その重みは `i` とともに狭義に増加します。したがって `x` の経路上で `W` の単調性の違反は発生せず、この経路は `find` によって短絡されません。

この操作列では頂点を 1 個ずつ既存の成分へ連結するため、`x` を含むクラスタのサイズが

```text
1, 2, ..., n
```

と増加します。このとき `D(x)` はランダムな順列の prefix maximum の個数であり、次の式が成り立ちます。

```text
E[D(x)] = H_n = Θ(log n).
```

その状態で `add_point(x, value)` を繰り返すと、毎回同じ未圧縮の経路をたどります。したがって、定数時間でないクエリについての期待 O(log n) と、`m = Ω(n)` の範囲における全体の期待 O(m log n) は、一般にはそれぞれ O(1), O(m) へ改善できません。

### 乱数が最悪の場合

同じ構成で、優先度がクラスタに追加される順に狭義に増加する順列が選ばれると、`D(x) = Θ(n)` となります。そこで `add_point` を Θ(m) 回実行すると Θ(mn) 時間になります。したがって、データ構造本体の最悪の場合の上界 O(mn) はタイトです。`disconnect` の再帰の深さも同じ例で Θ(n) になり得ます。

さらに `unordered_map` の 1 回の操作は仕様上の最悪の場合 O(m) であるため、登録フェーズは最悪 O(m^2) です。これを含む全工程の決定論的な上界は次のとおりです。

```text
O(n + q + m n + m^2).
```

## 9. 実装上の乱数について

実際のコードは

```cpp
shuffle(rd.begin(), rd.end(), mt19937(1321312));
```

のように固定のシードを使用するため、プログラムそのものは決定論的です。本稿の期待計算量は、この順列を一様ランダムに選ぶという解析上のモデルに対する保証です。固定のシードを知っている入力の作成者に対しては期待計算量の保証を主張できません。この作成者は前節の Θ(mn) の入力を構成することができます。

実行時に十分にランダムなシードを選び、入力列がシードと独立である場合は、本稿で示した期待計算量 O(n + q + m log(n + 1)) が成り立ちます。

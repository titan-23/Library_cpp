# `titan_cpplib/graph/dycone.cpp` の計算量解析

対象は `OfflineDynamicConnectivity<T>` である。以下では、正しさの説明に必要な範囲でアルゴリズムも記述するが、主眼は実装されている各ループの計算量を証明することにある。

## 1. 記号と計算モデル

- `n`: 頂点数。
- `q`: コンストラクタに渡すクエリ容量。配列 `S` は最初から長さ `q` で確保・初期化される。
- `m`: 実際に登録したクエリ数 `t = Q.size()`。常に `m <= q`。
- `D(x)`: その時点のポインタ森 `P` における、`x` 自身を含む `x` から根までの**未圧縮の**頂点数。

次を仮定する。

1. `rd` は頂点集合上の一様ランダム順列である。
2. 登録されるクエリ列は `rd` と独立である。実行時間などを観測して次のクエリを選ぶ適応的敵対者は考えない。
3. `unordered_map` の 1 操作は期待 O(1) とする。
4. `T` のコピー、加算、減算は O(1) とする。
5. 自己ループ、多重辺、存在しない辺の削除などについては、この実装が正しく動作する入力契約の範囲を考える。

この確率モデルでは、後で証明する期待値はすべて `rd` に関する。ハッシュの期待値はこれとは別の仮定 3 による。

## 2. 結論

構築から `run()` の終了までの期待計算量は

```text
O(n + q + m log(n + 1))
```

である。通常の `m = q` なら

```text
O(n + q log(n + 1))
```

であり、緩く `O((n + q) log(n + 1))` と書いてもよい。`run()` だけなら期待 `O(m log(n + 1))` である。対数因子は 1 個であり、この上界は入力列によっては漸近的にタイトになる。

データ構造本体の最悪計算量は 1 操作 O(n)、`run()` 全体 O(mn) である。ハッシュ表の最悪衝突まで含めた全工程の決定論的上界は

```text
O(n + q + m n + m^2)
```

である。空間計算量は Θ(n + q) である。`disconnect` 1 回の再帰深さの期待値は O(log(n + 1)) だが、最悪補助スタックは O(n) である。

以下でこれらを証明する。

## 3. アルゴリズムの構造

追加された辺 `e` の削除時刻を `d(e)` とする。削除されない辺については `d(e) = +∞` とみなし、実装は辺重み

```text
w(e) = -d(e)
```

を `S` に記録する。削除されない辺の番兵は `-INT_MAX` である。

`run()` はクエリを先頭から再生し、現在存在する辺の重み最小全域森を維持する。辺を追加して閉路ができた場合、新辺より重い閉路上の最大重み辺を差し替える。時刻 `t` に削除される辺の重みは `-t` であり、その時点で生存する他の辺の削除時刻は `t` より後なので、それらの重みは `-t` より小さい。したがって、削除される森辺を切ったときに代替辺を探す必要はない。

この最小全域森を辺そのものとしては保持せず、次のレベル付きポインタ森で表す。

- `P[x]`: `x` の親。根では `P[x] = x`。
- `W[x]`: `x` のクラスタが `P[x]` のクラスタに併合される重みレベル。根では番兵 `1`。
- `rd[x]`: ランダム優先度。

`sub_add` が新しい親リンクを作る唯一の箇所であり、必ず優先度の小さい代表を大きい代表の子にする。このため常に

```text
x != P[x] なら rd[x] < rd[P[x]]                       (H)
```

が成り立つ。`P[x] = P[P[x]]` という短絡も (H) を保存し、切断はリンクを削除するだけなので、(H) は実行全体を通じた不変条件である。

## 4. 抽象クラスタ鎖とポインタ経路

計算量証明の核心は、重みの単調性が壊れた未圧縮リンクも含めて `D(x)` を評価することである。そのために、まず実装が暗黙に保持する抽象的なクラスタ鎖を定義する。

### 4.1 クラスタ鎖

頂点 `x` に対するクラスタ鎖とは、`x` を含む頂点集合の狭義包含列

```text
C_0 ⊊ C_1 ⊊ ... ⊊ C_k,    x ∈ C_0
```

である。各クラスタの代表を

```text
r_i = argmax { rd[v] | v ∈ C_i }
```

とする。包含列なので、一度代表が `a` からより高優先度の `b` に変わると、後で `a` に戻ることはない。

列 `(r_0, ..., r_k)` から連続する同じ値を 1 個に縮約した列を、このクラスタ鎖の **record 列** と呼ぶ。

### 4.2 経路表現補題

**補題 1（未圧縮経路の record 表現）**

各公開クエリの処理開始時点において、任意の固定頂点 `x` の未圧縮 `P` 経路は、`rd` と独立に定まるクラスタ鎖の record 列の部分列である。`sub_add` の実行途中に走査される 2 本の鎖についても同じ性質が成り立つ。

**証明。** クエリ列に沿った帰納法で示す。

初期状態では各頂点が単独クラスタ `{x}` なので成立する。

`disconnect` は `sum, sz` を先祖から減算するだけで `P, W` を変更しない。`connect` も `sum, sz` を加算しながら既存の `P` を歩くだけである。よって両者は record 表現を変更しない。

`find` と `sub_del` の内側にある

```cpp
P[u] = P[P[u]];
```

は、`u` の record 列から現在の親を 1 個削除する操作である。`u` の部分木にある頂点の経路も、`u` 以降で同じ親を 1 個失うだけであり、それ以外の経路は変化しない。従って全経路が以前の record 列の部分列となり、補題を保存する。

`sub_del` の

```cpp
P[u] = u;
W[u] = 1;
```

は 1 本の鎖をその位置で 2 本に切る。切断後の各経路は切断前の経路の連続部分であり、それぞれ対応するクラスタ鎖の部分鎖で表せる。辺差し替え中の切断では、直後の `sub_add` と合わせて以下の鎖マージになる。

残るのは `sub_add` による親リンク生成である。途中の `find(u) == find(v)` が真なら新しいリンクを作らず、短絡済みの鎖を `connect` で閉じるだけなので、すでに扱った場合に帰着する。以下では 2 成分を実際に併合する場合を考える。

`sub_add` の開始時に 2 本の既存クラスタ鎖を考える。各包含 `C_i ⊊ C_{i+1}` には、それを生じさせた重みレベルを付記しておく。このレベル付きクラスタ鎖も帰納的に端点と辺重みだけから定まり、`rd` に依存しない。短絡によって物理経路から消えた record は抽象鎖には残してよい。コードがそれを走査しないことは、最終的な物理経路を完全な record 列の部分列にするだけだからである。新しい重み `w` で両側のクラスタを併合した集合も同様に `rd` と独立である。

`sub_add` のループ不変条件を次のように取る。

1. すでに処理した下位部分は、2 本のレベル付きクラスタ鎖を重み順にマージした結果の record を表す。
2. `u`, `v` は両鎖の未処理部分の現在の代表である。
3. 変数 `w` は次に処理する包含・併合レベルである。

ループ進入時には、まだ何もマージしていないので成立する。

ループ先頭の

```cpp
u = connect(u, w);
v = connect(v, w);
```

は、両方の鎖を「次に重み `w` で併合すべきクラスタ」まで単調に進める。その後

```cpp
if (rd[u] < rd[v]) swap(u, v);
P[v] = u;
W[v] = w;
```

とする。併合前の 2 クラスタを `A, B` とすると、`u, v` はそれぞれ `argmax_rd A`, `argmax_rd B` である。比較後の `u` は

```text
argmax_rd(A ∪ B)
```

であり、負けた代表 `v` から勝った代表 `u` へのリンクを作ることは、クラスタ鎖に `A ∪ B` を追加したときに生じる record の変化をちょうど 1 個表す。

この操作でレベル `w` の和集合が処理済みになり、ループ不変条件 1 が 1 段進む。さらに、書き換え前の

```cpp
np = P[v];
nw = W[v];
```

を保存し、反復末尾で `u = np, w = nw` とする。従って次の反復は、負けた代表が元々属していた鎖の未処理部分から、その次の包含レベル `nw` を処理する。勝った代表側は和集合の代表としてその場に残る。このためループ不変条件 2, 3 も保存される。

従ってループ全体は 2 本のレベル付きクラスタ鎖を重み順に安定マージし、和集合クラスタの代表が変わる箇所だけをリンクとして出力する。マージされる集合とその順序は端点と重み列だけで決まり、優先度比較は各和集合にどの頂点名を付けるかだけを決める。

書き換えた代表 `v` の既存の側枝 `y` も確認する。`y` の鎖で `v` が代表となるクラスタを `A_y`、その包含レベルを `W[y]` とする。新しい併合レベル `w` が `W[y]` 以上なら、併合される和集合はその時点ですでに `A_y` 全体を含む。

`w < W[y]` なら、`v` の新しい親側でレベル `w` 以後に現れるクラスタを包含順に `B_0 ⊊ B_1 ⊊ ...` とする。`y` 用の抽象クラスタ鎖には

```text
A_y ⊊ A_y ∪ B_0 ⊆ A_y ∪ B_1 ⊆ ...
```

を追加し、等しい集合は除く。この列は入れ子であり、既存のレベル付き鎖と新しい辺だけから決まるので `rd` と独立である。`v` は `A_y` の最大優先度であり、`v` より高い record が親側に現れるたびに、その頂点は対応する `A_y ∪ B_i` の最大優先度になる。従って物理経路 `... -> y -> ... -> v -> u -> ...` はこの和集合列の record である。

これがコード上で `W[y] >= W[v]` という stale リンクとして見える場合である。実際の重み閾値クラスタではない集合を抽象鎖に追加しているが、計算量証明に必要なのは `rd` と独立な入れ子集合列であって、各集合が現在のグラフの閾値連結成分であることではない。後の短絡はこの record 列から要素を削除するだけである。

以上より、`sub_add` 後も全頂点の経路について `rd` と独立なクラスタ鎖が存在する。また、ループはその 2 本の record 列を前から消費しているので実行途中の走査鎖にも同じ性質がある。帰納法により補題が示された。∎

この補題で重要なのは、「現在の重み閾値成分だけからなる正規化済み経路」ではなく、stale リンクを含む未圧縮経路を評価している点である。従って stale リンクの生成総数を別のポテンシャルで償却する必要はない。

## 5. 未圧縮経路長の期待値

**補題 2（record 数）**

`rd` と独立な任意のクラスタ鎖

```text
C_0 ⊊ C_1 ⊊ ... ⊊ C_k
```

の record 列の長さを `L` とすると、

```text
E[L] <= 1 + ln n
```

である。

**証明。** `s_i = |C_i|` と置く。`C_{i-1}` から `C_i` へ拡大したときに代表が変わるのは、`C_i \ C_{i-1}` のいずれかが `C_i` 全体の最大優先度を持つ場合に限り、かつその場合に必ず変わる。一様ランダム順列の対称性から

```text
Pr[r_i != r_{i-1}]
  = (s_i - s_{i-1}) / s_i
  = 1 - s_{i-1} / s_i.
```

`0 < z <= 1` に対する `1 - z <= ln(1/z)` を使うと、期待値の線形性より

```text
E[L]
  = 1 + sum_{i=1}^k Pr[r_i != r_{i-1}]
  <= 1 + sum_{i=1}^k ln(s_i / s_{i-1})
  = 1 + ln(s_k / s_0)
  <= 1 + ln n.
```

各事象の独立性は使用していない。必要なのは各 `C_i` が `rd` と独立であることだけである。∎

補題 1 の未圧縮 `P` 経路は record 列の部分列なので、直ちに次を得る。

**定理 3（未圧縮経路長）**

任意のクエリ境界、任意のクエリ列によって固定された頂点 `x` について、

```text
E[D(x)] <= 1 + ln n = O(log(n + 1)).
```

これは償却評価ではなく、各時点・各固定頂点に対する期待値評価である。

## 6. 各内部処理の決定論的コスト

ここでは乱数について平均を取る前に、1 つの固定された `P` の状態で各処理が何ノードを触るかを評価する。

### `find(u)`

外側ループは `u` を親へ進める。内側ループの 1 反復は `P[u]` をその祖父へ進める。いずれも開始時の `u` の根経路上を上向きにしか動かず、新しいノードを経路へ挿入しない。従って `O(D(u))`。

### `disconnect(u)` と `connect(u, w)`

ともに `u` の根経路またはその接頭部分を 1 回歩くので `O(D(u))`。`disconnect` の再帰深さも `D(u)` である。

### `max_edge(u, v)`

最初の 2 回の `find` と、その後の合流点までの走査は、`u, v` の 2 本の根経路だけを上向きに歩く。従って `O(D(u) + D(v))`。

### `sub_add(u, v, w)`

最初の 2 回の `disconnect` は `O(D(u) + D(v))`。マージループでは、各反復で 2 本の走査鎖の少なくとも一方の record を 1 個消費する。`connect` が 1 回に複数ノードを飛ばしても、それらのノードは以後同じ入力鎖から再び消費されない。従って全反復を合計した `connect` の走査回数と親の付け替え回数は `O(D(u) + D(v))`。最後の `connect(u)` を含めても同じ上界である。

### `sub_del(u, v, w)`

対象重みを探す走査、単調性違反の短絡、切断後に `sum, sz` を全先祖から引く走査は、いずれも `u` の根経路上である。末尾の `find(u)`, `find(v)` まで含めて `O(D(u) + D(v))`。対象辺が森にない場合は探索が根まで空振りするだけなので同じ上界である。

### `inner_add_point(u, value)`

短絡せず `u` から根までを 1 回歩くので、正確に Θ(`D(u)`)。圧縮しないことは最悪計算量には影響するが、定理 3 は未圧縮経路を評価しているため、期待計算量の証明には隙間を作らない。

### 乱数依存の内部頂点への注意

`max_edge` が返す `p` は `rd` に依存するので、「固定頂点 `p` に対する定理 3」をそのまま適用してはならない。しかし `p` と、差し替え時に `sub_del` が歩く経路は、直前に走査した固定端点 `u, v` の 2 本の経路の部分である。従ってその費用は `D(u) + D(v)` に決定論的にチャージできる。内部で選ばれた乱数依存頂点に期待深さの定理を適用する必要はない。

以上から、公開クエリ 1 個の処理時間は次の通りである。

| クエリ | 決定論的コスト | 期待コスト |
|---|---:|---:|
| `ADD` | O(`D(u) + D(v)`) | O(log(n + 1)) |
| `DEL` | O(`D(u) + D(v)`) | O(log(n + 1)) |
| `ADD_POINT` | Θ(`D(u)`) | O(log(n + 1)) |
| `GET_SUM` | O(`D(u)`) | O(log(n + 1)) |
| `GET_SIZE` | O(`D(u)`) | O(log(n + 1)) |
| `IS_SAME` | O(`D(u) + D(v)`) | O(log(n + 1)) |
| `GET_COUNT` | Θ(1) | Θ(1) |

従って、期待値の線形性から `run()` 全体は期待 `O(m log(n + 1))` である。経路長に関して操作列全体の償却を取る必要はない。

## 7. 前処理、総計、空間

コンストラクタは長さ `n` の配列を初期化・shuffle し、長さ `q` の `S` を初期化するので Θ(n + q)。クエリ登録は `vector` の償却と仮定 3 のハッシュ期待値のもとで 1 回期待償却 O(1)、合計期待 O(m)。`run()` の結果配列構築は Θ(m)。よって総期待計算量は

```text
O(n + q + m log(n + 1)).
```

配列 `P, W, rd, sz, sum` は Θ(n)、`S` は Θ(q)、`Q`, `res`, `mp` は O(m) であり、`m <= q` なので空間は Θ(n + q)。再帰スタック O(n) もこの漸近上界に含まれる。

## 8. 上界のタイトさと最悪計算量

### 期待 Θ(log n) が必要な操作列

具体的に頂点を `0, 1, ..., n-1` とし、まず辺

```text
(0,1), (1,2), ..., (n-2,n-1)
```

をこの順に追加する。次に頂点 `x = 0` への `add_point` を必要回数登録し、最後に上の辺を追加順の逆順で削除する。辺 `(i-1,i)` は `i` が大きいほど早く削除されるので、その重みは `i` とともに狭義増加する。従って `x` の経路上で `W` の単調性違反は起きず、この経路は `find` に短絡されない。

この操作列では頂点を 1 個ずつ既存成分へ連結するため、`x` を含むクラスタサイズが

```text
1, 2, ..., n
```

と増える。このとき `D(x)` はランダム順列の prefix maximum の個数であり、

```text
E[D(x)] = H_n = Θ(log n).
```

その状態で `add_point(x, value)` を繰り返すと、各回が同じ未圧縮経路を歩く。従って、非定数クエリについての期待 O(log n)、および `m = Ω(n)` の領域における全体の期待 O(m log n) は一般には O(1), O(m) へ改善できない。

### 乱数の最悪実現

同じ構成で優先度がクラスタ追加順に狭義増加する順列を引くと、`D(x) = Θ(n)` となる。そこで `add_point` を Θ(m) 回行えば Θ(mn) 時間になる。従ってデータ構造本体の最悪上界 O(mn) はタイトである。`disconnect` の再帰深さも同じ例で Θ(n) になり得る。

さらに `unordered_map` の仕様上の最悪 1 操作は O(m) なので、登録フェーズは最悪 O(m^2)。これを含む全工程の決定論的上界は

```text
O(n + q + m n + m^2).
```

## 9. 実装上の乱数について

実コードは

```cpp
shuffle(rd.begin(), rd.end(), mt19937(1321312));
```

と固定シードを使うため、プログラムそのものは決定論的である。本稿の期待計算量は、この順列を一様ランダムに選ぶという解析モデルに対する保証である。固定シードを知る入力生成者に対しては期待保証を主張できず、前節の Θ(mn) の入力を構成できる。

実行時に十分ランダムな seed を選び、入力列が seed と独立なら、本稿の期待 O(n + q + m log(n + 1)) が適用される。

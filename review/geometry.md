## 1. ファイル構成と数値モデル

### 自己完結性 (`195,206,247,259,301,320`)

6 箇所で `rep(i,n)` を使用していますが、このファイルにも、このファイルが読み込むファイルにも定義がありません。通常の `for` に置き換えなければ単独ではコンパイルできません。`numeric_limits` も使用していますが、`<limits>` を直接読み込んでいません。

`#pragma once` を付けてヘッダーのように使用されている一方で、ほとんどの自由関数は非 `inline` であり、大域名前空間にあります。複数の翻訳単位から読み込むと単一定義規則 (ODR) に違反します。また、`titan23` 内の他のライブラリと名前空間の規約が一致しません。

### 既定コンストラクタによる無効な状態 (`21-79`)

`Point()=default` は `x,y` を初期化しません。点で構成される `Line`, `Segment`, `Circle` も、既定コンストラクタで構築すると座標と半径が不定になります。既定コンストラクタによる構築を許可する場合は 0 などの有効な値で初期化するか、無効なオブジェクトを公開された操作に渡すことができない設計にする必要があります。

### 許容誤差 (`15-20`)

固定の絶対値 `EPS=1e-9` は座標の大きさに応じて変化しません。外積と内積の値は座標の 2 乗の大きさになり、`d1*d2` の値は 4 乗の大きさになります。想定する座標の範囲を明記するか、量の大きさに応じた絶対誤差と相対誤差を用いる必要があります。

誤差付きの `lessThan` を `sort` と `inplace_merge` の比較関数にも使用していますが、この比較は厳密弱順序を満たしません。値 `0`, `0.75*EPS`, `1.5*EPS` では、隣り合う値同士を同値として扱う一方で、最初と最後の値には `<` が成立するため、比較上の同値関係が推移的ではありません。このため、標準のソート関数が求める条件を満たしません。ソートには誤差補正なしの辞書式順序を使用し、許容誤差は幾何判定だけに使用すべきです。

該当箇所は、凸包の `271-274`、最近点対の併合の `341-343`、交差数の前処理の `370-372`、共通接線のソートの `557-562` です。

## 2. 点、直線、線分

### 退化した直線 (`109-154`)

`p1==p2` または `l.a==l.b` の場合は、射影の分母 `base.norm()` が 0 になります。例えば `projection((0,0),(0,0),(1,0))` は `0/0` を計算して NaN を返します。零ベクトルの外積と内積はともに 0 であるため、退化した `Line` は任意の点を「直線上」と判定し、他の線に対しても平行かつ直交と判定します。

退化した直線をコンストラクタで禁止するか、各関数で点として別に処理する必要があります。`distancePointToSegment` も射影を使用するため、同じ前提が必要です。

### 線分交差 (`157-175`)

狭義の交差を `lessThan(d1*d2,0)` で判定しているため、各外積が明確に 0 でなくても、積だけが `EPS` 以内になる場合があります。

```text
s1 = (0,0)--(1,0)
s2 = (0.5,-1e-5)--(0.5,1e-5)
```

上の線分は実際に交差しますが、外積はそれぞれ `±1e-5`、積は `-1e-10` であり、0 として扱われます。端点も直線上にはないため、結果は `false` になります。各外積を個別に負、零、正に分類してから符号を比較すべきです。

`getIntersection` は、`isIntersecting` が `true` であれば交点が一意であると仮定しています。共線で重なる線分 `(0,0)--(2,0)` と `(1,0)--(3,0)` では `d1=d2=0`, `t=0/0` になります。「一意な交点」と「重なる区間」を戻り値で区別する必要があります。

### 等価判定

`Line::operator==` は、保持している 2 端点が順序も含めて近似的に一致するかを判定します。そのため、同一の直線でも端点を逆にした場合や別の 2 点で表した場合は `false` になります。表現の一致であるのか、幾何学的な直線の一致であるのかを関数名で区別すべきです。`Circle::operator==` も一貫しておらず、中心だけを誤差付きで比較し、半径は厳密な `==` で比較しています。

## 3. 多角形・凸包

### 点の包含 (`217-265`)

反時計回りの凸多角形に対する `convexPolygonContainsPoint` の扇形分割と二分探索は、退化しておらず、頂点が順序どおりに並んだ入力では整合します。その向きと凸性を前提条件として明記する必要があります。

`isPointInsidePolygon` は説明では「辺上を含まない」としていますが、正方形の左辺上の点 `(0,0.5)` を `true`、右辺上の点 `(1,0.5)` を `false` と判定します。最初に `isPointOnPolygon` で境界を除外するか、外部、境界、内部の三値を返すべきです。

靴紐公式による面積と、通常の単純多角形に対する半直線法の主要部分は整合しますが、自己交差、頂点の重複、向きの扱いについては別に仕様を定める必要があります。

### `convexHull` (`268-293`)

同一の点を事前に除外しません。同一の点が 2 個の場合は `n==2` としてそのまま 2 点を返し、3 個の場合も点が重複した凸包を作成します。

`include_collinear=true` かつ全点が共線の場合は、3 点 `p0<p1<p2` から `{p0,p1,p2,p1}` を返します。上側の列と下側の列の両方が内部の点を保持した状態で結合されるためです。厳密弱順序でソートして同一の点を除外し、全点が共線の場合を別に処理する必要があります。

### `convexHullDiameter` (`295-314`)

各頂点からの距離が増加する間だけ `k` を進める局所的な探索であり、標準的な回転キャリパー法が使用する「辺に対する面積が増加する間は進める」という不変条件とは異なります。固定した頂点から各頂点までの距離の列は一般に単峰とは限らないため、この停止規則だけでは全組の最大値を保証する証明は得られません。

一方、本レビューでは具体的な誤答例も確定していないため、確定した不具合ではなく、正当性の証明が不足していると判定します。安全性を優先する場合は、標準的な対蹠点の回転キャリパー法に置き換えるべきです。

### `cutPolygon` (`316-330`)

切断線上の点を厳密な `>0` の判定で外側として扱い、隣接する辺ごとに交点として再び挿入するため、線上の頂点が重複したり、線上の辺がなくなったりします。符号付き距離を負、零、正に分類し、線上の点を保持するか除外するかについて一貫した規則を定めたうえで、重複した点を除外する必要があります。

### `closestPair` (`334-355`)

x 座標でソート済みの初回の入力、有効な `[l,r)`、y 座標の厳密弱順序による併合という条件がそろえば、分割統治と中央の帯状領域の走査は `O(n log n)` で整合します。現在は誤差付きの比較が併合に必要な順序の条件を満たさないため、標準アルゴリズムの保証が失われています。

## 4. 軸平行線分の交差数 (`357-403`)

実装は水平線分の開始と終了、および垂直線分の問い合わせだけを処理しますが、関数名と説明からは一般の線分を対象とするように見えます。斜めの線分を垂直線分として `seg.a.x` だけで処理し、水平線分同士や垂直線分同士の重なりも個数に含めません。軸平行な水平線分と垂直線分の交差専用であることを、名称と入力のチェックで示す必要があります。

有効な水平線分を保持する集合が `set<Real>` であるため、同じ y 座標の水平線分を複数保持できません。水平線分 `[0,2]×{0}`, `[0,4]×{0}` と垂直線 `x=1` の交差は 2 個ですが、1 個として扱います。短い線分の終了時には同じキーを削除するため、長い線分も削除されます。`multiset` で 1 件だけ削除するか、座標圧縮したうえで頻度を保持するデータ構造が必要です。

返り値も `int` であり、水平線分 46341 本と垂直線分 46341 本が全て交差すると `INT_MAX` を超えます。`distance(lower,upper)` は双方向反復子を線形に走査するため、計算量は `O(n log n + K)` です。個数を `O(log n)` で求めるには Fenwick 木などが必要です。

同じ x 座標のイベントは開始、垂直線、終了の順に処理されるため、端点での接触を交差に含める規則としては一貫しています。

## 5. 円

### 円同士の分類 (`405-416`)

`countCirclesIntersection` は交点の個数ではなく、共通接線の本数に近い `4,3,2,1,0` を返します。半径 1、中心間の距離 3 の 2 円は交点が 0 個ですが、4 を返します。同一の円は交点が無限個ですが 1 を返すため、接線の本数として解釈する場合も、退化した入力は別に処理する必要があります。関数名と戻り値の意味を一致させるべきです。

### 内接円・外接円 (`418-436`)

退化していない三角形では、辺の長さを重みとする内心の式と外心の公式は整合します。`A=B=C` の場合は周長が 0、共線の 3 点の場合は面積または外心の分母 `D` が 0 になります。内接円や外接円が一意に定まらない入力を検出し、成否を別に返す必要があります。Heron の公式の平方根の中の値も、細長い三角形では丸め誤差により負になる可能性があります。

### 円と直線 (`439-470`)

判別式が負の場合は `res` が空のままですが、末尾で無条件に `res[0],res[1]` を参照します。単位円と直線 `x=2` を渡すだけで範囲外参照になります。要素数を確認してからソートする必要があります。

`p1==p2` の場合は二次の係数が `a=0` となり、直線が円に接する場合は同じ点を 2 個返します。退化した直線を禁止し、返す点の個数の仕様を明示すべきです。通常の二次方程式の公式も、`b` と平方根の値が近い場合には桁落ちが発生する可能性があります。

### 2 円の交点 (`473-494`)

同一の円では `d=0` のまま `a=(...)/(2*d)` の計算に進み、座標が NaN の点を 2 個返します。円同士が接する付近では、`r1^2-a^2` が丸め誤差によりわずかに負になる可能性があります。先に同心円を分類し、存在判定と許容誤差を統一したうえで、平方根の中の値が誤差の範囲内にある場合は 0 に丸める必要があります。

### 点からの接線 (`496-519`)

半径が非負、座標が有限、点が円外または円上という条件では、接点の公式は整合します。関数名からは直線を返すように見えますが、戻り値は接点です。

### 2 円の共通接線 (`522-555`)

外接線と内接線で、角度と第 2 円側の符号の対応に誤りがあります。`c1=(0,0,1)`, `c2=(4,0,1)` では、前半は `y=±sqrt(3)/2` を返しますが、中心からの距離が 1 ではありません。後半も中心からの距離が `2/sqrt(5)` の線分を返すため、4 本とも接線ではありません。

正しい対応は次のとおりです。

- 外接線: `acos((r1-r2)/d)`、両円の接点方向は同符号
- 内接線: `acos((r1+r2)/d)`、第 2 円の接点方向は逆符号

許容誤差により境界条件を真と判定した場合、`acos` の引数がわずかに `[-1,1]` から外れる可能性もあるため、その範囲に丸める必要があります。

### 半径の前提条件

`Circle` のコンストラクタは負の半径を受け付けます。負の半径では交差の分類、包含、接線の本数の意味が成立しないため、構築時に `r>=0` を条件とすべきです。

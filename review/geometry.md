# `titan_cpplib/geometry` 理論レビュー

レビュー日: 2026-08-12
対象: `geometry.cpp` 1ファイル、全564行

## 結論

テスト・コンパイル・実行は行わず、外積の符号、退化入力、浮動小数点の比較、凸包、平面走査、円の解析式を静的に追った。このファイルは未定義マクロ`rep`を使うため自己完結しておらず、通常のヘッダーとしてまずコンパイルできない。これを除いても、線分交差の符号判定、交点がない円と直線、共通接線、軸平行線分の交差数に確定問題がある。

| 重要度 | 対象 | 要点 |
|---|---|---|
| 重大 | ファイル全体 | `rep`が未定義。非`inline`の大域関数群による多重定義 |
| 重要 | `isIntersecting` | 外積同士を掛けて`EPS`と比較し、実際に交差する線分を`false`とする |
| 重要 | `getIntersection` | 共線重複を交差と認めた後に`0/0`を計算 |
| 重要 | `countIntersections` | 軸平行線分専用だが一般的な名前。同じy座標の多重度を失う |
| 重要 | `getCircleLineIntersection` | 交点がない空の`vector`を無条件で添字参照 |
| 重要 | `getCommonTangentsLine` | 外接線・内接線の角度と第2円側の符号が混線 |
| 重要 | 円の退化入力 | 同一円、共線3点、1点だけの直線、負半径を処理しない |

## 1. ファイル構成と数値モデル

### 自己完結性 (`195,206,247,259,301,320`)

6箇所で`rep(i,n)`を使うが、このファイル自身にも読み込み先にも定義がない。通常の`for`へ置き換えなければ単独でコンパイルできない。`numeric_limits`も使うが、`<limits>`を直接読み込んでいない。

`#pragma once`付きでヘッダーのように使われる一方、ほぼ全ての自由関数は非`inline`かつ大域名前空間にある。複数の翻訳単位から読み込むと一意定義規則に違反し、`titan23`内の他のライブラリとも名前空間の規約が一致しない。

### 無効な既定状態 (`21-79`)

`Point()=default`は`x,y`を初期化せず、そこから構成される`Line`, `Segment`, `Circle`の既定オブジェクトも座標・半径が不定である。既定構築を許すなら0などの有効値を入れるか、無効なオブジェクトを公開操作へ渡せない設計が必要である。

### 許容誤差 (`15-20`)

固定絶対値`EPS=1e-9`は座標の大きさに追従しない。外積・内積では座標の2乗、`d1*d2`では4乗の大きさになる。想定する座標範囲を明記するか、量の大きさに応じた絶対・相対誤差を用いる必要がある。

誤差付き`lessThan`を`sort`と`inplace_merge`の比較関数にも使うが、厳密弱順序にならない。値`0`, `0.75*EPS`, `1.5*EPS`では前二組を同値扱いする一方、最初と最後には`<`が成立し、比較上の同値関係が推移的でない。標準の整列関数が要求する条件を満たさない。並べ替えには誤差補正なしの辞書式順序を使い、幾何判定だけに許容誤差を使うべきである。

該当箇所は凸包`271-274`、最近点対の併合`341-343`、交差数の前処理`370-372`、共通接線の整列`557-562`である。

## 2. 点、直線、線分

### 退化した直線 (`109-154`)

`p1==p2`または`l.a==l.b`では、射影の分母`base.norm()`が0となる。例えば`projection((0,0),(0,0),(1,0))`は`0/0`でNaNを返す。零ベクトルの外積・内積はともに0なので、退化した`Line`は任意の点を「直線上」とし、他の線と平行かつ直交とも判定する。

退化直線をコンストラクタで禁止するか、各関数で点として別処理する必要がある。`distancePointToSegment`も射影を通るため、同じ前提を受ける。

### 線分交差 (`157-175`)

狭義の交差を`lessThan(d1*d2,0)`で判定するため、各外積は明確に0でなくても、積だけが`EPS`以内になる。

```text
s1 = (0,0)--(1,0)
s2 = (0.5,-1e-5)--(0.5,1e-5)
```

は実際に交差するが、外積は各`±1e-5`、積は`-1e-10`で0扱いされる。端点も直線上ではないため`false`となる。各外積を個別に負・零・正へ分類してから符号を比較すべきである。

`getIntersection`は`isIntersecting`が`true`なら交点が一意だと仮定する。共線重複`(0,0)--(2,0)`と`(1,0)--(3,0)`では`d1=d2=0`, `t=0/0`となる。「一意な交点」と「重複区間」を戻り値で区別する必要がある。

### 等価判定

`Line::operator==`は保存した2端点の順序付き近似一致であり、同一直線でも端点を逆にした場合や別の2点で表した場合は`false`となる。表現の一致なのか、幾何学的な直線の一致なのかを関数名で区別すべきである。`Circle::operator==`も中心だけが誤差付きで、半径は厳密な`==`となり一貫しない。

## 3. 多角形・凸包

### 点の包含 (`217-265`)

反時計回りの凸多角形に対する`convexPolygonContainsPoint`の扇形分割と二分探索は、非退化・順序済み入力で整合する。その向きと凸性を契約に明記する必要がある。

`isPointInsidePolygon`は説明上「辺上を含まない」が、正方形の左辺上`(0,0.5)`を`true`、右辺上`(1,0.5)`を`false`とする。最初に`isPointOnPolygon`で境界を除くか、外部・境界・内部の三値を返すべきである。

靴紐公式による面積と、通常の単純多角形に対する半直線法の核は整合するが、自己交差・頂点重複・向きの意味は別途契約が必要である。

### `convexHull` (`268-293`)

同一点を事前に除かない。2個の同一点は`n==2`でそのまま2点を返し、3個でも重複した凸包を作る。

`include_collinear=true`かつ全点共線では、3点`p0<p1<p2`から`{p0,p1,p2,p1}`を返す。上側列と下側列の双方が内部点を保持した後に結合するためである。厳密弱順序で整列して同一点を除き、全共線の場合を分ける必要がある。

### `convexHullDiameter` (`295-314`)

各頂点からの距離が増える間だけ`k`を進める局所的な探索であり、標準的な回転キャリパー法が使う「辺に対する面積が増える間進める」という不変条件とは異なる。固定頂点からの頂点距離列は一般に単峰とは限らないため、この停止規則だけから全組の最大値を保証する証明は得られない。

一方、本レビューでは具体的な誤答例も確定していないため、確定不具合ではなく、正当性の証明が不足していると判定する。安全性を優先するなら、標準的な対蹠点の回転キャリパー法へ置き換えるべきである。

### `cutPolygon` (`316-330`)

切断線上を厳密な`>0`で外側扱いし、隣接辺ごとに交点として再挿入するため、線上の頂点が重複したり線上の辺が消える。符号付き距離を負・零・正へ分け、線上を保持するか除くか一貫した規則を定め、重複点を除く必要がある。

### `closestPair` (`334-355`)

x座標で整列済みの初回入力、有効な`[l,r)`、y座標の厳密弱順序による併合があれば、分割統治と中央帯の走査は`O(n log n)`で整合する。現在は誤差付き比較が併合の順序要件を満たさないため、標準アルゴリズム上の保証が失われる。

## 4. 軸平行線分の交差数 (`357-403`)

実装は水平線分の開始・終了と垂直線分の問い合わせだけを扱うが、関数名と説明は一般線分に見える。斜線を垂直線分として`seg.a.x`だけで処理し、水平同士・垂直同士の重なりも数えない。軸平行の水平対垂直専用であることを名称と検査で表す必要がある。

有効な水平線分を保持する集合が`set<Real>`なので、同じy座標の水平線分を複数保持できない。水平`[0,2]×{0}`, `[0,4]×{0}`と`x=1`の垂直線は2交差だが1と数える。短い線分の終了時には、同じキーを削除して長い線分まで消す。`multiset`で1件だけ削除するか、座標圧縮した頻度構造が必要である。

返り値も`int`で、水平46341本と垂直46341本が全て交差すれば`INT_MAX`を越える。`distance(lower,upper)`は双方向反復子を線形走査するため、計算量は`O(n log n + K)`である。個数を`O(log n)`で得るにはFenwick木などが必要である。

同じx座標の事象順は開始、垂直線、終了なので、端点接触を数える規則としては一貫する。

## 5. 円

### 円同士の分類 (`405-416`)

`countCirclesIntersection`は交点数でなく、共通接線本数に近い`4,3,2,1,0`を返す。半径1、中心距離3の2円は交点0個だが4を返す。同一円は交点が無限個だが1を返すため、接線本数としても退化入力は別処理が必要である。関数名と戻り値の意味を一致させるべきである。

### 内接円・外接円 (`418-436`)

非退化三角形では、内心の辺長重みと外心公式は整合する。`A=B=C`では周長0、共線3点では面積または外心の分母`D`が0となる。内接円・外接円が一意でない入力を検出し、成否を別に返す必要がある。Heronの公式の平方根内も、細長い三角形では丸めにより負になり得る。

### 円と直線 (`439-470`)

判別式が負なら`res`は空のままだが、末尾で無条件に`res[0],res[1]`を読む。単位円と直線`x=2`だけで範囲外参照となる。要素数を確認してから並べ替える必要がある。

`p1==p2`では二次係数`a=0`となり、接線時は同じ点を2個返す。退化した直線を禁止し、返す点数の仕様を明示すべきである。通常の二次方程式の公式も、`b`と平方根が近い場合に桁落ちし得る。

### 2円の交点 (`473-494`)

同一円は`d=0`のまま`a=(...)/(2*d)`へ進み、NaNの点を2個返す。接触付近では`r1^2-a^2`が丸めによりわずかに負となり得る。先に同心円を分類し、存在判定と許容誤差を統一し、誤差範囲の平方根内を0へ丸める必要がある。

### 点からの接線 (`496-519`)

非負半径、有限座標、点が円外または円上という条件では接点の公式は整合する。関数名は直線を返すように見えるが、戻り値は接点である。

### 2円の共通接線 (`522-555`)

外接線・内接線の角度と第2円側の符号が混線している。`c1=(0,0,1)`, `c2=(4,0,1)`では、前半が`y=±sqrt(3)/2`（中心からの距離が1でない）、後半も中心からの距離`2/sqrt(5)`の線分を返し、4本とも接線でない。

正しい対応は次である。

- 外接線: `acos((r1-r2)/d)`、両円の接点方向は同符号。
- 内接線: `acos((r1+r2)/d)`、第2円の接点方向は逆符号。

許容誤差により境界条件を真とした際、`acos`の引数がわずかに`[-1,1]`を外れる可能性もあるため、その範囲へ丸める必要がある。

### 半径の契約

`Circle`のコンストラクタは負半径を許す。負半径では交差分類、包含、接線数の意味が成立しないため、構築時に`r>=0`を要求すべきである。

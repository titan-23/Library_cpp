## 結論

テスト・コンパイル・実行は行わず、木の親子関係と訪問順、経路上の演算順、最短路の番兵値、参照先の寿命、計算量を静的に追った。優先して利用を止めるべきものは、未定義名を参照する`centroid_decomposition.cpp`、有向辺の追加関数と無向二部判定を混在させる`graph.cpp`、非可換演算を逆順に併合する`rerooting_dp.cpp`、空入力と一時値の寿命に問題がある`hungarian.cpp`である。

| 重要度 | 対象 | 要点 |
|---|---|---|
| 重大 | `centroid_decomposition.cpp` | メンバーにも局所にもない`n`を参照。空入力では結果も未初期化 |
| 重大 | `graph.cpp` | 有向`add_edge`を無向二部判定へ使うと、二部グラフを`false`と判定 |
| 重要 | `rerooting_dp.cpp` | 接尾積と全積が非可換演算で逆順 |
| 重大 | `hungarian.cpp` | 空行列・行長不一致、一時行列への参照、算術範囲 |
| 重要 | `rooted_tree.cpp` | 距離`-1`を訪問済み判定と兼用し、負辺と符号なし型で破綻 |
| 重要 | `k_nearest_sources.cpp` | `K==0`で範囲外。記載された計算量も過小 |
| 重要 | 最短路群 | 有限距離の加算、番兵値の範囲、型の条件が不足 |

以下の「本体整合」は、非空・連結・単純な無向木、非負辺など、各項で示す契約内での判定である。

## 1. コンパイル、初期状態、参照先の寿命

### `centroid_decomposition.cpp:55-85`

`solve`内の`n`はテンプレート引数に依存しない名前だが、メンバーにも局所変数にも存在しない。コンストラクタ引数`int n`はコンストラクタ本体だけの名前なので、`solve`からは見えない。このため通常の解析でコンパイル不能である。`G.empty()`などを使うべきである。

空グラフを受けるコンストラクタは`C`を初期化せずに戻るため、上を直しても`get_result()`が不定値を返す。初期化子で`C=-1`などを設定する必要がある。

分解本体は連結な木専用である。閉路では親だけを除外する再帰が循環し、森では頂点0の成分しか処理しない。

### `hungarian.cpp:23,115-183`

空行列で`_cost[0]`を読み、`min_cost_assignment({})`からも到達する。各行を同じ幅として読むため、行ごとの長さが異なる行列も範囲外参照となる。

`cost`を参照メンバーとして持つため、次の通常に見える構築は参照先を失う。

```cpp
Hungarian<int> h(vector<vector<int>>{{1}});
// 文末で一時vectorが破棄される
h.solve();
```

行列を値で保持するか、一時値からの構築を禁止し、参照先の寿命を明示する必要がある。被覆費用、双対値の更新、総費用は加減算の中間値も型に収まることを要する。浮動小数点での`diff==0`も数値的に不安定である。

### 無効な既定状態

`dijkstra_path.cpp`など、一部の既定コンストラクタは必要なグラフと要素数を構築しない。既定オブジェクトから問い合わせを許さないなら、既定コンストラクタを削除するか、有効な空状態と範囲検査を持たせるべきである。

## 2. 有向グラフと無向グラフの意味

### `graph.cpp:27-74,152-162`

`add_edge`は`G[u]`だけへ追加する有向辺の関数だが、`is_bipartite`はその隣接だけをたどりながら無向グラフの二部判定を意図している。頂点0,1へ`add_edge(1,0)`だけを追加すると、0を色0の独立成分として確定した後、1も色0で開始して`1->0`を見て`false`を返す。辺1本の無向グラフは二部なので誤答である。

最小全域木も`E`を無向の候補辺として扱う。`add_directed_edge`と`add_undirected_edge`を分離し、無向アルゴリズムは対称表現が保証された入力だけに適用すべきである。

同クラスの`static const int inf`は、`vector`コンストラクタの参照引数へ渡され、実体を必要とする使われ方をするが、名前空間内の定義がない。C++17以降なら`inline static constexpr`にするべきである。

`topological_sort`は閉路があると部分列を返すため、成功は結果の要素数で判定するという契約が必要である。

## 3. 木アルゴリズム

### `rerooting_dp.cpp:51-63`

隣接寄与が順に`A,B,C`、`merge`が文字列連結なら、接尾積の構築と頂点の全積は`CBA`になる。非可換モノイドを扱えるように見える宣言に対して、順序が逆である。

接尾積は概念上

```text
rs[i] = contribution[i] op contribution[i+1] op ...
```

でなければならない。後ろからの反復でも`merge(current, suffix)`の順にする必要がある。可換演算だけを扱うなら明記すべきである。`n==0`では`pdx[0]`が範囲外となり、非連結なら親子順配列の要素数を越えるため、非空の連結木という契約も必要である。

### `rooted_tree.cpp:65-75,177-264`

根からの距離`dep_weight==-1`を未訪問の番兵にも使う。鎖`0 --(-1)-- 1 --(2)-- 2`では頂点1が一度-1となり、戻り辺から未訪問と再判定され、距離が上書きされる。訪問状態は距離と分離しなければならない。

直径計算で`T max_d=-1`とするため、符号なし`T`では最大値となる。1頂点でも端点`u`が-1のまま、次の幅優先探索が負の添字を使う。端点を有効な頂点で初期化すべきである。2回の最遠点探索で直径を求める方法は非負辺の木が前提で、負辺では直径を保証しない。

重軽分解を使う`lca`, `la`, `path_kth`, `is_ancestor`自体は、有効な木で整合する。

### `euler_tour.cpp:43-185`

`n==0`で`2*n-1`が-1となり、巨大な`size_t`へ変換され、根も範囲外となる。非空、有効な根、`vertexcost.size()==n`、連結な木を検査する必要がある。

`lca_mul({})`は逆転した区間をセグメント木へ渡す。`set_edge(u,v)`は親子でない2頂点を渡すと、経路総和を1辺の現在値と誤認するため、`par[u]==v || par[v]==u`が必須である。

符号なし型の加減算も`2^W`を法とする加法群をなし、入場`+w`と退場`-w`はその意味で相殺する。必要条件は演算型が加法群であることと、利用側が剰余としての値を受け入れることである。

### LCA、重軽分解、木ハッシュ

- `lca.cpp`は非空・連結・単純な無向木なら、行きがけ順の親配列上のRMQとして整合する。閉路では積む時点で訪問済みにしないため同じ頂点を複数回積み、森では未訪問の`nodein==-1`を残す。
- `hld.cpp`は同じ契約下で部分木サイズ、重い子、鎖の先頭、行きがけ番号を正しく構築するが、内部の複製`G`から親辺を削除し、重い子を先頭へ移す。公開された`G`の意味は元の隣接リストと異なる。`build_list`は入力要素数`n`を要する。
- 重軽分解の補助クラスによる経路問い合わせは、鎖が`O(log N)`本あり、各区間のセグメント木処理が`O(log N)`なので、最悪`O(log^2 N)`である。`hld_segment_tree`, `hld_edge_segment_tree`, `hld_edge_lazy_segment_tree`の一部説明は過小である。
- `hld_edge_lazy_segment_tree`の別引数`n`は`hld.n`と一致しなければならず、小さいとセグメント木の範囲外となる。
- 辺用の補助クラスは、両向きの隣接リスト双方に同じ重みがあることを要する。
- `hashed_rooted_tree.cpp`は連結な根付き木なら確率的ハッシュの再帰式は整合する。乱数の上限が法自身を含み、確率的に0と同値になるため、`MOD-1`までにすべきである。閉路では再帰が循環する。
- `namori.cpp`も非空・連結・対称な無向表現・辺数Nを要する。`n=0`は`NDEBUG`指定時に負の添字へ進み、ハッシュ用乱数にも同じ上限問題がある。
- `perfect_binary_tree.cpp::la`は`k<0`または型のビット幅以上の移動が未定義動作となる。有効な符号付き頂点番号と移動幅を検査する必要がある。

## 4. 最短路と距離の数値条件

### Dijkstra法 (`dijkstra.cpp`, `dijkstra_path.cpp`)

非負辺と安全な加算の下で、優先度付き待ち行列と古い候補を捨てる処理は整合する。有限距離`d`と辺重み`c`の`d+c`は上限を検査せず、`T=int`, `d=INT_MAX-1`, `c=10`なら符号付き整数の未定義動作となる。単に`INF`を最大値にするだけでは防げず、全ての有限経路と中間和が型に収まる必要がある。

負辺ではDijkstra法の確定順序と計算量保証がなく、到達可能な負閉路では更新が止まらない。

### Warshall--Floyd法 (`warshall_floyd.cpp`, `warshall_floyd_path.cpp`)

通常版の本体、多重辺の最小値、経路復元版の次頂点更新、負閉路の伝播は、番兵値の契約内で整合する。必要条件は次である。

- `T`が符号付き順序型で`0<INF`、`-INF`が表現可能。
- 到達可能な全ての有限な部分距離が`(-INF,INF)`内。
- 加算の中間値が型に収まる。

各辺だけが範囲内でも不十分である。`INF=100`, 辺`0->1=60`, `1->2=60`, `2->3=-50`では真の`dist(0,3)=70`だが、中間値120を`INF`へ丸めたため、その後の-50を拾えない。到達可否を数値の番兵と分けるか、問題制約から全ての有限距離を包む`INF`を選ぶ必要がある。符号なし型では`-INF`が折り返し、比較が成立しない。

通常版と経路復元版の動的`add_edge`は、単純な非負辺限定ではない。新辺を複数回使う歩道が有利なら、その中に負閉路があり、実装は負閉路として伝播する。ただし上の数値条件は必須である。

### SIMD版

`warshall_floyd_simd.cpp`と`warshall_floyd_simd_nonnegative.cpp`はAVX-512命令専用である。対応するコンパイル指定がなければコンパイルできず、命令に非対応のCPUでは実行できない。対応CPU限定と明記するか、通常版・AVX2版への切替えが必要である。汎用版は有限値マスクにより`INF`の要素を保持している。

`n*n`を`int`で先に計算する実装群は、`n>46340`で符号付き整数がオーバーフローし得る。`size_t(n)*n`を事前検査して使うべきである。

## 5. 割当て、近傍始点、全域木

### `k_nearest_sources.cpp:20-85`

`K==0`かつ始点集合が非空では、挿入反復を回らず`w=0`のまま`dist[0]`を読む。`K>0`を要求するか、0なら早期に返すべきである。`n*K`も`int`で先に計算する。

非負辺、有効な始点、`K>0`の下では、各頂点について異なる始点からの近い距離をK個確定する処理は整合する。ただし更新と古い候補の判定が各`O(K)`なので、計算量は概ね

```text
O((K(N+M)+|S|) * (K + log(...)))
```

であり、現在の説明は過小である。`d+w`にもDijkstra法と同じ範囲条件が必要である。

### 最小全域木とSteiner木

`minimum_spanning_tree.cpp`と`Graph::minimum_spanning_tree`のKruskal法本体は、無向の候補辺上で整合する。非連結入力では最小全域木でなく最小全域森を返すため、成功状態または採用辺数`n-1`の確認が必要である。総費用もオーバーフローし得る。

`minimum_steiner_tree.cpp`は、最短路を順次接続する近似手法として中核を追跡した。到達不能な端子があると無言で処理を打ち切り、端子を含まない結果を正常値として返すため、失敗状態が必要である。復元経路を無向辺へ正規化するので、入力も対称な無向グラフでなければならない。最短路同士の合流により閉路を含み得るため、返り値は常に木とは限らない。

## 6. 多重定義、再帰、容量

`bfs_path.cpp`と`get_scc_graph.cpp`は、テンプレートでなく非`inline`の自由関数をヘッダー相当の`.cpp`に定義する。複数の翻訳単位から読み込むと一意定義規則に違反する。Tarjan法による強連結成分分解の本体は有効な有向グラフで整合するが、長い鎖では再帰の深さ上限を受ける。木ハッシュ、Namoriなどの再帰実装も同様である。

## 7. 理論上整合していると確認した主な部分

- `bfs_path.cpp`: 重みなしグラフの親復元。
- `get_scc_graph.cpp`: 到達時刻、lowlink、スタック内判定によるTarjan法と、縮約辺の重複除去。
- 重軽分解の4補助クラス: 非可換経路では上向き・下向きの集約を分ける順序。
- `minimum_spanning_tree.cpp`: 有効な無向辺集合上のKruskal法。
- `warshall_floyd_path.cpp`: `next[i][j]=next[i][k]`による経路復元。
- `perfect_binary_tree.cpp`: 有効な頂点番号とビット移動範囲内の親、子、LCA、距離、経路上のk番目。
- `namori.cpp`: 有効な一閉路無向グラフに対する閉路抽出と各木のハッシュ。

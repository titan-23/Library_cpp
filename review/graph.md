// 文末で一時的な vector が破棄される

## 2. 有向グラフと無向グラフの意味

### `graph.cpp:27-74,152-162`

`add_edge` は `G[u]` だけに追加する有向辺の関数ですが、`is_bipartite` はその隣接リストだけをたどる一方で、無向グラフの二部判定を意図しています。頂点 0, 1 に対して `add_edge(1,0)` だけを実行すると、頂点 0 を色 0 の独立した成分として確定した後、頂点 1 も色 0 で開始し、`1->0` を確認して `false` を返します。辺が 1 本の無向グラフは二部グラフであるため、これは誤答です。

最小全域木も `E` を無向の候補辺として扱います。`add_directed_edge` と `add_undirected_edge` に分離し、無向グラフ用のアルゴリズムは対称な表現が保証された入力だけに適用すべきです。

同じクラスの `static const int inf` は `vector` のコンストラクタの参照引数に渡されているため実体が必要ですが、名前空間内の定義がありません。C++17 以降であれば `inline static constexpr` にすべきです。

`topological_sort` は閉路があると部分列を返すため、成功したかどうかを結果の要素数で判定することを仕様として定める必要があります。

## 3. 木のアルゴリズム

### `rerooting_dp.cpp:51-63`

隣接頂点からの寄与が順に `A,B,C` で、`merge` が文字列の連結である場合、後ろからの累積積の構築結果と頂点の全体の積は `CBA` になります。非可換モノイドに対応しているように見える宣言に対して、順序が逆です。

後ろからの累積積は、概念上は次の式の値でなければなりません。

```text
rs[i] = contribution[i] op contribution[i+1] op ...
```

後ろから反復する場合も `merge(current, suffix)` の順にする必要があります。可換な演算だけを扱うのであれば、そのことを明記すべきです。`n==0` では `pdx[0]` が範囲外参照になり、非連結の場合は親子の順に並べた配列の要素数を超えるため、空でない連結な木という前提条件も必要です。

### `rooted_tree.cpp:65-75,177-264`

根からの距離 `dep_weight==-1` を、未訪問を表す番兵としても使用しています。パスグラフ `0 --(-1)-- 1 --(2)-- 2` では頂点 1 の距離が一度 -1 になり、逆向きの辺をたどるときに未訪問と再び判定されて、距離が置き換えられます。訪問状態は距離と分離しなければなりません。

直径の計算で `T max_d=-1` としているため、符号なしの `T` では最大値になります。1 頂点の場合も端点 `u` が -1 のままになり、次の幅優先探索が負の添字を使用します。端点は有効な頂点で初期化すべきです。2 回の最遠点探索で直径を求める方法は非負辺の木が前提であり、負辺がある場合に直径が求まることは保証されません。

重軽分解を使用する `lca`, `la`, `path_kth`, `is_ancestor` 自体は、有効な木では整合します。

### `euler_tour.cpp:43-185`

`n==0` では `2*n-1` が -1 になって巨大な `size_t` の値に変換され、根も範囲外になります。空でないこと、根が有効であること、`vertexcost.size()==n` であること、連結な木であることをチェックする必要があります。

`lca_mul({})` は始点と終点が逆転した区間をセグメント木に渡します。`set_edge(u,v)` は、親子でない 2 頂点を渡すと経路の総和を 1 辺の現在の値と誤って解釈するため、`par[u]==v || par[v]==u` が必須です。

符号なし型の加減算も `2^W` を法とする加法群をなし、行きがけの `+w` と帰りがけの `-w` はその意味で相殺されます。必要な条件は、演算の型が加法群であることと、利用側が剰余としての値を受け入れることです。

### LCA、重軽分解、木ハッシュ

- `lca.cpp` は、入力が空でなく連結な単純無向木であれば、行きがけ順の親の配列に対する RMQ として整合します。閉路がある場合は、スタックに積む時点で訪問済みにしないため同じ頂点を複数回積みます。森の場合は未訪問を表す `nodein==-1` が残ります。
- `hld.cpp` は、同じ前提条件の下で部分木のサイズ、重い子、チェインの先頭、行きがけ順の番号を正しく構築します。ただし、内部でコピーした `G` から親への辺を削除し、重い子を先頭に移動します。そのため、公開されている `G` の意味は元の隣接リストと異なります。`build_list` には要素数が `n` の入力が必要です。
- 重軽分解の補助クラスによる経路の問い合わせは、チェインが `O(log N)` 本あり、各区間のセグメント木の処理が `O(log N)` であるため、最悪の場合は `O(log^2 N)` です。`hld_segment_tree`, `hld_edge_segment_tree`, `hld_edge_lazy_segment_tree` の一部の説明は、計算量を実際より小さく記載しています。
- `hld_edge_lazy_segment_tree` に別の引数として渡す `n` は `hld.n` と一致しなければならず、小さい場合はセグメント木の範囲外参照になります。
- 辺用の補助クラスでは、両方向の隣接リストに同じ重みが格納されている必要があります。
- `hashed_rooted_tree.cpp` は、連結な根付き木であれば確率的ハッシュの再帰式が整合します。乱数の上限が法自身を含んでおり、0 と同値になる可能性があるため、上限は `MOD-1` までにすべきです。閉路がある場合は再帰が終了しません。
- `namori.cpp` も、空でないこと、連結であること、対称な無向グラフの表現であること、辺数が N であることが必要です。`n=0` の場合は、`NDEBUG` を指定すると負の添字を参照します。ハッシュ用の乱数にも同じ上限の問題があります。
- `perfect_binary_tree.cpp::la` は、`k<0` の場合または型のビット幅以上のシフトになる場合に未定義動作になります。符号付きの頂点番号とシフト幅が有効であることをチェックする必要があります。

## 4. 最短路と距離の数値条件

### Dijkstra 法 (`dijkstra.cpp`, `dijkstra_path.cpp`)

非負辺と安全な加算という条件の下では、優先度付きキューと古い候補を破棄する処理は整合します。有限の距離 `d` と辺の重み `c` の和 `d+c` は上限をチェックしておらず、`T=int`, `d=INT_MAX-1`, `c=10` の場合は符号付き整数の未定義動作になります。単に `INF` を最大値にするだけでは防ぐことができず、全ての有限な経路の長さと中間の和が型に収まる必要があります。

負辺がある場合は Dijkstra 法の確定順序と計算量が保証されず、到達可能な負閉路がある場合は更新が終了しません。

### Warshall--Floyd 法 (`warshall_floyd.cpp`, `warshall_floyd_path.cpp`)

通常版の本体、多重辺の最小値、経路復元版の次の頂点の更新、負閉路の伝播は、番兵値に関する前提条件の範囲で整合します。必要な条件は次のとおりです。

- `T` が符号付きの順序型であり、`0<INF` で、`-INF` を表現できること
- 到達可能な全ての有限な部分経路の距離が `(-INF,INF)` の範囲内にあること
- 加算の中間値が型に収まること

各辺が範囲内にあるだけでは不十分です。`INF=100`、辺 `0->1=60`, `1->2=60`, `2->3=-50` では真の値は `dist(0,3)=70` ですが、中間値の 120 を `INF` に丸めるため、その後の -50 が反映されません。到達できるかどうかを数値の番兵とは別に管理するか、問題の制約をもとに全ての有限な距離が収まる `INF` を選ぶ必要があります。符号なし型では `-INF` がラップアラウンドし、比較が成立しません。

通常版と経路復元版の動的な `add_edge` は、非負辺だけに限定されません。新しい辺を複数回使用する歩道が有利である場合はその中に負閉路があり、実装は負閉路として伝播します。ただし、上記の数値条件は必須です。

### SIMD 版

`warshall_floyd_simd.cpp` と `warshall_floyd_simd_nonnegative.cpp` は AVX-512 命令専用です。対応するコンパイル時の指定がなければコンパイルできず、この命令に対応していない CPU では実行できません。対応している CPU に限定することを明記するか、通常版や AVX2 版に切り替える必要があります。汎用版は、有限値のマスクにより `INF` の要素を保持しています。

`n*n` を先に `int` で計算する各実装は、`n>46340` で符号付き整数のオーバーフローが発生する可能性があります。事前にチェックしたうえで `size_t(n)*n` を使用すべきです。

## 5. 割り当て、近い始点、全域木

### `k_nearest_sources.cpp:20-85`

`K==0` かつ始点集合が空でない場合は、挿入処理のループが実行されず `w=0` のまま `dist[0]` を参照します。`K>0` を条件とするか、0 の場合は早期に返すべきです。`n*K` も先に `int` で計算しています。

非負辺、有効な始点、`K>0` という条件の下では、各頂点について異なる始点からの近い距離を K 個確定する処理は整合します。ただし、更新と古い候補の判定がそれぞれ `O(K)` であるため、計算量は概ね次のとおりです。

```text
O((K(N+M)+|S|) * (K + log(...)))
```

現在の説明は計算量を実際より小さく記載しています。`d+w` にも Dijkstra 法と同じ範囲の条件が必要です。

### 最小全域木と Steiner 木

`minimum_spanning_tree.cpp` と `Graph::minimum_spanning_tree` の Kruskal 法の本体は、無向の候補辺に対して整合します。非連結な入力では最小全域木ではなく最小全域森を返すため、成功状態を確認するか、採用した辺の数が `n-1` であることを確認する必要があります。総コストもオーバーフローする可能性があります。

`minimum_steiner_tree.cpp` は 2026-11-12 に更新しました。端子同士が連結でない場合は `solve` の失敗状態または `build_*` の例外として扱い、グラフが非負かつ対称な無向グラフであることを検証します。経路復元では既存の木と再び交差する場合を処理し、閉路と端子でない葉を残しません。方式は、距離のキャッシュを使用する逐次接続、逐次 Dijkstra、Mehlhorn 法、全体の MST の枝刈りから選択できます。小規模なグラフでの厳密解との比較と、ASan/UBSan による確認を追加しました。値域の条件と、方式ごとの品質と速度の違いは[利用方法](../titan_cpplib/graph/how_to_use_minimum_steiner_tree.md)を参照してください。

## 6. 多重定義、再帰、容量

`bfs_path.cpp` と `get_scc_graph.cpp` は、テンプレートではない非 `inline` の自由関数を、ヘッダーに相当する `.cpp` に定義しています。複数の翻訳単位から読み込むと単一定義規則 (ODR) に違反します。Tarjan 法による強連結成分分解の本体は有効な有向グラフで整合しますが、長いパスでは再帰の深さの上限による制約を受けます。木ハッシュ、Namori などの再帰による実装も同様です。

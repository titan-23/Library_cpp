# `titan_cpplib/math` 理論レビュー

レビュー日: 2026-08-12
対象: `.cpp` 12ファイル（`memo.md`は除外）

## 結論

テスト・コンパイル・実行は行わず、公式、整数の値域、除算の定義域、篩と素因数分解の反復不変条件を静的に追った。`math.cpp`の二次方程式と`isqrt`、`linear_equation.cpp`の行列形状、`Osa_k`と`PrimeFactorizer`の約数列挙に、通常の利用へ直接影響する確定問題がある。

| 重要度 | 対象 | 要点 |
|---|---|---|
| 重大 | `math.cpp` | 二次方程式の分母から`a`が欠落。`isqrt`は上側補正が不十分で、符号付き整数のオーバーフローも起こす |
| 重大 | `linear_equation.cpp` | 行列形状を検査せず範囲外参照。整数型では除算が切り捨てられて誤答 |
| 重要 | `osak.cpp`, `prime_factorizer.cpp` | 約数列挙の最後に不要な累乗を計算してオーバーフロー |
| 重要 | `divisor.cpp`, `get_primelist.cpp` | `i*i`, `n+1`, 切り上げ式、反復変数の更新が境界でオーバーフロー |
| 重要 | `fraction.cpp` | 最小値の符号反転、交差積、四則演算、無限大の順序 |
| 重要 | `pollard_rho.cpp` | 公開する128ビット型と内部の64ビット素数判定が不整合 |

「追加の確定問題なし」は、記載した入力・型契約の下で反例を構成できなかったという意味であり、任意精度や全入力を保証するものではない。

## 1. 方程式と平方根

### `math.cpp:8-22`

`solve_quadratic_equation(a,b,c)`は解を

```text
(-b ± sqrt(D)) / 2
```

としており、正しい分母`2*a`から`a`が欠落している。`a=2,b=0,c=-2`の解は`±1`だが、この実装は`±2`を返す。整数型の切り捨て以前に、実数型でも確定誤答である。退化した一次式と数値安定性も処理する`quadratic_equation.cpp`へ一本化するのが安全である。

同ファイルの`isqrt`は、初期近似`x`が真の床平方根より1大きい場合に、`x*x>v`を直接確認せず、`(x-1)^2<v`ならそのまま返し得る。また`v`が符号付き`__int128`の上限付近では、補正条件の`(x+1)*(x+1)`自体が表現範囲を超える。比較は`x>v/x`および`x+1<=v/(x+1)`の除算形にする必要がある。

`pow_mod<long long>`の`a*a`、整数`pow`、`factorial`も表現範囲を検査しない。負の指数は対応外である。

### `quadratic_equation.cpp:8-21`

有限値、`eps>0`、`a`が0でない通常の二次式では、桁落ちを避ける根の選択を含め式は整合している。`a=b=0`では「解なし」と「恒等的に0」をともに空の`vector`で表すため、必要なら戻り値で退化状態を区別する。`eps<=0`は分類を壊す。

### `linear_equation.cpp:20-55`

`b.size()==A.size()`と各行の列数を検査しない。`A={{1}},b={}`は`b[0]`、`A={{1},{}}`は`A[1][0]`を範囲外参照する。

テンプレート引数`T`は体をなす必要がある。`T=int`, `A={{2}},b={2}`では主元をそろえる`1/2`が0となり、解0を返す。`eps=0`, `A={{0.0}},b={0.0}`では`fabs(0)<0`が`false`となり、整合な式を「解なし」と判定する。行列形状、除算可能な型、正の許容誤差を入口で検査すべきである。

## 2. 篩、約数、素因数分解

### `divisor.cpp`

`get_divisors`, `divisors_num`, `factorization`の反復条件`i*i<=n`は、`n=LLONG_MAX`付近で`i=3037000500`の積がオーバーフローする。`i<=n/i`へ変える必要がある。

`56-83`の表生成は`n+1`、`j+=i`、添字積を`int`で行い、`INT_MAX`境界で符号付き整数のオーバーフローを起こす。`factorization(0)`が`{(0,1)}`を返すなど、0以下も数学的な定義域外である。`n>=1`と容量上限を明示し、容量と反復変数の型を広げる必要がある。

### `get_primelist.cpp`

`get_primelist_range(-1,3)`は`-1,0,2`を返す。0を除く分岐が`l==0`の場合にしかなく、負数を非素数として落とさないためである。非負区間専用なら`l>=0`を要求し、一般整数区間を受けるなら値`<2`を一律に除外する。

区間篩の`(l+p-1)/p`は`l`が`LLONG_MAX`近傍でオーバーフローする。空区間を先に返し、商と剰余で切り上げを求めるべきである。通常の篩も`n+1`, `i*i`, `j+=i`を`int`で行うため、同種の境界問題を持つ。

### `osak.cpp:22,42-89`

約数列挙は各素因数の最後の指数を処理した後も、次回使わない`now*=p`を実行する。素数65521を`int`版で列挙すると、65521を格納した後に`65521^2`を計算し、符号付き整数がオーバーフローする。再帰版も同じである。乗算は次の反復があるときだけ行う必要がある。

既定構築後の照会は空の`min_factor`を読み、`get_divisors(0)`は空の因数列の先頭を読む。構築上限を保持し、`1<=n<=N`を検査すべきである。

### `prime_factorizer.cpp:19-97`

こちらも最後の指数の後に不要な`now*=p`を行う。例えば`3^39`は`long long`に収まるが、その約数を出した後の`3^40`は収まらない。

さらに既定構築では素数表が空なので、`p_factorization(4)`を`{4}`と誤分類する。`PrimeFactorizer(10)`へ49を照会しても`{49}`になる。コンストラクタ引数が`LLONG_MAX`なら`n+1`が直ちにオーバーフローし、平方根が`INT_MAX`を越える範囲では素数を`vector<int>`へ狭める。対応する最大照会値を保存し、型と構築範囲を一致させる必要がある。

### `is_primell.cpp`, `pollard_rho.cpp`

`is_primell`は符号付き64ビットの正整数範囲では、使用する決定的Miller--Rabin基底と`__int128`による積の組合せが整合する。

一方、`PollardRho`の公開型は`__int128`なのに、ビット長は`__builtin_clzll`へ縮小し、素数判定も`is_primell(long long)`へ暗黙変換する。`LLONG_MAX`を越える素数では、rho法が値自身を返した後の素数判定が切り詰められ、値と1を再投入し続け得る。`std::gcd`と`std::abs`の`__int128`対応も標準では保証されない。公開範囲を符号付き64ビットへ限定するか、全ての基本処理を128ビット対応に統一する必要がある。

## 3. 数体系・組合せ

### `fraction.cpp`

`Fraction<long long>(1,LLONG_MIN)`の`-q`、`Fraction(LLONG_MIN,1)`の絶対値化、`pow(LLONG_MIN)`の`-k`はいずれも表現不能な符号反転で未定義動作になる。四則演算と比較も積を先に作るため、例えば`LLONG_MAX/1 + 1/1`や大きい分母同士の交差積がオーバーフローする。より広い型または交差約分が必要である。

`q==0`で正負の無限大を表すが、`+∞`と`-∞`は相互に`<`が`false`、双方の`<=`が`true`、`==`は`false`となり、数値順序を作らない。無限大を仕様から外すか、比較を明示的に処理する必要がある。公開メンバー`p,q`を直接変更すると、既約性と分母符号の不変条件も壊せる。

### `mod_comb.cpp:17-45`

逆元の漸化式は、法が素数かつ事前計算上限`n<mod`であることを要する。`mod=7`で7まで構築すると`fact[7]=0`となり、`nCr(7,0)`が0になる（正解は1）。照会の負値、構築上限超過、既定構築後の空表も検査しない。`nHr(0,0)`は通常の組合せ規約なら1だが、現在は0である。

### `stern_brocot_tree.cpp`

正の分子・分母では`encode_path`, `decode_path`, `lca`, `ancestor`と、同方向へ進む回数ごとの倍加二分探索を追跡し、本体は整合する。`get_node(0,1)`は途中で0除算、`get_node(0,0)`は最大公約数0による除算となるため、`p>0,q>0`が必須である。

探索上限が`numeric_limits<T>::max()`で、境界が見つからない場合の番兵`lim+1`はオーバーフローする。値の番兵でなく、見つかったかを示す真偽値か、より広い型を用いるべきである。各区間の`log a_i`の総和を含め、二分探索の計算量は`O(log d)`である。

## 4. 複数の翻訳単位からの利用

このリポジトリでは`.cpp`をヘッダーのように読み込むが、次の自由関数は非`inline`であるため、複数の翻訳単位から使うと一意定義規則に違反する。

- `divisor.cpp`
- `get_primelist.cpp`
- `is_primell.cpp`
- `math.cpp`
- `quadratic_equation.cpp`

単一ファイルへの展開専用なら制約として明記し、通常のライブラリにするなら`inline`化するか、宣言と実装を分離する必要がある。`math.cpp`と`is_primell.cpp`の一部は`namespace titan23`外にあり、標準名との衝突余地もある。

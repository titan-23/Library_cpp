## 1. 方程式と平方根

### `math.cpp:8-22`

`solve_quadratic_equation(a,b,c)` は解を

```text
(-b ± sqrt(D)) / 2
```

としており、正しい分母 `2*a` から `a` が欠落しています。`a=2,b=0,c=-2` の解は `±1` ですが、この実装は `±2` を返します。整数型の切り捨て以前に、実数型でも確実に誤答となります。退化した一次式と数値安定性にも対応する `quadratic_equation.cpp` へ一本化するのが安全です。

同ファイルの `isqrt` は、初期近似値 `x` が平方根を切り捨てた真の値より 1 大きい場合に `x*x>v` を直接確認せず、`(x-1)^2<v` であればそのまま返す可能性があります。また `v` が符号付き `__int128` の上限付近にある場合は、補正条件の `(x+1)*(x+1)` 自体が表現範囲を超えます。比較は `x>v/x` および `x+1<=v/(x+1)` のように除算の形にする必要があります。

`pow_mod<long long>` の `a*a`、整数 `pow`、`factorial` も表現範囲を確認しません。負の指数には対応していません。

### `quadratic_equation.cpp:8-21`

有限値、`eps>0`、`a` が 0 でない通常の二次式では、桁落ちを避ける根の選択を含めて式は整合しています。`a=b=0` では「解なし」と「恒等的に 0」をどちらも空の `vector` で表すため、必要であれば戻り値で退化した状態を区別するようにします。`eps<=0` では分類が成り立たなくなります。

### `linear_equation.cpp:20-55`

`b.size()==A.size()` と各行の列数を確認していません。`A={{1}},b={}` は `b[0]` を、`A={{1},{}}` は `A[1][0]` を範囲外参照します。

テンプレート引数 `T` は体をなす必要があります。`T=int`, `A={{2}},b={2}` ではピボットをそろえるための `1/2` が 0 となり、解 0 を返します。`eps=0`, `A={{0.0}},b={0.0}` では `fabs(0)<0` が `false` となり、整合している式を「解なし」と判定します。行列の形状、除算可能な型、正の許容誤差を関数の開始時に確認すべきです。

## 2. 篩、約数、素因数分解

### `divisor.cpp`

`get_divisors`, `divisors_num`, `factorization` のループ条件 `i*i<=n` は、`n=LLONG_MAX` 付近で `i=3037000500` の積がオーバーフローします。`i<=n/i` に変更する必要があります。

`56-83` の表の生成は `n+1`、`j+=i`、添字の積を `int` で計算し、`INT_MAX` の境界で符号付き整数のオーバーフローを起こします。`factorization(0)` が `{(0,1)}` を返すなど、0 以下も数学的な定義域の外です。`n>=1` と容量の上限を明示し、容量とループ変数の型を広げる必要があります。

### `get_primelist.cpp`

`get_primelist_range(-1,3)` は `-1,0,2` を返します。0 を除く分岐が `l==0` の場合にしかなく、負数を非素数として除外しないためです。非負の区間専用とするなら `l>=0` を条件とし、一般の整数区間を受け付けるなら値 `<2` を一律に除外するようにします。

区間篩の `(l+p-1)/p` は `l` が `LLONG_MAX` の近傍にあるとオーバーフローします。空区間の場合は先に結果を返し、商と剰余で切り上げを求めるべきです。通常の篩も `n+1`, `i*i`, `j+=i` を `int` で計算するため、同種の境界の問題があります。

### `osak.cpp:22,42-89`

約数列挙は各素因数の最後の指数を処理した後も、次回使用しない `now*=p` を実行します。素数 65521 の約数を `int` 版で列挙すると、65521 を格納した後に `65521^2` を計算し、符号付き整数がオーバーフローします。再帰版も同じです。乗算は次の反復があるときだけ行う必要があります。

デフォルト構築後の問い合わせは空の `min_factor` を参照し、`get_divisors(0)` は空の因数列の先頭を参照します。構築時の上限を保持し、`1<=n<=N` を確認すべきです。

### `prime_factorizer.cpp:19-97`

こちらも最後の指数の後に不要な `now*=p` を実行します。例えば `3^39` は `long long` に収まりますが、その約数を列挙した後の `3^40` は収まりません。

さらにデフォルト構築では素数表が空であるため、`p_factorization(4)` を `{4}` と誤って分類します。`PrimeFactorizer(10)` へ 49 を問い合わせても `{49}` になります。コンストラクタの引数が `LLONG_MAX` なら `n+1` が直ちにオーバーフローし、平方根が `INT_MAX` を超える範囲では素数を `vector<int>` へ縮小変換します。対応する問い合わせの最大値を保存し、型と構築した範囲を一致させる必要があります。

### `is_primell.cpp`, `pollard_rho.cpp`

`is_primell` は、符号付き 64 ビットの正整数の範囲では、使用する決定的な Miller--Rabin の基底と `__int128` による積の組合せが整合しています。

一方、`PollardRho` が公開する型は `__int128` ですが、ビット長の計算では値を `__builtin_clzll` へ縮小して渡し、素数判定でも値を `is_primell(long long)` へ暗黙に変換して渡します。`LLONG_MAX` を超える素数では、rho 法が値自身を返した後の素数判定で値が切り詰められ、値と 1 を再び投入し続ける可能性があります。`std::gcd` と `std::abs` の `__int128` への対応も標準では保証されません。公開する範囲を符号付き 64 ビットに限定するか、すべての基本処理を 128 ビット対応に統一する必要があります。

## 3. 数体系と組合せ

### `fraction.cpp`

`Fraction<long long>(1,LLONG_MIN)` の `-q`、`Fraction(LLONG_MIN,1)` の絶対値の計算、`pow(LLONG_MIN)` の `-k` は、いずれも表現できない符号反転であるため未定義動作になります。四則演算と比較も積を先に計算するため、例えば `LLONG_MAX/1 + 1/1` や大きい分母同士のたすき掛けの積がオーバーフローします。より広い型を使用するか、乗算の前に一方の分子ともう一方の分母を約分する必要があります。

`q==0` で正負の無限大を表しますが、`+∞` と `-∞` は相互に `<` が `false`、双方の `<=` が `true`、`==` は `false` となり、数値としての順序が成り立ちません。無限大を仕様から外すか、比較を明示的に処理する必要があります。公開メンバー `p,q` を直接変更すると、既約性と分母の符号の不変条件も成り立たなくなる可能性があります。

### `mod_comb.cpp:17-45`

逆元の漸化式には、法が素数であり、かつ事前計算の上限が `n<mod` を満たすことが必要です。`mod=7` で 7 まで構築すると `fact[7]=0` となり、`nCr(7,0)` が正しい値の 1 ではなく 0 になります。問い合わせの負の値、構築時の上限の超過、デフォルト構築後の空の表も確認しません。`nHr(0,0)` は通常の組合せの規約なら 1 ですが、現在は 0 です。

### `stern_brocot_tree.cpp`

`encode_path`, `decode_path`, `lca`, `ancestor` と、同じ方向へ進む回数を倍加と二分探索で求める処理を追跡しました。分子と分母が正であれば本体は整合しています。`get_node(0,1)` は途中で 0 除算、`get_node(0,0)` は最大公約数 0 による除算となるため、`p>0,q>0` が必須です。

探索の上限が `numeric_limits<T>::max()` であり、境界が見つからない場合の番兵 `lim+1` はオーバーフローします。値の番兵ではなく、見つかったかどうかを示す真偽値か、より広い型を使用すべきです。各区間の `log a_i` の総和を含め、二分探索の計算量は `O(log d)` です。

## 4. 複数の翻訳単位からの利用

このリポジトリでは `.cpp` をヘッダーのように読み込みますが、次のファイルの非メンバー関数は `inline` でないため、複数の翻訳単位から使用すると単一定義規則に違反します。

- `divisor.cpp`
- `get_primelist.cpp`
- `is_primell.cpp`
- `math.cpp`
- `quadratic_equation.cpp`

単一ファイルへの展開専用とするなら制約として明記し、通常のライブラリにするなら `inline` にするか、宣言と実装を分離する必要があります。`math.cpp` と `is_primell.cpp` の一部は `namespace titan23` の外にあり、標準ライブラリの名前と衝突する余地もあります。

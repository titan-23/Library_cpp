# Wavelet Matrix 上の二分探索

## 対象

この文書では、wavelet matrix を使った二分探索を説明する。対象は「配列の添字」ではなく「キーの値順」に対する探索である。実装は [`wavelet_matrix_sum.cpp`](../titan_cpplib/ds/wavelet_matrix_sum.cpp) の `WaveletMatrixSum<T, W>` を参照する。API設計の経緯は [`wavelet_matrix.md`](wavelet_matrix.md) の4.5節にある。

記号は次の通り。

- `n`: 配列長
- `σ`: キーの値域の上端。キーは `[0, σ)`
- `L`: `ceil(log2(σ))`

## 前提: 区間の降下

wavelet matrix は、キーを上位ビットから1ビットずつ安定分割した `L` 段のビット列を持つ。段 `bit` において、区間 `[l, r)` の要素は次の2つの子区間に分かれる。

- 0側: `[rank0(l), rank0(r))`。現在のビットが0の要素
- 1側: `[mid + (l - rank0(l)), mid + (r - rank0(r)))`。現在のビットが1の要素

`mid` はその段全体に含まれる0の個数である。実装では `_v[bit].rank0` と `_mid[bit]` がこれに当たる。

この変換には次の性質がある。

- 上位ビットが等しい要素のうち、0側は値が小さい半分、1側は値が大きい半分に対応する
- 各枝の要素数は `rank0` の差で `O(1)` で求まる
- 段ごとに0側の重みの累積和 `_zero_sum` を持つと、各枝の重みの総和も `O(1)` で求まる

最上位ビットから最下位ビットまで降りると、区間は同一キーの要素だけからなる区間になる。

## 二分探索としての見方

各段で0側と1側のどちらへ進むかを選ぶことは、値域を半分に絞る判定1回に相当する。`L` 段でキーが1つに定まる。

したがって、値域 `[0, σ)` に対する二分探索を、判定関数を外から呼ぶ代わりに wavelet matrix の降下として実行できる。判定に必要な枝の個数と総和が各段 `O(1)` で得られるため、探索全体は `O(L)` で終わる。

## 2つの方式

| 方式 | 内容 | 計算量の目安 |
|---|---|---:|
| 外側二分探索 | `range_count` や `sum_lt` を判定関数とし、`k` や `value` を外側で二分探索する | `O(L log n)` または `O(L^2)` |
| 直接降下 | 各段で枝の個数・総和を見て、進む枝をその場で決める | `O(L)` |

値順に関する単調な探索では直接降下を使う。外側二分探索が必要になるのは、後述の「値順で表現できない探索」に限られる。

## 実装例

### 個数を条件に降りる: `kth_smallest`

区間 `[l, r)` で昇順 `k` 番目のキーを求める。最小の例である。

- 0側の個数 `count0` を求める
- `k < count0` なら、答えの現在ビットは0である。0側へ降りる
- `k >= count0` なら、答えの現在ビットは1である。`k -= count0` として1側へ降りる

判定は「`k` 番目の要素が現在の値域の下半分にあるか」である。この判定が `rank0` 2回で済むため、ソートせずに `O(L)` で `k` 番目が求まる。

### 境界値に沿って降りる: `range_freq`, `count_sum_lt`

`upper` 未満のキーの個数や総和を求める。探索ではなく境界値が与えられる場合だが、降下の形は同じである。

- `upper` の現在ビットが1なら、0側の枝は全要素が `upper` 未満である。個数と総和を加算し、1側へ降りる
- 0なら、0側へ降りる

「枝の全体を採用して反対側へ進む」という処理は、次の探索でも使う。

### 総和を条件に降りる: `min_count_smallest_sum_ge`

キーの昇順に要素を採用し、重みの総和が `target` 以上になる最小個数を求める。segment tree の `max_right` を、配列の位置順ではなく値順に行う操作に相当する。内部実装は `_min_count_sum_ge` である。

各段の処理は次の通り。

- 0側の総和 `sum0` を累積和から `O(1)` で得る
- `sum0 >= target` なら、境界は0側の中にある。0側へ降りる
- `sum0 < target` なら、0側は全採用と確定する。`result += count0`, `target -= sum0` として1側へ降りる

最下段で同一キーの区間に到達したら、そのキーを何個採るかを `_leaf_min_count` で決める。

- `weight = key` の場合、区間内の重みはすべて等しい。`ceil(target / key)` の除算で決まり、全体は `O(L)`
- 一般の重みの場合、安定分割後の累積和 `_leaf_sum` 上で `lower_bound` する。全体は `O(L + log n)`

この探索は、値順の累積和が単調であることを前提とする。そのため重みは非負に限定する。負の重みを許すと、枝の総和だけでは「枝の途中で一度 `target` に達したか」を判定できない。

### 個数を指定して総和を取る: `sum_k_smallest`

昇順先頭 `k` 個の重みの総和を求める。内部実装は `_sum_k` である。

降下は `kth_smallest` と同じで、`k <= count0` なら0側へ、そうでなければ `sum0` を答えに加算して1側へ降りる。個数を条件とする降下と総和を条件とする降下は、同じ処理の変種である。

### 候補の枝が高々1つの探索: `has_majority`

区間の過半数を占めるキーの有無を判定する。

過半数を占めるキーが存在するなら、各段でその要素は片方の枝に過半数のまま残る。よって過半数を持つ枝を選び続ければ候補が1つに絞れる。どちらの枝も過半数に満たない段があれば、その時点で不在と確定する。

## 直接降下が成立する条件

次がすべて成り立つ場合に直接降下を使える。

- **探索軸が値順である。** 個数 `k` や境界キーの探索は各段の枝で表現できる。元配列上の位置の探索は各段で表現できないため、`count_range(l, mid, lower, upper)` などを判定関数とする外側二分探索になる
- **述語が値順に単調である。** `max_right` と同じく、一度偽になったら偽のままである必要がある。累積XORのように真偽が往復する条件には使えない
- **枝の集約値が段ごとに低コストで得られる。** 総和なら段ごとの累積和で足りる。`min`, `max`, `gcd` では段ごとにRMQなどの構造が必要であり、総和用の累積和では代用できない

## 計算量

静的な総和付き wavelet matrix での比較を示す。

| 方法 | 計算量 |
|---|---:|
| 値順に直接降下する | 一般の重みは `O(L + log n)`、`weight = key` は `O(L)` |
| `k` を外側で二分探索する | `O(L log n)` |
| `value` を外側で二分探索する | `O(L^2)` |
| 元配列上の位置を外側で二分探索する | `O(L log n)` |

動的版を含めた比較は [`wavelet_matrix.md`](wavelet_matrix.md) の4.5.6節にある。

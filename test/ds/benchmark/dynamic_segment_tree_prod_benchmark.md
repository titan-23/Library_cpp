# 動的セグメント木の prod と境界探索の高速化の測定記録

2026-11-13 の記録です。DynamicSegmentTree、DynamicSegmentTreeInit、DynamicLazySegmentTree の prod と、通常版および初期値付き版の max_right、min_left を対象にしました。

## 測定条件

- CPU は AMD Ryzen Threadripper 3990X (Zen 2)、コンパイラは GCC 12.3.0 で、オプションは `-std=c++17 -O2 -DNDEBUG` です。
- 変更前のコードは HEAD (`9634bd5`) のヘッダです。各値は、CPU 4 に固定して変更前と変更後を交互に 5 回ずつ実行した中央値です。チェックサムは全行で一致しました。
- 操作別の値は [dynamic_segment_tree_prod_benchmark.cpp](dynamic_segment_tree_prod_benchmark.cpp) で計測しました。N=1e9 に 25 万個の点更新を行ってから 100 万回の操作を計測します。遅延版では点更新の代わりに 25 万個の区間加算を行います。
- 混合の値は既存の [dynamic_segment_tree_benchmark.cpp](dynamic_segment_tree_benchmark.cpp)、[dynamic_segment_tree_monoid_benchmark.cpp](dynamic_segment_tree_monoid_benchmark.cpp)、[dynamic_lazy_segment_tree_benchmark.cpp](dynamic_lazy_segment_tree_benchmark.cpp) の既定の条件 (Q=5e5) で計測しました。

## prod

### 原因

- prod は、l と r が別の子に分かれた後、左端側の経路を最後までたどってから右端側の経路をたどっていました。
- 各経路は、前のノードを読み込まないと次のノードが定まらない読み出しの連鎖であり、2 つの連鎖の読み出しは同時には進行しません。
- 通常版では prod に 1 回あたり get の約 2.3 倍の時間 (約 1290 サイクル) がかかっていました。

### 変更点

- 3 つのクラスの inner_prod で、分かれた後の左端側と右端側の経路を同じループで 1 段ずつ交互にたどるようにしました。これにより 2 つの経路の読み出しが同時に進行します。
- 初期値付き版は、経路の途中と分岐点にある初期値の隙間を、元の prefix_prod および suffix_prod と同じ規則で結合します。
- 分かれるまでの共通の経路は、子の選択を条件付き転送で記述できる形にしました。短い区間では共通の経路が長く、この部分の変更が有効です。
- inner_prod に `[[gnu::noinline]]` を付けました。呼び出し元のループに展開された場合は、操作別の測定で 5% ほど遅くなりました。
- 使用されなくなった prefix_prod と suffix_prod を削除しました。

### 採用しなかった案

- 降下を分岐なしで実装する案です。整数とアドレスをマスクで選択し、通常版の prod と set の分岐予測の失敗を 1 回あたり 17 回と 11 回から 3 回と 1 回に減らしました。しかし set は約 20% 遅く、prod_short も約 10% 遅くなりました。分岐予測が的中すれば次のノードの読み出しを比較の前に開始できますが、分岐をなくすと比較の結果を待つ必要があるためと考えられます。GCC 12 は三項演算子で記述した選択を分岐に戻すため、マスクで記述する必要がありました。
- set を、経路を記録して降下した後に下から集約値を求め直す反復の形にする案です。分岐ありで 10〜17% 遅くなりました。既存の記録 [dynamic_segment_tree_iterative_candidates.csv](dynamic_segment_tree_iterative_candidates.csv) と同じ傾向です。
- 遅延版で、遅延作用の有無で分岐せずに恒等作用を合成する案です。prod と get の差は ±3% の範囲で、効果はありませんでした。

## 境界探索 (max_right, min_left)

### 原因

- 通常版と初期値付き版の max_right と min_left は、左の子から順に調べる再帰で実装されていました。
- max_right で l へ降下する途中に右へ進む段でも、左の子を読み込んで全体が l より前にあることを確認していました。この読み出しは降下する経路の外にあります。
- 初期値付き版は、子の間の初期値の区間を調べる関数も段ごとに呼び出していました。

### 変更点

- 遅延版と同様に、境界まで降下しながら残りの部分木をスタックに積み、境界に近い順に判定し、失敗した部分木へ降下する反復の形にしました。
- 右へ進む段では左の子を読み込みません。
- 初期値付き版は、子の間の初期値の区間も部分木とあわせて積みます。min_left で左の子へ降下するとき、左の子の末尾から r までの初期値は左の子より先に調べる必要があるため、別に保持して最初に調べます。
- 遅延版は以前から反復の形であるため変更していません。

### 採用しなかった案

- 失敗した部分木を降下するときに反対側の子を先読みする案と、部分木を積む時点でその部分木を先読みする案です。通常版でも遅延版でも差は 1% 未満でした。

## 検証

- 既存の dynamic_segment_tree_random、dynamic_segment_tree_generic_test、dynamic_segment_tree_util_test、dynamic_segment_tree_util_extra_test、dynamic_lazy_segment_tree_util_extra_test を `-O2`、`-O3 -march=native`、AddressSanitizer と UndefinedBehaviorSanitizer 付きの 3 構成で実行し、すべて成功しました。警告は出力されませんでした。
- prod に次の誤りを 1 つずつ入れると dynamic_segment_tree_random が失敗することを確認しました。
  - 初期値付き版で分岐点の隙間を省く
  - 初期値付き版で左側の経路の隙間を省く
  - 通常版で右側の経路の左の子を省く
  - 遅延版で左側の葉の長さを誤った値にする
  - 遅延版で右側の経路の遅延作用を省く
- 境界探索に 8 通りの誤りを入れ、次の 6 通りで dynamic_segment_tree_random と dynamic_segment_tree_generic_test が失敗しました。
  - 初期値付き版の先頭の初期値を省く
  - 積む順序を逆にする
  - 降下するときの子の間の初期値を省く (2 方向)
  - 積む初期値を省く
  - 通常版の min_left の答えを 1 ずらす
- 残り 2 通りは境界と分岐の座標が等しいときの扱いを変更するもので、部分木を一段細かく分けて調べるだけであるため結果は変化しません。

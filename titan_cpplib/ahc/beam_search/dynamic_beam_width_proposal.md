# 動的ビーム幅調整の改善案

対象は通常版の `beam_search.cpp` とターンスキップ版の `beam_search_turn.cpp` です。
目的は TL ちょうどで探索が終了するようにビーム幅 W を毎ターン調整することです。
この文書には現状の失敗原因の分析と置き換え案の設計を記載します。実装は対象外です。

## 現状の仕組み

### 通常版 (`beam_param.cpp` の `get_beam_width`)

- 10 ターンごとに幅を更新します。それ以外のターンでは前回の値を返します。
- 開始からの累積平均 `time_sum / beam_width_sum` で単位コストを見積もります。
- 推奨幅 `pred_width = (残時間 / 残ターン) / 単位コスト` を求めます。
- 最終値は `(pred_width*2 + 過去の平均幅) / 3` の加重平均です。

### turn 版 (`compute_req_w` + `recommend_width`)

- 残りのメタターン数を `(max_turn - min_target_in_tree) / ema_step` で推定します。
- メタターンを active と empty に分け、active のコストは W に比例するとみなします。
- コスト係数には開始からの累積平均 (`time_active_sum / count_active` など) を使用します。
- 幅は `get_cands()` での **pool の生成時** に確定します。

## 失敗原因の分析

### 両版に共通する構造的な問題

1. **累積平均は過去のすべての値を含むため、コストの変化に追従できません。**
   1 候補あたりのコストはターンとともに変化します。分岐数、状態のサイズ、tour の長さ、rollback の深さが探索の進行につれて増える問題が多くあります。開始からの平均は序盤の値の影響を強く受け、終盤の実際のコストを過小評価します。その結果、W を小さくするのが遅れて TL を超過するか、逆に一度 W を小さくしたときの履歴の影響で W が元に戻らなくなります。

2. **開ループの予測と反映の遅れが組み合わさり、フィードバックが発散する方向に働きます。**
   通常版では、ターン t で選択した W によってターン t+1 の展開コストが定まります。一方 `timestamp()` は、ターン t の所要時間を新しい `candidates.size()` (= W_t 側) と対応付けて記録します (`beam_search.cpp:428`)。この所要時間の実体は、前の世代の幅 W_{t-1} での展開コストです。W を小さくした直後は「大きい dt ÷ 小さい W」となって単位コストを過大評価し、次の推奨幅がさらに小さくなります。これが繰り返されて W が小さくなり続けます。W を大きくした直後は、逆に推奨幅が過大になります。期待どおりに動作する場合があるのは、幅が一定であれば所要時間と幅の対応のずれがなくなるためと説明できます。

3. **固定コストを分離していません。**
   1 ターンのコストは `dt = a + b*W` の形になります。`dt / W` を単位コストにすると `b_hat = a/W + b` となり、W が小さい領域で b を過大評価します。W が一度小さくなると、過大な単位コストが原因で元の幅に戻らなくなります。

4. **予測が外れた場合に備える仕組みがありません。**
   TL の超過を防ぐために W を強制的に縮小する処理も、時間が余ったときに残り時間を使い切る処理もありません。

### 通常版に固有の問題

- **過去の平均幅との加重平均によって幅の変化が遅れます。**
  `ave_beam_width` は開始からの平均であり、初期値やキャリブレーション期間の幅の影響が最後まで残ります。そのため推奨値への収束が遅くなり、10 ターン周期の更新と合わさって振動や停滞が発生します。
- **10 ターンごとの更新では間隔が長すぎます。**
  ターン数が数百程度にとどまる問題では、調整の機会が数十回しかありません。超過を検出してから W を小さくするまでの遅れが TL の超過につながります。
- **キャリブレーションの期間がターン数で定められています。**
  最初の 11 ターンは初期幅のまま実行します。初期幅が過大な場合は、この期間だけで予算の大半を使い切ります。失った時間は取り戻すことができません。

### turn 版に固有の問題

1. **幅を決定する時点とその幅で展開する時点が離れています。**
   pool の幅は `get_cands()` が pool を作成した時点、すなわちその target_turn への最初の候補が push された時点で固定されます。その pool の leaf が実際に展開されるのは何メタターンも後です。制御工学でいうむだ時間が大きいうえに可変であるため、どのコストモデルを使用しても安定しません。turn 版が通常版より悪化しやすい最大の要因はこの点です。

2. **残りのメタターン数の推定値が大きく外れやすくなっています。**
   `min_target_in_tree` の前進量は、生存している leaf のうち最も遅れているものに左右されます。ビームの大半が先のターンへ進んでいても、遅れている leaf が 1 つ残ると delta_target = 0 が続きます。その結果 `ema_step` が小さくなって remain_meta が大きくなり、W が 1 のまま変化しなくなります。逆に、遅れている leaf がなくなって min_target が大きく進むと W が急に大きくなります。平均の進行速度で割る推定の方法そのものが、この分布の裾に対して頑健ではありません。

3. **empty ターンのコストも一定ではありません。**
   empty メタターンの dt は tree の走査にかかる時間であり、tree サイズに比例します。tree サイズは W と、ノードが生存しているターンの範囲の長さによって変化しますが、現状は 1 つの累積平均だけで扱っています。

## 設計方針

予測精度を上げるのではなく、**比率によるフィードバック制御**を中心にします。
理由は次のとおりです。

- 消費ペースと目標ペースの比だけを使用すれば、コストモデルの絶対値のバイアスが打ち消されます。`dt = a + b*W` の a が不明でも、threshold による枝刈りで非線形性が生じても、更新の符号は常に正しく、反復によって不動点に収束します。
- 更新率に上限 (レートリミット) を設ければ、所要時間と幅の対応のずれやむだ時間があっても振動しません。
- 毎ターン更新できるため、コストのドリフトに自動的に追従します。

コストモデル (a + b*W の回帰) は廃止せず、キャリブレーション直後の大きな初期補正にだけ使用します。定常時の追従は制御器で行います。

## 提案 1: 共通コントローラ (両版)

毎ターン、次の値を計算します。turn 版ではコストを計上したメタターンごとに計算します。

```
dt_hat     = EMA(直近の 1 ターン所要時間, alpha = 0.2〜0.3)
budget     = time_limit - elapsed - reserve        // reserve は後述
target_dt  = budget / remain_costed_turns
r          = target_dt / dt_hat
W_next     = clamp( round(W_cur * clip(r, 1/rho, rho)), W_min, W_max )
```

- **1 ターンあたりの変化率の上限 rho は 1.3〜1.5 とします。**
  むだ時間が 1〜数ターンの系でも振動しない値を、この範囲から実測で選択します。
- **`beam_width` は初期値であり、上限ではありません。**
  制御器が必要と判断した場合は、指定された幅を超えて広げます。上限と下限を設定する場合は、別のパラメータ `max_beam_width` と `min_beam_width` で指定します。既定値は `min = 1`、`max = 無制限` です。現行の turn 版では指定された幅を上限としていますが、この挙動は廃止します。
- **探索の開始時は指定された幅を使用します。**
  最初の数ターンだけ rho を 2 程度に大きくし、指定された幅が適切でない場合も速やかに補正します。幅が過大な場合に失った時間は取り戻すことができないため、適切な幅の見当がつかない問題では小さめの `beam_width` を渡すことを推奨します。ライブラリ側では初期値を自動的に小さくしません。
- **固定ターン数のキャリブレーション期間は廃止します。**
  最初の 1 サンプルで EMA を初期化し、2 ターン目から制御します。

### 所要時間と幅の対応付けの修正

dt をそのターンに実際に展開した親の数と対応付けます。

- 通常版: `timestamp()` に渡す幅を新しいビームの大きさ `candidates.size()` から、そのターンに展開した親の数 `cand.size()` に変更します。
- turn 版: `expanded_leaf_count` を使用します。現状で既に正しく対応付けられています。

比率による制御では単位コストの絶対値を使用しませんが、初期補正用の回帰とログの解釈のために、この対応付けを修正します。

### TL の超過と余った時間への対策

- **reserve**: TL の 2〜5% を経路復元と出力のために確保し、budget からあらかじめ差し引きます。
- **幅の強制的な縮小**: `elapsed + dt_hat * remain_costed_turns > time_limit` が成立した場合は、レートリミットを適用せずに 1 回の更新で W を `W_next = max(W_min, W_cur * r)` まで小さくします。残り時間が dt_hat を下回った場合は W = 1 に固定し、探索を最後まで実行することを最優先にします。
- **終盤での残り時間の使い切り**: 残りターンが少ない局面では rho による上側の制限を緩め、余った予算を最終盤の幅に割り当てます。メモリの上限を超えないように、別途上限を設けます。

### remain_costed_turns

- 通常版: `max_turn - turn` とします。正確な値をそのまま使用できます。
- turn 版: 提案 2 に記載します。

## 提案 2: turn 版固有の変更

### 展開直前での幅の適用

pool の生成時に幅を確定する代わりに、**展開の直前に上位 W 件へ切り詰める**方式にします。

- メタターン t の `get_next_beam` の前に、pool[t] の生存している entry に対して最新の推奨幅 W_t を計算します。
- `pool.size() > W_t` の場合は score で `nth_element` を行い、上位 W_t 件に入らなかった entry の aid を非生存にして解放します。その後 tree を走査します。
- pool の生成時の幅は上限として残します。値は `min(W_max, 直近推奨 * 1.5〜2)` 程度にし、メモリの使用量と push のコストを抑えます。

この変更により、幅の決定とコストの発生が同じメタターンになり、むだ時間がなくなります。
副作用として、push 時の threshold が実際に適用する幅に対応する threshold より緩くなり、try_op の受理がやや増えます。上限を推奨幅に近づけ、推定が安定した時点で上限を小さくすれば影響は小さくなります。

### ループ構造に基づく残りメタターン数の見積もり

`ema_step` と `min_target_in_tree / ave_step` による推定を廃止します。
コストが発生する残りのイテレーション数は、ループ構造から直接見積もることができます。

- ループは turn を 1 ずつ進めます。`min_target_in_tree > turn` のイテレーションはスキップされ、コストはほとんど発生しません。
- したがって、コストが発生する残りのイテレーション数の上限は `U = max_turn - max(turn + 1, min_target_in_tree)` です。
- 過去の実績から `costed_rate = turn_sum / (turn + 1)` を求め、`remain_costed_turns = min(U, (max_turn - turn) * costed_rate)` とします。timestamp_meta はコストが発生するターンでのみ呼び出されるため、分子はそのまま使用できます。

U は決定的な上限であるため、推定が外れても TL を超過する方向にはずれません。
遅れている leaf 1 つに左右される `min_target` の前進速度とは異なり、分布の裾に対して頑健になります。

### active / empty の扱い

dt_hat は active と empty を区別せずに、コストが発生するターンの所要時間から求めた EMA で十分です。
active と empty の比率が急に変化する問題では、現行の分離で使用している active 率とそれぞれの dt を累積平均から EMA に変更し、`dt_hat = rate * dt_active + (1 - rate) * dt_empty` と合成します。分離の考え方は現行のままとし、統計量を求める範囲だけを直近に限定します。

## 提案 3: 終了状態への到達が必須で探索のターン数が可変の問題への対応

max_turn が上限にすぎず、finished な State への到達が必須の問題では、探索の実質的なターン数は finish が最初に現れるターンで定まります。
このターンはインスタンスと探索の質に依存し、探索中の見積もりも毎ターン変化します。
`remain = max_turn - turn` をそのまま使用すると残りターン数を過大評価し、W が小さいまま TL を大きく残して終了します。逆に、楽観的な見積もりをそのまま使用すると TL を超過します。この問題には次の 3 段階で対応します。

### State インターフェースの追加

```cpp
// この状態から finish までに必要なターン数の見積もりを返す
// このメソッドは optional である
// requires で検出し、定義されていない場合は従来の max_turn ベースにフォールバックする
int estimate_remaining_turns() const;
```

- 厳密な値である必要はありません。**単調で、真の残りターン数におおむね比例していれば十分です。** 常に 2 倍の値を返すようなスケールのずれは、後述の較正で打ち消されます。
- 実装例: 残りのタスク数、残りの距離 ÷ 1 ターンの平均移動量、未処理の要素数
- 呼び出す箇所は、展開する親の状態へ apply した直後です。すべての親で呼び出すとコストが幅に比例して増えるため、先頭の k 個 (8 個程度) の親のサンプリングで十分です。

### 集約と較正

1. **集約には悲観的な側の分位点を使用します。**
   サンプルの 75% 点程度を R_t とします。残りターン数を過大評価しても W が小さくなるだけで安全ですが、過小評価すると TL の超過につながります。この非対称性があるため、悲観的な側の値を採用します。
2. **予測値の減少速度で較正します。**
   予測器のスケールのバイアスを、実際の 1 ターンあたりの予測値の減少量 `p = EMA(R_t - R_{t+1})` で評価し、`remain_hat = clamp(R_t / max(p, eps), 1, max_turn - turn)` とします。予測器が整合的であれば p ≈ 1 となり、較正は恒等変換になります。turn 版の min_target の進行速度による推定と同じ考え方ですが、対象がビームを代表する状態の予測値であり、最も遅れている leaf の前進に左右されない点で頑健です。
3. **remain_hat の変動はレートリミットで抑えます。**
   remain_hat が毎ターン変化しても、W の変化率は rho で抑えられているため発散しません。remain_hat 自体を EMA で弱く平滑化してもかまいませんが、残り十数ターンの終盤では平滑化を無効にし、遅れによって時間が余ることを避けます。

### 制御器への接続

- 共通コントローラの `remain_costed_turns` を remain_hat に置き換えるだけで接続できます。EMA、レートリミット、reserve、幅の強制的な縮小はそのまま使用できます。比率による制御は、remain が何を表すかに依存しません。
- turn 版では `remain_costed_turns = min(U ベースの推定, remain_hat * costed_rate)` と組み合わせます。
- 現行の仕様では最初の finish で探索を打ち切って return します。この前提では予算を finish に到達するターンまでに配分する必要があり、remain_hat がそのターン数の見積もりに当たります。将来 finish の後も TL まで改善を続けるモードを追加する場合も、remain の定義を「TL までに見込まれる反復数」に変更するだけで制御器を共用できます。

## 検討したが採用しなかった案

- **予測モデルの精緻化 (a + b*W + c*tree_size の逐次回帰)**:
  むだ時間と、所要時間と幅の対応のずれが残る限り、モデルの精度を上げても開ループでは安定しません。制御器の初期補正を補助する目的であれば、将来導入する余地があります。
- **総ノード数の予算を先に決定する方式**:
  TL / 単位コストで総展開数を先に決定し、均等に配分します。実装は最も簡単ですが、単位コストのドリフトの影響を受けやすい方式です。比率による制御が毎ターン行う計算を静的に近似したものにすぎません。
- **事前のドライラン**:
  短時間の試行で幅を決定してから、本番の探索を実行します。TL の一部を本番の探索に使用できなくなるうえ、序盤と終盤でコストが異なる問題に対応できません。

## 検証計画

- `width_hist` と毎ターンの dt を CSV に出力し、幅の推移、終了時刻、振動の有無を確認します。
- 合成 State で次のケースを確認します。
  - 1 候補あたりのコストがターンに比例して増えるケース
  - 分岐数が途中で階段状に変化するケース
  - turn 版: target_turn の大きな差分を混ぜ、min_target が停滞するケース
  - 終了状態への到達が必須の問題: finish への到達で打ち切る合成 State に、バイアスとノイズを加えた `estimate_remaining_turns` を実装し、finish 時点の消費時間が TL の近傍に入るケース
- 合格条件
  - 終了時刻が `[0.93 * TL, TL]` に入ります。終了状態への到達が必須の問題では finish 時点で判定します。
  - 幅が単調でない振動 (周期的な上下) をしません。
  - 固定幅を手動で調整した基準と比較して、スコアが劣化しません。

## 実装時の変更対象

- `beam_param.cpp`: `get_beam_width`, `recommend_width`, `compute_req_w` に相当する処理を比率による制御に置き換えます。EMA、レートリミット、reserve、幅の強制的な縮小を追加します。`min_beam_width` と `max_beam_width` を追加し、既定値はそれぞれ 1 と無制限にします。累積平均による統計はログの互換性のために残してもかまいません。
- 両版共通: `estimate_remaining_turns` を requires で検出し、展開する親から抽出したサンプルに対して呼び出します。分位点で集約し、p で較正して remain_hat を算出します。
- `beam_search.cpp`: `timestamp()` へ渡す幅を、展開した親の数 `cand.size()` に変更します。幅の更新を毎ターン行うようにします。
- `beam_search_turn.cpp`: `get_cands()` で確定する幅を上限として扱うように変更します。メタターンの先頭で pool[t] を上位 W_t 件に切り詰める処理を追加します。`ema_step` に依存する remain_meta の推定を、ループ構造に基づく見積もりに置き換えます。

# クラスタリング拡張案

## 結論

SA（焼きなまし）版には追加する価値がある。ただし、通常のK-meansを置き換えるものではなく、次の場合に使う別の選択肢とする。

- クラスタの個数や重さに条件がある
- 点ごとに所属可能なクラスタが異なる
- K-meansでは表しにくい費用や制約を加えたい
- 最小費用流で使う `O(nk)` 本の辺を作るには規模が大きすぎる
- K-meansで得た局所解から、所属を入れ替えてさらに改善したい

通常の二乗ユークリッド距離だけなら、まずK-means++と複数初期値を使う方が速く、安定している。SA版は、K-meansの結果を初期解として短時間だけ使う形を基本とする。

## 現在の三方式が正確に求める範囲

### 通常版

中心を固定すると、各点を費用が最小の中心へ割り当てる処理は正確である。所属を固定したときも、`center_of` が最良の中心を返すなら中心更新は正確である。

ただし、この二つを交互に繰り返しても、クラスタリング全体の最適解が得られるとは限らない。初期値に依存する局所解で止まる。

### Hamerly法

Hamerly法は、条件を満たす距離について不要な距離計算を省く方法である。通常版と同じ所属を求めるための高速化であり、解の正確さを上げる方法ではない。

### 個数制約付き版

中心を固定したとき、個数制約を守る所属のうち、整数の `flow_cost` の合計が最小になる所属を最小費用流で求める。この部分は正確である。

その後の中心更新まで含めた全体は、通常版と同じく交互更新であり、全体の最適解は保証しない。また、`flow_cost` が本来の `cost` を丸めた値なら、正確なのは丸めた費用に対してである。

### SA版

SA版は、一点の移動や二点の交換を繰り返す近似解法である。一時的な悪化も許すため、K-meansが抜けられない局所解から移動できることがある。一方で、最適解や、最小費用流と同じ所属を得る保証はない。

したがって「最小費用流の方が常に正確」「SAの方が常に高品質」という関係ではない。

| 比較する範囲 | 有利な方法 |
|---|---|
| 固定中心、個数制約、加算可能な整数費用 | 最小費用流が最適な所属を保証 |
| 中心更新まで含む全体 | どちらも全体の最適解を保証しない |
| 通常のK-meansを短時間で解く | K-means++と複数初期値 |
| 複雑な制約や費用を扱う | SAが組み込みやすい |
| `n` と `k` が大きく `O(nk)` 本の辺が重い | SAを時間で打ち切る方法が使いやすい |

一般のK-meansは計算困難な問題なので、最小費用流を一部に使ってもクラスタリング全体が厳密解法になるわけではない。

## SA版の役割

近傍の詳細は [`sa_neighborhood_design.md`](sa_neighborhood_design.md) にまとめる。

### 推奨する使い方

1. K-means++、通常版、または個数制約付き版で初期解を作る。
2. SAで一点移動、二点交換、三点循環、二・三クラスタ再構築を行う。
3. 必要なら、最後に改善する操作だけを繰り返して仕上げる。

個数が固定なら二点交換を使う。個数に上下限があるなら、条件を守る一点移動と二点交換を併用する。

制約なしのK-meansでは、SAを最初から長く回すより、複数初期値のK-meansへ時間を使った方がよい場合が多い。SAは任意で有効にする仕上げ処理とする。

### 最初に扱う範囲

初版は次に絞る。

- クラスタ数は固定
- 初期所属を受け取る
- 各クラスタの費用の合計を最小化する
- クラスタごとの点数に下限と上限を設定できる
- 一点移動、二点交換、三点循環、二・三クラスタ再構築を使う
- 常に条件を満たす状態だけを保持する
- 既存の `sa_run` に渡せる状態を作る

点ごとの重さ、所属先の制限、固定済みの所属は、その次に追加する。これらを最初から一つの巨大な設定型へ入れると、無効な操作が増え、実装も使い方も分かりにくくなる。

### 状態が持つもの

```cpp
labels              // 各点の所属
members             // 各クラスタに属する点
position_in_cluster // members 内の位置
cluster_sizes       // 各クラスタの点数
cluster_data        // 中心と費用を差分計算するための集計情報
total_cost          // 全クラスタの費用合計
```

一点を削除するときは `members` の末尾と交換して削除すれば `O(1)` で更新できる。`position_in_cluster` も同時に更新する。

提案中の操作は、移動元、移動先、点番号、変更前後の費用だけを持つ。採択されるまで所属配列を書き換えない。これにより、棄却時の復元を不要にする。

### 費用を高速に更新する方法

一般の `cost` と `center_of` だけでは、一点を移すたびに移動元と移動先の中心を作り直し、その全所属点の費用を計算し直す必要がある。これでは一手が最悪 `O(n)` になり、SAには重い。

そこでSA版では、クラスタごとの小さな集計情報から費用を計算できることを前提にする。

二乗ユークリッド距離なら、点の次元を `d` として次を持てばよい。

```cpp
count                    // 点数
coordinate_sum           // 各座標の合計
squared_norm_sum         // 各点の座標二乗和の合計
```

クラスタ内の二乗誤差和は、この集計情報から計算できる。一点移動と二点交換の評価・適用はいずれも `O(d)` になる。

汎用版では、利用側が次の処理を定義する形がよい。

```cpp
make_empty_cluster_data()
add_point(cluster_data, point_index)
remove_point(cluster_data, point_index)
cluster_cost(cluster_data)
make_center(cluster_data)
```

SA側は、影響する二クラスタの集計情報だけを複製して変更後の費用を求める。集計情報が大きい問題には、問題専用のSA状態を書いた方がよい。

### 近傍操作

次の順で用意するのがよい。

| 優先度 | 操作 | 主な用途 |
|---:|---|---|
| 1 | 一点を別クラスタへ移す | 個数に余裕がある場合の基本操作 |
| 1 | 異なるクラスタの二点を交換する | 個数固定の場合の基本操作 |
| 2 | 三クラスタ間で一点ずつ循環移動する | 二点交換だけでは抜けられない局所解 |
| 2 | 二、三クラスタの一部を再構築する | 境界付近の所属をまとめて変更する |
| 3 | クラスタの分割と統合を同時に行う | 中心の配置自体が悪い場合 |

一点移動では、移動前の中心までの距離だけを比較せず、移動後に両クラスタの中心が変わることも含めて費用差を計算する。Lloyd法が収束した後でも、この一点移動で改善できる場合がある。二点交換と循環移動も、影響するクラスタの集計情報から変更後の費用を直接求める。

費用の大きい点や、現在の所属先と次に良い所属先の費用差が小さい点を選びやすくする方法も有力である。ただし、一部は一様に選び、偏った選び方だけにしない。

### 無作為な二点交換が弱い理由

全点から二点を一様に選ぶ方法は、実装は軽いが改善率が低い。

- 同じクラスタの二点を選ぶと所属が変わらない
- 離れたクラスタ同士を選ぶと費用が大きく悪化しやすい
- 隣り合う二クラスタを選んでも、交換する価値があるのは主に境界付近の点である
- 終盤は温度が低いため、大きく悪化する提案はほぼ採択されない

クラスタ数が多いほど、有力な二クラスタと有力な二点を同時に引く確率は小さくなる。探索回数を増やすだけでは無駄が多い。

二点交換は残すが、次の順で候補を選ぶ。

1. 交換を試す二クラスタを選ぶ。
2. 一方から、交換候補になりやすい点を選ぶ。
3. 他方から少数の候補点を調べ、正確な費用差が最もよい点を選ぶ。
4. 一部の試行だけは、偏りを避けるため無作為に選ぶ。

### 二クラスタの選び方

有力なのは次の三通りである。

#### 中心が近いクラスタを選ぶ

各クラスタについて、中心が近いクラスタを少数保存する。二点交換と一点移動の相手は、その中から選ぶ。明らかに離れたクラスタ同士の提案を減らせる。

中心が動くため、近いクラスタの一覧は一定回数の採択後か、再構築後に更新する。古い一覧を提案に使っても、最終的な費用差を現在の状態から計算すれば正しさは失われない。実装では各点の次候補も、この一覧にあるクラスタだけから選ぶ。

#### 境界を共有しそうなクラスタを選ぶ

各点について、現在の所属先以外で費用が最小のクラスタを一つ求める。その組を数え、相互に候補点が多いクラスタ同士を選びやすくする。

これは中心間距離だけより、実際の点の分布を反映する。細長いクラスタや密度に偏りがある場合にも使いやすい。

#### 費用が大きいクラスタから選ぶ

最初のクラスタを、クラスタ内費用が大きいものから選びやすくする。ただし点数が多いだけで費用も大きくなるため、個数が自由なら一点当たり費用も見る。

個数固定なら、同じ個数のクラスタ同士では総費用をそのまま比較できる。個数が異なる場合は、総費用と一点当たり費用を混ぜて選ぶか、両方の選択方法を持つ。

### 点の選び方

点 `i` について次を持つとよい。

```text
現在費用      = 現在のクラスタ中心に対する費用
次候補費用    = 現在の所属先以外で最も小さい費用
所属の余裕    = 次候補費用 - 現在費用
次候補クラスタ
```

- 現在費用が大きい点は、現在のクラスタ内で外れた位置にある
- 所属の余裕が小さい点は、別のクラスタへ移りやすい
- 次候補クラスタが交換相手なら、二点交換の候補として特に有力である

現在費用だけで選ぶと、点群全体の外側にある点を過剰に選びやすい。外側の点は中心から遠くても、他の全中心からはさらに遠いことがある。この場合は現在費用が大きくても所属の余裕も大きく、交換候補としては弱い。

そのため、二点交換では所属の余裕を主に使い、現在費用の大きい点を一部混ぜる。候補を一つに固定せず、上位の点から確率的に選ぶ方が探索範囲を保てる。

### 二点交換の具体案

個数固定の場合は次の方法が扱いやすい。

1. クラスタAを、費用を考慮しつつ選ぶ。
2. Aと近いクラスタ、またはAとの境界点が多いクラスタからBを選ぶ。
3. Aから、次候補がBで所属の余裕が小さい点 `x` を選ぶ。
4. Bから、次候補がAの点と現在費用が大きい点を合わせて数個選ぶ。
5. `x` と各候補 `y` の交換後費用を正確に計算し、最もよい組を提案する。

一回につきBの全点を調べると重いため、候補数に上限を設ける。候補がない場合だけBから一様に数点選ぶ。

二乗ユークリッド距離では、クラスタごとに点数、座標和、座標二乗和を持てば、一組の交換後費用を `O(d)` で正確に求められる。候補数を `s` とすると、一回の提案は `O(sd)` である。

所属の余裕や次候補クラスタは、中心が変わるたびに全点分を更新すると重い。実装では各クラスタに近い `h` 個の中心だけを候補とし、一定回数の採択ごとに `O(nhd+k²d)` で更新する。その間は古い値を候補選びだけに使う。採択判定に使う費用差は必ず現在の集計情報から計算する。

### 一点移動はLloyd法の後でも有効

Lloyd法の収束は、現在の中心を固定したときに各点が最も近い中心へ所属していることを表す。一点を移した後は移動元と移動先の中心も変わるため、中心の変化まで含めれば改善する一点移動が残っている場合がある。

二乗ユークリッド距離で、点 `x` を点数 `a` のクラスタAから点数 `b` のクラスタBへ移す費用差は、現在の中心を `center_a`、`center_b` として次の形になる。

```text
- a / (a - 1) * squared_distance(x, center_a)
+ b / (b + 1) * squared_distance(x, center_b)
```

この式は `a >= 2` の場合に使える。中心を固定した距離比較より強く、一点につき候補クラスタを少数に絞れば高速である。

### 全体の端にあるクラスタについて

点群全体の端にあるクラスタが、必ず悪いわけではない。外側の点は移動先の候補が少ないため、所属が明確なことも多い。

一方、個数制約がある場合は、端のクラスタが必要な点数を集めるため内側へ細長く伸びることがある。また、隣接するクラスタが少ないため、二点交換だけでは中心を大きく動かしにくい。この場合は局所解から抜けにくい。

したがって「端にある」という理由だけで選ぶのではなく、次を使って問題のあるクラスタを判定する。

- 一点当たり費用が大きい
- クラスタ内で中心から遠い点が多い
- 形が細長い
- 近い別クラスタとの境界点が多い
- 分割して作る二クラスタの費用が大きく改善する

端のクラスタを直すには、二点交換を増やすより、隣接する二、三クラスタの再構築や、分割と統合を同時に行う操作が向く。

「クラスタの端にある点」と「点群全体の端にある点」は区別する。クラスタ同士の境界にある点は交換候補として有力だが、点群全体の外側にある点は、他の所属先がなく交換候補として弱いことがある。

### 二、三クラスタの破壊・再構築

追加する価値は高い。ただし、現在の中心を固定して所属だけを決め直す方法では、同じ所属に戻りやすい。

- 通常版の収束後は、各点が現在の中心に最も近い
- 個数制約付き版の収束後は、現在の中心に対する所属を最小費用流で求め終えている

したがって、二クラスタを選び、現在の二中心に対して点を割り当て直すだけでは、ほとんど変化しない。中心の候補を選び直すか、現在の中心を使わずに局所的なK-meansをやり直す必要がある。

#### 境界付近だけを再構築する

最初に入れるなら、この方法がよい。

1. 中心が近い二、三クラスタを選ぶ。
2. 現在の所属先と別の所属先の費用差が小さい点を集める。
3. 集めた点だけ所属を外し、残した点から各クラスタの集計情報を作る。
4. 個数制約を守りながら、外した点を割り当て直す。
5. 影響したクラスタの費用差を求め、通常のSAと同じ基準で採択する。

クラスタの中心付近にある点は所属が変わりにくいため残し、判断が難しい点だけを再構築する。全所属点を扱うより速く、同じ所属へ戻る割合も下げられる。

境界付近の点だけでなく、現在の中心から特に遠い点を少数混ぜる方法もよい。誤ったクラスタへ取り残された点を動かしやすくなる。

#### 選んだクラスタ全体を再構築する

選んだクラスタの所属点をすべて集め、新しい仮中心を選んで、その範囲だけK-meansを数回行う。仮中心には次のいずれかを使う。

- 集めた点からK-means++で選ぶ
- 最も離れた点を順に選ぶ
- 現在の中心から離れた点を一つ選び、中心配置を崩す

選んだ点数を `m`、クラスタ数を `r`、局所的なK-meansの反復数を `J` とすると、個数制約がない場合は `O(Jmrd)` である。ここでは `r` は2または3なので、`m` を制限すれば使いやすい。

各クラスタの個数が固定され、仮中心も固定されている場合、二クラスタへの最良の割当は、各点について二中心への費用差を並べることで `O(md+m log m)` で求められる。三クラスタでは、先頭二クラスタへ割り当てた点数を状態とする動的計画法を使えば、対象点数 `m` に対して最悪 `O(m³)` で正確に求められる。対象が大きい場合は、交換を繰り返す近似も候補になる。

この操作は計算が重いので、毎回は行わない。開始から中盤に低い割合で使い、選んだ点数が上限を超える場合は境界付近だけの再構築へ切り替える。

#### 分割と統合を同時に行う

三クラスタを扱うなら、無作為に三つ選ぶより次の操作が有力である。

1. クラスタ内費用が大きいクラスタを一つ選び、二つに分ける。
2. 中心が近い二クラスタを一つにまとめる。
3. 関係する三クラスタの所属を再構築する。

クラスタ数を変えずに、中心が不足している場所へ一つ移せる。現在の中心配置そのものが悪い場合は、一点移動や二点交換より大きな改善を得やすい。

個数が固定されている場合は、実際にクラスタを一つへ減らすのではなく、選んだ三クラスタの点を集め、指定された三つの個数を守って分け直す。分割と統合は、新しい中心を作る方針を表す。

### その他の有力な近傍

#### 三クラスタの循環移動

クラスタAからB、BからC、CからAへ一点ずつ移す。各クラスタの個数を保ったまま三点を動かせる。二点交換がすべて非改善でも、三点の循環移動なら改善する場合がある。

三点を全探索すると重いため、最初の一点を無作為または高費用の点から選び、残りは移動先の候補を少数調べる。

#### 連鎖移動

一点を別クラスタへ移し、上限を超えたクラスタからさらに一点を別のクラスタへ移す。最後に空きのあるクラスタへ到達したら、一連の移動をまとめて提案する。

点数や重さに上下限がある場合に有効である。連鎖の長さは2から5程度で打ち切り、同じクラスタを二度通らないようにする。

#### 場所を指定した再構築

座標上の一点を選び、その近くにある点を所属に関係なく集めて再構築する。クラスタ全体ではなく、問題のある狭い範囲だけを変更できる。座標上で近い点を高速に集める方法がある場合に有力である。

### 近傍の使い分け

- 一点移動と二点交換を大部分に使う。
- 三点の循環移動と境界付近の再構築を次に使う。
- クラスタ全体の再構築と分割・統合は、合わせて数パーセント程度から試す。
- 重い再構築は開始から中盤を中心に使い、終盤は小さい操作を増やす。
- 再構築する点数に上限を設け、巨大なクラスタを選んだ場合は境界付近の点だけを使う。

再構築中は本体の所属を変更せず、作業用配列に新しい所属と集計情報を作る。採択された場合だけ本体へ反映すれば、棄却時の復元処理は不要である。作業用配列は状態に持たせて再利用する。

### 初期解

公開関数 `clustering_sa_from_labels` は、利用側が作った有効な所属を受け取る。通常版と個数制約付き版のK-meansから始める場合も、その結果の `labels` を渡す。

大規模入力で最小費用流を避けたい場合は、指定個数になるよう点を詰めるだけの初期化も用意する。ただし、初期解の品質は低いため、点の順番を乱すか、近い中心を優先する簡単な初期化を選べるようにする。

### 計算量

点数を `n`、クラスタ数を `k`、点の次元を `d`、SAで評価する操作数を `M` とする。

二乗ユークリッド距離用の集計情報を使う場合は次の通り。

| 処理 | 時間 | 追加メモリ |
|---|---:|---:|
| 初期状態の構築 | `O(nd+k)` | `O(n+kd)` |
| 一点移動の評価・適用 | `O(d)` | `O(d)` |
| 二点交換の評価・適用 | `O(d)` | `O(d)` |
| 三点の循環移動の評価・適用 | `O(d)` | `O(d)` |
| `b` 点を `r` クラスタへ再構築 | `O(Jbrd)` | `O(b+rd)` |
| `m` 点を `r` クラスタへ再構築 | `O(Jmrd)` | `O(m+rd)` |
| SA全体 | `O(nd+Md)` | `O(n+kd)` |

`b` は境界付近から選んだ点数、`m` は選んだクラスタに属する点数、`r` は再構築するクラスタ数、`J` は局所的なK-meansの反復数である。一般の集計情報では、`d` をその集計情報の複製・更新・費用計算にかかる時間へ置き換える。

SA全体の行は、一点移動、二点交換、三点の循環移動だけを使う場合である。再構築を行った分は、その回数と対象点数に応じて別に加える。

最小費用流版は固定中心に対して強いが、各反復で `O(nk)` 本の辺を持つ。SA版は評価する操作数を時間に合わせて止められるため、大きな入力で計算量を調整しやすい。

## 追加しておきたい別のクラスタリング

### 優先度1: K-center

各点から最も遠い点までの距離を最小化する。点のまとまりより、拠点配置、担当範囲、最大移動距離の抑制に向く。

距離が三角不等式を満たし、中心を入力点から選ぶ場合、最も遠い点を次の中心として選ぶ方法は最適値の2倍以内を保証する。時間 `O(nk)`、追加メモリ `O(n)` で実装できる。AHCの初期解として使いやすいため、SA版の次に追加する価値が高い。

想定ファイル名は `kcenter.cpp` とする。

### 優先度2: K-medoids

各クラスタの中心を、必ず入力点の一つから選ぶ。平均を定義できないデータや、任意の距離表を使う場合に向く。

現在の `cost` と `center_of` でも表現はできるが、素朴に最良の代表点を探すとクラスタごとに点数の二乗時間がかかる。代表点の交換を差分評価する専用版には意味がある。

想定ファイル名は `kmedoids.cpp` とする。初版では後回しでよい。

### 優先度3: 重さ付きの容量制約

各点が人数、需要、荷物量などの重さを持ち、各クラスタの合計に上下限がある設定である。現在の個数制約付き版は点数を制約しており、この設定とは異なる。

点を分割できない場合、単純な最小費用流では正確に表せない。SAとの相性はよいが、有効な初期解の作成と、複数点をまとめて入れ替える操作が必要になる。初版の一点移動・二点交換が安定してから追加する。

### 優先度4: Mini-batch K-means

毎回全点を調べず、一部の点だけで中心を更新する近似版である。`n` が非常に大きい場合には速いが、通常版より解が不安定になる。AHCでは入力全体を見られる規模が多いため、優先度は低い。

### 優先度5: 密度によるクラスタリング

点が密な部分をクラスタとし、疎な点を外れ値として扱う。クラスタ数を事前に決めない用途には合うが、近傍探索の方法まで用意しないと汎用実装は `O(n^2)` になる。座標用の近傍探索ライブラリを整えてから検討する。

## 新しい実装が不要な設定

次は現在の通常版で表現できるため、まず使用例を追加すればよい。

- 重み付きK-means: `cost` に点の重みを掛け、`center_of` で重み付き平均を求める
- K-medians: 距離の絶対値和を `cost` とし、`center_of` で中央値を求める
- 独自の点型や中心型: 現在も `Point` と `Center` を別の型にできる

ただし、重さの合計に上下限を付ける設定は現在の通常版では表現できない。

## ディレクトリ構成

K-means以外の方式も同じ場所で扱うため、ディレクトリ名は `clustering/` とする。

```text
titan_cpplib/ahc/clustering/
  README.md
  kmeans.cpp
  kmeans_hamerly.cpp
  kmeans_balanced.cpp
  clustering_partition.cpp
  clustering_sa.cpp
  docs/
    kmeans.md
    clustering_sa.md
    hierarchical_clustering.md
    design.md
    sa_neighborhood_design.md
    benchmark.md
  test/
```

`clustering_partition.cpp` は所属、クラスタ内の位置、点数、一点移動、二点交換、三点循環を管理する。費用計算とSAを分けることで、問題専用の評価関数からも再利用できる。

既存のK-means、SA版、今後追加するK-centerやK-medoidsを同じ分類で管理する。

## 実装順

1. `clustering_partition.cpp`
2. 二乗ユークリッド距離用の `clustering_sa.cpp`
3. 一点移動と二点交換
4. K-means結果を初期解にする使用例
5. 個数固定・上下限制約と三点の循環移動
6. 境界付近の二、三クラスタ再構築
7. クラスタ全体の再構築と分割・統合
8. 利用側が集計方法を渡せる汎用版
9. K-center
10. 重さ付き容量制約とK-medoidsは必要になった時点で追加

SA版を最初から万能にせず、通常の二乗ユークリッド距離と個数制約で、差分計算と有効な状態の維持を確実にする。その後に汎用化する方が、短期AHCで使える実装になりやすい。

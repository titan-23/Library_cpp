# クラスタリングSAの近傍設計

## 実装済みの範囲

`clustering_partition.cpp` と `clustering_sa.cpp` に、二乗ユークリッド距離専用の初版を実装した。

- 一点移動
- 候補を絞った二点交換
- 三点の循環移動
- 二クラスタから境界付近と高費用の点を取り出す再構築
- 二クラスタ再構築が同じ所属へ戻った後の三クラスタ再構築
- 個数自由、個数固定、個数の上下限
- 候補情報の定期更新と近傍別の統計
- 既存の `sa_run` へ渡せる `ClusteringSaState`

連鎖移動、分割と統合、点の重さ、空クラスタは未実装である。公開インターフェースと計算量は [`clustering_sa.md`](clustering_sa.md) にまとめる。

## 対象

K-meansで使う二乗ユークリッド距離の合計を、SAでさらに改善する場合を中心に扱う。クラスタごとの個数が自由な場合、固定の場合、上下限がある場合を対象とする。

最も重要なのは、無作為な二点交換を大量に試すことではない。改善の可能性があるクラスタと点を安く絞り、最後の費用差だけを現在の状態から正確に求める。

## 結論

一つの近傍だけでは弱い。変更の大きさが異なる次の近傍を組み合わせる。

| 大きさ | 近傍 | 役割 |
|---|---|---|
| 小 | 一点移動 | 個数に余裕がある場合の基本 |
| 小 | 候補を絞った二点交換 | 個数固定の場合の基本 |
| 中 | 三点の循環移動 | 二点交換の局所解を抜ける |
| 中 | 連鎖移動 | 個数や重さの上下限を守る |
| 大 | 二、三クラスタの部分再構築 | 境界付近をまとめて直す |
| 大 | 分割と統合 | 中心配置そのものを変える |

探索の大部分は小さい近傍に使う。大きい近傍は高価だが、中心配置が悪い局所解を抜けるために必要である。

## 設計原則

### 候補選びと採択判定を分ける

中心が近い、所属の余裕が小さい、クラスタ内費用が大きい、といった情報は候補を選ぶためだけに使う。採択判定に使う費用差は、現在のクラスタ集計から正確に計算する。

候補情報が少し古くても、探索効率が下がるだけで費用差は誤らない。この性質を使い、候補情報を毎回更新しない。

### 条件を破る状態を作らない

個数固定なら二点交換や三点の循環移動を使う。上下限があるなら、実行後も範囲内に収まる一点移動か、最後に条件を満たす連鎖移動だけを提案する。

条件違反へ罰則を付けて一時的に許す方法は、罰則の調整が別に必要になる。初版では常に有効な状態だけを扱う。

### 大きな変更の費用差を点数で割らない

再構築は多くの点を動かすため、費用差も大きくなりやすい。しかし、費用差を変更点数で割ってSAへ渡すと、最小化する目的そのものが変わる。

大きな変更は探索の前半で使う、対象点数を制限する、再構築後に局所改善して悪化を小さくする、という方法で扱う。

### 完全な候補制限にしない

近いクラスタと境界点だけに限定すると、候補情報が外れた場合に必要な変更へ到達できない。一部はクラスタと点を一様に選ぶ。割合は小さくてよいが、0にはしない。

## 状態と補助情報

### 常に正しく保つ情報

```cpp
labels              // 各点の所属
members             // 各クラスタの所属点
position_in_cluster // members内の位置
cluster_sizes       // 各クラスタの点数
coordinate_sums     // 各座標の合計
squared_norm_sums   // 各点の座標二乗和の合計
cluster_costs       // 各クラスタの費用
total_cost          // 全費用
```

`members` から点を削除するときは末尾の点と交換する。`position_in_cluster` も同時に更新すれば `O(1)` で削除できる。

二乗ユークリッド距離では、クラスタ `C` の点数を `count`、座標和を `sum`、座標二乗和を `squared_sum` とすると、費用は次で求められる。

```text
cluster_cost(C) = squared_sum - dot(sum, sum) / count
```

一点移動、二点交換、三点の循環移動では、影響するクラスタの集計だけを変更する。

この式は空でないクラスタに使う。空クラスタの費用は0とする。初版は各クラスタの下限を1以上にすると実装が単純になる。

下限0も扱う場合、空クラスタには中心がない。候補選びのために以前の中心を残すことはできるが、その値を費用計算には使わない。最初の一点を入れた後の費用は0であり、その点が新しい中心になる。空クラスタへ新しい中心を置く操作は、通常の一点移動とは分けて扱う。

### 定期的に更新する候補情報

```cpp
nearby_clusters       // 各中心に近いクラスタ
alternative_cluster   // 各点の次候補クラスタ
assignment_gap        // 次候補費用 - 現在費用
point_cost             // 現在の中心に対する費用
boundary_points       // クラスタの組ごとの境界候補
cluster_badness       // 問題のありそうなクラスタを選ぶ値
```

中心が変わるたびに全点分を更新すると重い。実装では、各クラスタに近い `h` 個の中心だけを各点の次候補として調べ、一定回数の採択後か大きな再構築後にまとめて更新する。

## 問題のあるクラスタの選び方

実装では複数クラスタを無作為に取り出し、その中で一点当たり費用が最大のクラスタを選ぶ。候補数を増やすほど悪いクラスタを早く直せるが、同じ場所へ探索が偏りやすくなる。そこで50クラスタ以上では序盤だけ16個を比べ、中盤以降は4個へ戻す。`early_cluster_samples` と `cluster_samples` は個別に変更でき、自動切替えも無効にできる。

### クラスタ内費用

総費用が大きいクラスタを選びやすくする。ただし個数が異なる場合、点数が多いだけで総費用も大きくなるため、一点当たり費用も別に見る。

### 分割したときの改善見込み

一つのクラスタ内で仮の二中心を作り、数回だけK-meansを行う。元の費用から仮分割後の費用を引いた値が大きければ、その場所には中心が不足している可能性が高い。

全体の端にあるかどうかより、この値の方が直接的である。端のクラスタでもまとまっていれば分割候補にはならない。

### 統合したときの悪化

空でないクラスタA、Bの点数を `a`、`b`、中心を `center_a`、`center_b` とすると、二乗ユークリッド距離で両者を統合した際の費用増加は次になる。

```text
a * b / (a + b) * squared_distance(center_a, center_b)
```

この値が小さい二クラスタは、中心を一つ減らす候補になる。分割による改善が大きいクラスタと、統合による悪化が小さい二クラスタを組み合わせるのが、分割と統合の基本である。

### 境界点の多さ

各点の次候補クラスタを数え、相互に候補点が多いクラスタ同士を隣接候補とする。中心間距離だけでは拾いにくい、細長いクラスタ同士の関係も反映できる。

## 点の選び方

### 所属の余裕

```text
所属の余裕 = 次候補中心への費用 - 現在中心への費用
```

この値が小さい点はクラスタ同士の境界に近く、移動や交換の候補として有力である。

点群全体の外側にある点は、現在中心から遠くても、他の中心からはさらに遠いことがある。現在費用だけで候補を選ばず、所属の余裕も見る。

### 現在費用

現在費用が大きい点は、誤ったクラスタへ取り残されている可能性がある。所属の余裕が小さい点を中心に選びつつ、現在費用が大きい点も混ぜる。

### 一様な選択

候補上位だけを選び続けると、現在の中心から見て不利な変更を試せない。一部は全点から一様に選ぶ。

## 小さい近傍

### 一点移動

個数が固定されていない場合の基本である。点 `x` を、点数 `a` のクラスタAから点数 `b` のクラスタBへ移す費用差は次になる。

```text
- a / (a - 1) * squared_distance(x, center_a)
+ b / (b + 1) * squared_distance(x, center_b)
```

`a >= 2` が必要である。個数の上下限がある場合は、移動後も両クラスタが範囲内か先に確認する。

Lloyd法の収束後でも有効である。Lloyd法は現在の中心を固定した所属を調べるが、この式は一点移動後の中心変化も含める。

候補クラスタをすべて調べると一点につき `O(kd)` である。近い中心と次候補クラスタだけを調べれば `O(hd)` に減らせる。`h` は一つの中心について調べる候補クラスタ数である。

### 候補を絞った二点交換

個数固定の場合の基本である。

1. 費用が大きいクラスタAを選ぶ。
2. Aと近いか、境界点が多いクラスタBを選ぶ。
3. Aから、次候補がBで所属の余裕が小さい点 `x` を選ぶ。
4. Bから、次候補がAの点と現在費用が大きい点を合わせて `s` 点選ぶ。
5. `x` と各候補の交換後費用を正確に求め、最もよい組を提案する。

一組の評価は `O(d)`、一回の提案は `O(sd)` である。候補が取れない場合はBから数点を一様に選ぶ。

個数制約付きK-meansの直後は、現在の中心を固定した所属が `flow_cost` に対して最小費用流で最適化されている。そのため、中心を固定した二点交換では `flow_cost` を改善しない。交換後の二中心も更新した費用差を使う必要がある。`flow_cost` が本来の `cost` を丸めた値なら、この最適性は `flow_cost` に対するものであり、`cost` に対するものではない。

### 三点の循環移動

クラスタAからB、BからC、CからAへ一点ずつ移す。各クラスタの個数を保ち、二点交換では越えられない局所解を越えられる。

三点を全探索しない。最初の点と移動先を選び、次候補クラスタをたどって三クラスタの輪を作る。各段階で候補を少数に絞り、最後に三クラスタの費用差を正確に求める。

候補数を各段階で `s` として全組合せを調べると `O(s^2d)` になる。残りを順に選ぶ方法なら `O(sd)` だが、見つかる改善は少なくなる。両方を設定で選べるようにする。

### 連鎖移動

一点を別クラスタへ移し、上限を超えたクラスタから別の一点をさらに移す。空きのあるクラスタへ到達した時点で、全体を一つの変更として評価する。

個数や重さに上下限がある場合に有力である。連鎖の長さを小さく制限し、同じクラスタを二度通らない。途中の状態は本体へ反映しない。

点の個数が完全に固定なら、連鎖は閉じた輪になる。長さ2が二点交換、長さ3が三点の循環移動である。

### 複数点交換

点ごとに重さがある場合は、一点対一点の交換では容量を合わせにくい。片側の二点と他方の一点を交換する操作や、少数点同士を交換する操作を用意する価値がある。

個数だけを固定する設定では必要性が低いため、重さ付き容量制約を追加するときに実装する。

## 大きい近傍

### 二クラスタの境界点を再構築する

最初に追加する大きい近傍として適している。

1. 隣接する二クラスタを選ぶ。
2. 所属の余裕が小さい点と現在費用が大きい点を合わせて `b` 点外す。
3. 残した点から二クラスタの集計を作る。
4. 外した点を個数制約に従って割り当て直す。
5. 中心を更新し、割当と中心更新を少数回繰り返す。

個数固定で、現在の仮中心に対して一方へ入れる必要がある点数を `p` とする。各点について次を計算する。

```text
difference[i] = cost(point[i], center_a) - cost(point[i], center_b)
```

`difference` が小さい方から `p` 点をA、残りをBへ入れると、仮中心を固定した割当として最適になる。`nth_element` を使えば選択は平均 `O(b)`、費用計算を含めて一回 `O(bd)` である。

中心更新も含めて `J` 回繰り返す場合は平均 `O(Jbd)` になる。これは二クラスタ全体の最適解を保証しないが、無作為な二点交換より大きな変更を一度に作れる。

両クラスタに少なくとも一点を残すか、再構築用の仮中心を別に与える。点をすべて外して中心が未定義になる状態で、以前の中心を無条件に使わない。

### 二クラスタ全体を再構築する

二クラスタの全所属点を集め、仮中心を選び直して同じ処理を行う。対象点数を `m` とすると平均 `O(Jmd)` である。

現在の二中心から始めると同じ所属へ戻りやすい。次のいずれかで中心配置を崩す。

- 集めた点からK-means++で二中心を選ぶ
- 最も離れた二点を仮中心にする
- 高費用の点を一つ選び、もう一つをそこから遠い点にする

対象点数が上限を超える場合は、境界点だけの再構築へ切り替える。

### 三クラスタを再構築する

二クラスタでは作れない変更や、分割と統合に使う。

実装では対象を最大36点に制限する。仮中心と各クラスタの必要個数を固定した割当は、先頭二クラスタへ入れた点数を状態とする動的計画法で正確に求める。時間と割当復元用のメモリは最悪 `O(b³)` なので、二クラスタ版と同じ128点までは広げない。

一定確率で混ぜると、二クラスタ版が有効な100クラスタ問題で重要な試行回数を奪った。現在は二クラスタ版が規定回数だけ同じ所属へ戻った後に三クラスタ版を使う。失敗した二クラスタを固定して第三クラスタだけ加える案も比較したが、三クラスタすべてを選び直す方が平均費用はよかった。

対象が大きい場合は、近い中心へ仮割当した後、一点移動、二点交換、三点の循環移動で条件を直す。これは近似になるが、計算時間を制限しやすい。

### 分割と統合

クラスタ数を変えず、中心が不足している場所へ中心を移す操作である。

1. 分割したときの改善見込みが大きいクラスタAを選ぶ。
2. Aと異なるクラスタから、統合時の悪化が小さいB、Cを選ぶ。
3. A、B、Cの点を集め、三クラスタへ再構築する。

個数固定の場合も、A、B、Cの元の個数を守って三分割する。ここでいう分割と統合は、新しい中心を作る方向を決めるための考え方であり、最終的なクラスタ数や個数を変えるものではない。

点群全体の端にあるクラスタが細長くなった場合も、この操作が向く。端であること自体は選択条件にせず、分割による改善見込みを使う。

### 場所を限定した再構築

座標上の一点を選び、その周辺の点を所属に関係なく集めて再構築する。複数のクラスタにまたがる狭い範囲だけを変更できる。

点の近傍を高速に列挙できる場合に有力である。中心から遠い点を基準に選ぶ方法と、クラスタ境界を基準に選ぶ方法を用意する。

## 再構築の二つの使い方

### 改善処理として使う

現在の所属も候補に含め、費用が改善した場合だけ採用する。安定して費用を下げられるが、局所解から抜ける役割は弱い。

### SAの変更として使う

仮中心を無作為に選び直し、現在より悪い再構築結果も通常の温度で採択判定する。局所解を抜けられるが、大きく悪化しやすい。

前半はSAの変更として使い、中盤以降は改善処理として使う方法が扱いやすい。同じ関数の設定で意味を変えるより、呼び出す側で用途を分ける。

## 探索段階ごとの使い分け

| 探索段階 | 多く使う | 少し使う |
|---|---|---|
| 初期解の直後 | 一点移動、二点交換による改善 | 二クラスタ再構築 |
| 前半 | 二点交換、三点の循環移動 | 全体再構築、分割と統合 |
| 中盤 | 一点移動、二点交換 | 境界点再構築、連鎖移動 |
| 終盤 | 一点移動、二点交換 | 小さい境界点再構築 |
| SA終了後 | 改善する操作だけ | 高見込みの二クラスタ再構築 |

個数が自由なら一点移動を中心にする。個数固定なら二点交換を中心にし、三点の循環移動と二クラスタ再構築を補助にする。

大きな変更は一回の費用が高いため、単純な試行回数ではなく実行時間も見て割合を決める。

## 近傍の選択割合を調整する

近傍ごとに次を数える。

```text
試行回数
有効な提案数
採択数
改善した採択数
最良解を更新した回数
改善量の合計
使った時間
同じ状態へ戻った再構築回数
```

採択率だけを基準にしない。小さな改善を多く出す近傍だけが増え、大きな改善をまれに出す近傍が消えるためである。

一定時間ごとに、改善量と最良解更新を実行時間で割った値を参考に選択割合を調整する。探索の前半、中盤、終盤では別々に集計する。どの近傍も最低限の試行割合を残す。

自動調整は便利だが、初版から必須にはしない。まず統計を記録し、固定した割合を問題ごとに決められるようにする。

## 高速化

### 二段階で候補を調べる

所属の余裕、中心間距離、現在費用で安く候補を絞り、その候補だけ正確な費用差を求める。候補数 `s` を小さく固定すれば、一回の計算時間が安定する。

### 作業用配列を使い回す

点候補、再構築対象、仮の所属、仮のクラスタ集計を状態に持ち、毎回確保しない。再構築の最大点数を設定し、その大きさまで最初に確保する。

### 採択まで本体を書き換えない

小さい近傍は変更後のクラスタ集計だけを作る。大きい近傍は作業用配列へ新しい所属を作る。採択された場合だけ本体へ反映し、棄却時は作業領域を捨てる。

### 候補情報をまとめて更新する

次候補クラスタと所属の余裕は、一定回数の採択後に全点分を更新する。候補を使った提案の有効率が下がった場合は、予定より早く更新する。

### 汎用版と高速版を分ける

利用側が任意のクラスタ集計を渡せる版は再利用しやすい。一方、二乗ユークリッド距離専用版は集計方法と費用式を固定でき、定数倍を小さくできる。

最上位を狙う用途では、所属管理だけを共通化し、二乗ユークリッド距離用の状態と近傍を専用実装する。任意の費用を受け取る一つの巨大な実装へまとめない。

## 制約別の推奨構成

| 条件 | 主な近傍 | 補助する近傍 |
|---|---|---|
| 個数自由 | 一点移動 | 二点交換、二クラスタ再構築、分割と統合 |
| 個数固定 | 候補を絞った二点交換 | 三点の循環移動、二・三クラスタ再構築 |
| 個数に上下限 | 有効な一点移動、二点交換 | 連鎖移動、部分再構築 |
| 点に重さがある | 連鎖移動、複数点交換 | 部分再構築 |
| 所属先に制限がある | 許可された候補だけの小さい近傍 | 許可条件付き再構築 |

## 計算量

点数を `n`、クラスタ数を `k`、次元を `d` とする。近いクラスタの候補数を `h`、交換相手の候補点数を `s`、再構築する点数を `b`、局所的なK-meansの反復数を `J` とする。

| 処理 | 時間 |
|---|---:|
| 一点移動 | `O(hd)` |
| 二点交換 | `O(sd)` |
| 三点の循環移動 | `O(sd)` または `O(s²d)` |
| 長さ `l` の連鎖移動 | `O(lsd)` |
| 二クラスタの部分再構築 | 平均 `O(Jbd)` |
| 三クラスタの部分再構築 | `O(J(bd+b³))` |
| 候補情報の全更新 | `O(nhd+k²d)` |
| 中心間距離の全更新 | `O(k²d)` |

追加メモリは、所属とクラスタ集計に `O(n+kd)`、各点の次候補に `O(n)`、中心の近傍候補に `O(kh)` を使う。二クラスタ再構築の作業領域は `O(b+d)`、三クラスタ再構築は割当復元を含めて最悪 `O(b³+d)` である。

## SAとの接続

`State::modify` では近傍を選び、変更後の費用と必要な差分だけを保存する。本体の所属は変更しない。

`State::advance` で所属、クラスタ集計、全費用を確定する。`State::rollback` は保存した提案を破棄するだけにする。

大きな再構築も同じ形にする。ただし、作業用の所属配列を持つため、`modify` の実行時間が大きくなりすぎないよう対象点数と反復数に上限を設ける。

初期状態はK-means++の複数初期値、または個数制約付きK-meansから作る。同じ初期状態を何度も使うより、初期中心や最初の大きな再構築を変えて複数の探索を行う。

## 実装順

1. クラスタ所属と集計情報
2. 一点移動
3. 候補を絞った二点交換
4. 候補情報の定期更新と近傍別の統計
5. 三点の循環移動
6. 二クラスタの境界点再構築
7. 二クラスタ全体の再構築
8. 連鎖移動
9. 三クラスタ再構築と分割・統合
10. 近傍の選択割合の自動調整

最初から全近傍を入れない。一点移動と二点交換について、正確な費用差、条件維持、一秒当たりの試行数を確認してから大きい近傍を加える。

## 比較で記録するもの

- 時間ごとの最良費用
- 近傍ごとの試行数と採択数
- 改善した採択数と改善量
- 最良解の更新回数
- 一回当たりの時間
- 候補点を調べた数
- 再構築した点数
- 再構築後に同じ所属へ戻った割合
- 無効な提案の割合

最終費用だけでは、近傍が弱いのか、候補選びが外れているのか、計算が重すぎるのかを区別できない。時間ごとの推移と近傍別の内訳を残す。

# MirrorGrid: 鏡とブロックを配置するグリッド

`MirrorGrid` は長方形の盤面の各セルに直進、2 種類の鏡、光を吸収するブロックのいずれかを配置し、外周のポートまたは盤面内のセルから出た光の終点と経路を求めます。1 つのセルのタイルを変更する操作については、盤面を変更せずに、終点が変化するポートだけを取得できます。

```cpp
#include "titan_cpplib/ahc/grid/mirror_grid.cpp"
using namespace titan23;
```

## 最小例

```cpp
vector<string> rows = {
    "./..",
    "....",
    ".\\..",
};
MirrorGrid grid(rows);               // '.' は直進、'/' と '\' は鏡、'#' はブロック
grid.set(1, 3, MirrorTile::Block);   // 1 つのセルを変更する
cout << grid;                        // 盤面を文字で出力する

// ポート 1 (上辺の左から 2 番目) から入射した光の終点
RayEnd end = grid.trace_port(1);
if (end.is_port()) {
    cout << "port " << end.port << '\n';
} else if (end.is_block()) {
    cout << "block " << end.row << ' ' << end.column << '\n';
}
```

```text
./..
...#
.\..
port 13
```

ポート `1` から下向きに入射した光はセル `(0, 1)` の `/` で反射して左に進み、左辺の最も上にあるポート `13` に到達します。

## 規約

### セル、辺、タイル

セルの座標は左上を `(0, 0)` とし、`(row, column)` の順に表記します。セルの辺と方向は `GridDirection` で表し、順序は `Up`, `Right`, `Down`, `Left` です。

`enter_side` は光がセルに入るときに通過した辺を表します。下向きに進む光の `enter_side` は `Up` です。

| `MirrorTile` | 出力の文字 | 上から入った光 | 右から入った光 | 下から入った光 | 左から入った光 |
|---|---|---|---|---|---|
| `Empty`  | `.` | 下から出る | 左から出る | 上から出る | 右から出る |
| `Slash` | `/` | 左から出る | 下から出る | 右から出る | 上から出る |
| `Backslash` | `\` | 右から出る | 上から出る | 左から出る | 下から出る |
| `Block` | `#` | 吸収される | 吸収される | 吸収される | 吸収される |

### ポート番号

盤面の行数を `H`、列数を `W` とすると、外周には `2(H + W)` 個のポートがあります。ポートには上辺の左端から時計回りに番号を付けます。`2 × 3` の盤面では次の番号になります。

```text
       0   1   2
     +---+---+---+
  9  |   |   |   |  3
     +---+---+---+
  8  |   |   |   |  4
     +---+---+---+
       7   6   5
```

問題の入力の順序は時計回りとは限らないため、ポート番号は `port_at(side, index)` で求めます。`index` は上辺と下辺では列番号、右辺と左辺では行番号です。

| `side` | `index` の意味 | `port_at(side, index)` |
|---|---|---|
| `Up` | 列番号 | `index` |
| `Right` | 行番号 | `W + index` |
| `Down` | 列番号 | `W + H + (W - 1 - index)` |
| `Left` | 行番号 | `2W + H + (H - 1 - index)` |

`port_position(port)` は逆方向の変換であり、ポートに接するセルと、そのセルでポートがある辺を返します。同じセルに接するポートも辺ごとに区別します。`1 × 1` の盤面では上、右、下、左の辺のポートが順に `0, 1, 2, 3` です。

### 終点 `RayEnd`

光の終点は構造体 `RayEnd` で返されます。終点の種類に該当しないメンバは `-1` です。

```cpp
struct RayEnd {
    int port;     // 光が出たポートの番号
    int row;      // 光を吸収したセルの行
    int column;   // 光を吸収したセルの列
    int side;     // 光が到達した面

    bool is_port() const;
    bool is_block() const;
    bool is_loop() const;
};
```

| 終点の種類 | 判定 | `port` | `row`, `column`, `side` | 同じ終点を作成する関数 |
|---|---|---|---|---|
| 盤面の外に出た | `is_port()` | ポート番号 | `-1` | `RayEnd::port_hit(port)` |
| ブロックに吸収された | `is_block()` | `-1` | 吸収したセルと光が到達した面 | `RayEnd::block_hit(row, column, side)` |
| 閉路を周回し続ける | `is_loop()` | `-1` | `-1` | `RayEnd::loop()` |

- 面 `side` の値は上、右、下、左の順に `0` から `3` であり、`GridDirection` の値と一致します。
- 外周のポートから入射した光の終点は、必ずポートかブロックの面です。閉路は盤面内から出した光だけで発生します。
- ポート `p` から入射した光がポート `q` に到達するなら、ポート `q` から入射した光は同じ経路を逆向きに進んでポート `p` に到達します。終点のポートは入射したポートと必ず異なります。
- 同じブロックでも上の面と下の面は別の終点として扱います。
- ブロックを配置しない問題では終点が必ずポートであるため、判定せずに `end.port` を使用できます。
- 2 つの `RayEnd` は `==` で比較できます。

`end_id(end)` は終点を `0` 以上 `end_count()` 未満の整数に変換します。終点ごとの集計を配列で保持する場合に使用します。次の表ではポート数を `P = 2(H + W)` とします。

| 終点の種類 | `end_id` |
|---|---|
| 盤面の外に出た | `port` |
| ブロックに吸収された | `P + 4(row × W + column) + side` |
| 閉路を周回し続ける | `P + 4HW` |

## API 一覧

時間計算量の `K` は変更するセルの 4 辺から外向きに経路を追跡するときに通過するセル数の合計、`L` は 1 本の経路が通過するセル数です。

| メソッド | 内容 | 時間計算量 |
|---|---|---|
| `MirrorGrid(height, width)` | 盤面を作成する。全セルが `Empty` になる | `O(HW)` |
| `MirrorGrid(rows)`, `MirrorGrid(rows, tile_chars)` | 文字列の配列から盤面を作成する | `O(HW)` |
| `from_grid(rows)`, `from_grid(rows, tile_chars)` | 文字列の配列から盤面を再作成する。大きさは `rows` に合わせる | `O(HW)` |
| `height()`, `width()`, `port_count()`, `end_count()` | 行数、列数、ポート数、`end_id` の値の個数を返す | `O(1)` |
| `get(row, column)` | 現在のタイルを返す | `O(1)` |
| `set(row, column, tile)` | タイルを変更する | `O(1 + K)` |
| `port_at(side, index)`, `port_position(port)` | ポート番号と位置を相互に変換する | `O(1)` |
| `trace_port(port)` | ポートから入射した光の終点を返す | `O(1)` |
| `trace_port(port, on_cell)` | 終点を返し、通過したセルごとに `on_cell` を呼び出す | `O(1 + L)` |
| `trace_from(row, column, side)` | セルの辺 `side` から外へ出た光の終点を返す | `O(1)` |
| `trace_from(row, column, side, on_cell)` | 終点を返し、通過したセルごとに `on_cell` を呼び出す | `O(1 + L)` |
| `trace_all_ports()` | 全ポートの終点をポート番号順の `vector<RayEnd>` で返す | `O(P)` |
| `ports_through(row, column)` | 光がそのセルに入る外周のポートを返す。最大 4 個 | `O(1)` |
| `preview(row, column, tile)` | 盤面を変更せずに、タイルを変更した場合に終点が変化するポートを返す。最大 4 個 | `O(1)`。経路を追跡する場合は `O(1 + K)` |
| `end_id(end)` | 終点を整数に変換する | `O(1)` |
| `exit_side(tile, enter_side)` | セル内で光が出る辺を `0` から `3` の整数で返す。吸収される場合は `-1` を返す。クラス外の関数である | `O(1)` |
| `os << grid` | 盤面を `H` 行の文字列で出力する | `O(HW)` |

`preview` と `ports_through` は次の構造体を返します。

```cpp
struct PortChange {
    int port;                  // 終点が変化するポート
    RayEnd old_end, new_end;   // 変更前の終点と変更後の終点
};

struct PortDelta {
    array<PortChange, 4> changes;  // 先頭の count 件だけが有効で、残りの値は不定
    int count = 0;
};

struct PortList {
    array<int, 4> ports{};     // 先頭の count 件だけが有効
    int count = 0;
};
```

`on_cell` は `on_cell(int row, int column, GridDirection enter_side)` の形式の関数であり、光が通過したセルごとに通過した順で呼び出されます。同じセルを 2 回通過する場合は 2 回呼び出されます。光を吸収したブロックのセルでは呼び出されないため、吸収された位置は戻り値の `row`, `column` で確認します。

## 用途別の使用例

### 盤面の読み込み

文字列の配列をコンストラクタか `from_grid` に渡します。文字は出力と同じく `.` が直進、`/` と `\` が鏡、`#` がブロックです。

```cpp
int H, W;
cin >> H >> W;
vector<string> rows(H);
for (string &row : rows) cin >> row;
MirrorGrid grid(rows);
```

文字が異なる問題では、タイルを表す文字を `Empty`, `Slash`, `Backslash`, `Block` の順に連結した文字列を第 2 引数に渡します。第 2 引数に含まれない文字は `Empty` として扱います。次の例は `0` を直進、`1` を `/`、`2` を `\` として読み込みます。

```cpp
MirrorGrid grid(rows, "012");
grid.from_grid(rows, "012");   // 作成済みの盤面を再作成する場合
```

### 入力の順序からポート番号への変換

入力が「上辺を左から、下辺を左から、左辺を上から、右辺を上から」の順に与えられる場合は次のように読み込みます。

```cpp
vector<int> a(grid.port_count());
for (int c = 0; c < W; ++c) cin >> a[grid.port_at(GridDirection::Up, c)];
for (int c = 0; c < W; ++c) cin >> a[grid.port_at(GridDirection::Down, c)];
for (int r = 0; r < H; ++r) cin >> a[grid.port_at(GridDirection::Left, r)];
for (int r = 0; r < H; ++r) cin >> a[grid.port_at(GridDirection::Right, r)];
```

### 終点だけでスコアが定まる問題の焼きなまし

`preview` で終点が変化するポートだけを取得してスコアの差分を計算し、採択する場合だけ `set` を呼び出します。次の例では、ポート `p` から入射した光をポート `target[p]` に到達させる問題を扱い、到達先が一致したポートの個数をスコアとします。`rnd(n)` は `0` 以上 `n` 未満の乱数を返す関数、`accept(diff)` は採択を判定する関数とします。

```cpp
// dest[p] = ポート p から入射した光が到達するポート (ブロックを配置しない問題)
vector<int> dest(P);
vector<RayEnd> ends = grid.trace_all_ports();
for (int p = 0; p < P; ++p) dest[p] = ends[p].port;
int score = 0;
for (int p = 0; p < P; ++p) score += dest[p] == target[p];

for (int iter = 0; iter < 200000; ++iter) {
    int row = rnd(H), column = rnd(W);
    // 直進, '/', '\' の 3 種類のうち、現在と異なるタイルを選択する
    MirrorTile tile = (MirrorTile)(((int)grid.get(row, column) + 1 + rnd(2)) % 3);
    PortDelta delta = grid.preview(row, column, tile);  // 盤面は変更されない
    int diff = 0;
    for (int i = 0; i < delta.count; ++i) {
        const PortChange &change = delta.changes[i];
        diff += change.new_end.port == target[change.port];
        diff -= change.old_end.port == target[change.port];
    }
    if (accept(diff)) {
        grid.set(row, column, tile);  // 採択した場合だけ盤面を変更する
        for (int i = 0; i < delta.count; ++i) {
            dest[delta.changes[i].port] = delta.changes[i].new_end.port;
        }
        score += diff;
    }
}
```

`sa.cpp` の `State` に組み込む場合は、`modify` で `preview` の呼び出しとスコアの差分の計算までを行い、`advance` で `set` の呼び出しと `dest` の更新を行います。`modify` は盤面を変更しないため、`rollback` は空の処理で十分です。

Spectrum Router (yukicoder score contest 013) はこの形式の問題です。受信番号は `B[p] = A[dest[p]]` で求まります。

### 適用とロールバック

操作の適用とロールバックで状態を管理する探索 (ビームサーチなど) では、適用とロールバックのそれぞれで `set` を 1 回呼び出します。`set` で元のタイルに戻すと内部の記録も元の値に戻ります。次の例は `beam_search.cpp` の `State::apply_op` と `State::rollback` に対応します。

```cpp
struct Action {
    int row, column;
    MirrorTile before, after;
};

struct State {
    MirrorGrid grid;

    void apply_op(const Action &action) {
        grid.set(action.row, action.column, action.after);
    }

    void rollback(const Action &action) {
        grid.set(action.row, action.column, action.before);
    }
};
```

`before` には操作を作成する時点の `grid.get(row, column)` を設定します。候補の操作を `preview` で評価し、実際に適用する操作だけに `set` を使用すると高速です。

### 経路に依存するスコアと複数セルの変更

照らされたセルの個数のように経路に依存するスコアや、2 個以上のセルを同時に変更する操作では、`preview` の代わりに次の手順を使用します。次の例は照らされたセルの個数をスコアとし、複数のセルを同時に変更します。

```cpp
// lit[row][column] = そのセルを通過する光の本数
// スコアは照らされたセルの個数
auto add_path = [&](int port) {
    grid.trace_port(port, [&](int row, int column, GridDirection) {
        if (lit[row][column]++ == 0) ++score;
    });
};
auto remove_path = [&](int port) {
    grid.trace_port(port, [&](int row, int column, GridDirection) {
        if (--lit[row][column] == 0) --score;
    });
};

// changes: 変更する (row, column, tile) の一覧
// 1. 変更前の盤面で、変更するセルを通過するポートを収集する
vector<int> ports;
for (auto [row, column, tile] : changes) {
    PortList through = grid.ports_through(row, column);
    ports.insert(ports.end(), through.ports.begin(), through.ports.begin() + through.count);
}
sort(ports.begin(), ports.end());
ports.erase(unique(ports.begin(), ports.end()), ports.end());
// 2. 変更前の経路の分をスコアから除く
for (int port : ports) remove_path(port);
// 3. 盤面を変更する
for (auto [row, column, tile] : changes) grid.set(row, column, tile);
// 4. 変更後の経路の分をスコアに加える
for (int port : ports) add_path(port);
```

変更するセルをいずれも通過しない光は、変更後も同じ経路を進みます。したがって経路や終点が変化し得るポートは、すべて手順 1 で収集したポートに含まれます。変更するセルが `m` 個の場合、収集されるポートは高々 `4m` 個です。棄却する場合は `set` で元のタイルに戻し、スコアも元の値に戻します。

- 終点だけでスコアが定まる場合、手順 2 と手順 4 は `on_cell` を渡さない `trace_port(port)` で十分であり、どちらも `O(1)` で完了します。
- 経路長は `on_cell` が呼び出された回数で求まり、反射回数は `grid.get(row, column)` が鏡であった回数で求まります。
- 光を吸収したブロックのセルでは `on_cell` が呼び出されません。そのセルも集計に含める場合は戻り値の `row`, `column` を参照します。

### 盤面内の光源と閉路

`trace_from(row, column, side)` はセル `(row, column)` の辺 `side` から外へ出た光を追跡します。出発時には光源のセルのタイルを参照しません。

```cpp
MirrorGrid grid(2, 2);
grid.set(0, 0, MirrorTile::Slash);
grid.set(0, 1, MirrorTile::Backslash);
grid.set(1, 0, MirrorTile::Backslash);
grid.set(1, 1, MirrorTile::Slash);
// (0,0) から右へ出た光は 4 個の鏡で反射して (0,0) に戻る
RayEnd end = grid.trace_from(0, 0, GridDirection::Right);
assert(end.is_loop());

// 光源のセルをブロックにすると、戻った光はそのセルで吸収される
grid.set(0, 0, MirrorTile::Block);
end = grid.trace_from(0, 0, GridDirection::Right);
assert(end == RayEnd::block_hit(0, 0, GridDirection::Down));
```

- 辺 `side` の先が盤面外の場合は、その位置のポートを終点として直ちに返します。
- 光が光源のセルに戻った場合は、ほかのセルと同様に扱います。同じ辺から再び外へ出た場合は、閉路を周回し続ける終点を返します。
- `on_cell` は出発時の光源のセルでは呼び出されません。光が戻って光源のセルを通過するときには呼び出されます。
- `ports_through` と `preview` の対象は外周のポートから入射した光だけです。盤面内の光源については、光源ごとに通過するセルを `on_cell` で記録するか、全光源を再度追跡します。

### 終点ごとの集計

```cpp
// hits[終点の番号] = その終点に到達する光の本数
vector<int> hits(grid.end_count());
for (int port = 0; port < grid.port_count(); ++port) ++hits[grid.end_id(grid.trace_port(port))];
// ブロック (1,1) の上の面に到達する光の本数
int top = hits[grid.end_id(RayEnd::block_hit(1, 1, GridDirection::Up))];
```

## 注意点

- `preview` は盤面を変更しません。採択する場合に `set` を呼び出します。
- `set` は経路を追跡して記録を更新するため、`preview` より 1 桁から 2 桁遅くなります。候補の操作の評価には `set` とロールバックを使用しないようにします。
- `preview` が返す `changes` は先頭の `count` 件だけが有効です。残りの要素は初期化されていないため参照しないようにします。
- `on_cell` の中では同じ `MirrorGrid` の `set` を呼び出さないようにします。
- 終点が同じで経路だけが変化する操作では、`preview` の `count` は `0` になります。経路に依存するスコアの問題では「経路に依存するスコアと複数セルの変更」の手順を使用します。
- `ports_through` が返すポートの集合は、そのセル自身のタイルに依存しません。ポートの順序はタイルによって異なる場合があります。
- `preview` が経路を追跡するのは次の場合だけであり、この場合の時間計算量は `O(1 + K)` です。
  - 同じ光が 2 回通過するセルをブロックに変更する場合
  - 一部の辺だけで光を吸収するタイルを追加し、そのタイルが変更前か変更後のタイルである場合
- 引数の範囲チェックは `TITAN_DEBUG` の定義時だけ行われます。開発時は include の前に `#define TITAN_DEBUG` を記述します。
- 高さと幅は 1 以上とします。引数なしのコンストラクタで作成した `MirrorGrid` は、`MirrorGrid(height, width)` を代入するまで使用できません。

## 内部実装

### 盤面の表現

盤面は外周に番兵を 1 セルずつ加えた `(H + 2) × (W + 2)` の 1 次元配列で保持します。セル `(row, column)` の位置は `(row + 1)(W + 2) + (column + 1)` です。ある辺から隣のセルへ進むときは、位置に次の値を加算します。

| 辺 | 加算する値 |
|---|---|
| 上 | `-(W + 2)` |
| 右 | `+1` |
| 下 | `+(W + 2)` |
| 左 | `-1` |

隣のセルには反対側の辺から入ります。光が番兵に到達した場合は盤面の外に出たと判定し、番兵の位置からポート番号を表で求めます。角の番兵には上下左右の移動で到達しないため、番兵とポートは 1 対 1 に対応します。

経路の追跡では、セルのタイルから光が出る辺を表で求めて隣のセルへ進む処理を繰り返します。直進のセルでは進行方向も入る辺も変化しないため、表を参照せずに同じ方向へ進みます。

### 経路の有限性

ブロック以外のタイルは 4 辺を 2 組に分け、同じ組の辺どうしを接続します。

- 直進: 上と下、右と左
- `/`: 上と左、右と下
- `\`: 上と右、下と左

辺 `a` から入った光が辺 `b` から出るなら、辺 `b` から入った光は辺 `a` から出ます。入った辺から出ることはありません。

「どのセルにどの辺から入ったか」を状態とすると、ある状態の直前の状態は一意に定まります。入った辺を挟んで隣接するセルが直前のセルであり、直前のセルを出た辺とタイルから、直前のセルに入った辺が定まるためです。外周のポートから入射した直後の状態には盤面内に直前の状態が存在しないため、経路が同じ状態を 2 回通過することはありません。状態は `4HW` 個であるから、外周のポートから入射した光は必ず外周のポートかブロックの面で終了します。盤面内に閉路が存在しても、外周のポートから入射した光がその閉路に入ることはありません。

終点のポートは入射したポートと異なります。同じポートに戻るには経路の途中で折り返す必要があるが、どのタイルでも光は入った辺から出ないためです。

盤面内から出した光は閉路を周回する場合があります。直前の状態が一意に定まるため、閉路に途中から合流することはありません。したがって閉路を周回する光は必ず最初の状態に戻ります。`on_cell` を渡す `trace_from` は、最初の状態に戻ったことで閉路を検出します。

### 終点の記録

各セルの各辺について、その辺から外へ出た光の終点を記録します。これは `trace_from(row, column, side)` の終点を全セルの全辺について表に保持することに相当します。要素数は `4(H + 2)(W + 2)` であり、ブロックのセルの辺についても記録します。この方法は [Spectrum Router の解説](https://prussiancoder.github.io/spectrum-router-tools/editorial-254ce1e7e340fa76/) の step6 に基づきます。

光は逆向きにも同じ経路を進みます。したがって辺 `side` の記録がポート `p` であれば、ポート `p` から入射した光はその辺を通過してこのセルに入ります。

終点の記録は盤面だけで定まります。`set` で元のタイルに戻すと記録も元の値に戻ります。

`from_grid` は全セルのタイルを設定した後、すべての外周のポートと、光を吸収するすべての面から経路を 1 回ずつ追跡して記録を作成します。経路上で光が入った辺の記録は、追跡を開始したポートまたは面です。どの追跡でも通過しない辺の記録は閉路です。各辺の通過は高々 1 回であるため、計算量は `O(HW)` です。

記録の値は内部の番号であり、`end_id` の値とは異なります。除算を使用せずに行と列を復元できるように、列番号を固定のビット数で格納しています。

| 求める値 | 終点の記録からの求め方 |
|---|---|
| `trace_from(row, column, side)` | その辺の記録を返す |
| `trace_port(port)` | ポートに接するセルが光を吸収する場合は、そのブロックの面を返す。吸収しない場合は、光が出る辺の記録を返す |
| `trace_all_ports()` | 全ポートについて `trace_port` と同じ処理を行う |
| `ports_through(row, column)` | 4 辺の記録を上、右、下、左の順に参照し、ポートである記録を初めて出現した順に返す |

### `set` による記録の更新

`set(row, column, tile)` で値が変化する記録は、変更するセルを通過する経路上の辺の記録に限られます。これらの辺はすべて、変更するセルの 4 辺から外向きに延ばした経路上にあります。以下では変更するセルをセル `x` とします。`set` は次の手順で記録を更新します。

1. セル `x` の内部の接続を切断したと仮定した場合の、4 辺それぞれの到達先を求めます。到達先は外周のポート、ほかのブロックの面、セル `x` に戻る辺のいずれかです。多くの場合は現在の記録から求まり、その条件は `preview` の場合と同じです。記録から求まらない場合だけ 4 辺から外向きに経路を追跡します。ある辺から出た光が別の辺に戻った場合、戻った辺から出た光は同じ経路を逆向きに進むため、その到達先は追跡せずに設定します。出た辺自体に戻ることはありません。
2. 新しいタイルを適用し、各辺について「その辺からセル `x` に入った光の終点」を求めます。光が吸収される場合、終点はセル `x` のその面です。吸収されない場合は、光が出る辺の到達先を手順 1 の結果から求めます。到達先がセル `x` に戻る辺である場合は、戻った辺から再びセル `x` に入った光として処理を続けます。最初に入った辺に戻った場合は閉路です。
3. 4 辺の経路を追跡して記録を更新します。辺 `s` から延ばした経路上の各セルでは、光が入った辺に、辺 `s` について手順 2 で求めた終点を設定します。その経路で光を吸収したブロックの面にも同じ値を設定します。これらの辺から出た光は経路を逆向きに進み、辺 `s` からセル `x` に入るためです。
4. 手順 3 で通過するセルで光が出た辺の記録は、経路が外周のポートかブロックの面で終了する場合は変化しないため更新しません。経路がセル `x` に戻る場合は、戻った辺について手順 2 で求めた終点を設定します。
5. セル `x` 自身の 4 辺には手順 1 の到達先を設定します。セル `x` に戻る辺には、戻った辺について手順 2 で求めた終点を設定します。

手順 3 では、経路の最初のセルの記録が新しい値と同じである場合、その経路の追跡をスキップします。同じ経路上の記録はすべて同じ値であるためです。

### `preview` の計算方法

セル `x` に入るポートは `ports_through` で、変更前の終点は `trace_port` で、いずれも終点の記録から求まります。変更後の終点はセル `x` の 4 辺の記録から次のように求めます。ここで「セル `x` に戻る辺」は、セル `x` の内部の接続を切断したと仮定した場合に、その辺から外へ出た光がセル `x` に戻る辺を指します。

1. **セル `x` に戻る辺がない場合**
   4 辺の記録がすべて異なり、いずれも閉路でもセル `x` 自身の面でもなければ、セル `x` に戻る辺はありません。この場合は 4 辺を新しいタイルで再接続します。辺 `e` の記録がポート `p` であれば、ポート `p` から入射した光は辺 `e` から入ります。新しいタイルが辺 `e` で光を吸収する場合の終点はセル `x` の面 `e` であり、吸収しない場合の終点は光が出る辺の記録です。
2. **変更前がブロックの場合**
   記録がセル `x` 自身の面である辺がセル `x` に戻る辺であり、戻り先はその面の辺です。残りの辺の記録は、その辺から直接到達する終点です。これにより 4 辺の到達先がすべて求まるため、新しいタイルを適用します。光が出る辺がセル `x` に戻る辺である場合は、戻った辺から再びセル `x` に入った光として処理を続けます。
3. **変更前と変更後がいずれも鏡または直進の場合**
   終点は変化しないため `count == 0` を返します。
4. **鏡または直進をブロックに変更する場合**
   - 閉路の記録が 2 辺にある場合は、その 2 辺が互いにセル `x` に戻る辺であり、残りの 2 辺から入る光がセル `x` のその面で吸収されます。
   - 4 辺とも閉路の記録である場合は何も変化しません。
   - 同じ終点が 2 辺ずつに出現する場合は、記録から終点が定まらないため経路を追跡します。
5. **一部の辺だけで光を吸収するタイルが変更前か変更後のタイルである場合**
   経路を追跡します。

2 から 5 は 1 に該当しない場合、すなわちセル `x` に戻る辺がある場合の処理です。

1 の判定が正しい理由は次のとおりです。セル `x` に戻る辺 `s` が存在すると仮定します。辺 `s` から出た光は別の辺からセル `x` に戻ります。

- 戻った辺で吸収される場合、辺 `s` の記録はセル `x` 自身の面です。
- 吸収されずに辺 `s` から出る場合、辺 `s` の記録は閉路です。
- 別の辺 `t` から出る場合、辺 `s` と辺 `t` の記録は同じ値です。

いずれの場合も 1 の条件に反します。

3 で終点が変化しない理由は次のとおりです。セル `x` に戻る辺は 2 本ずつ対になります。対が 1 組の場合、残りの 2 辺 `a`, `b` はそれぞれ終点 `A`, `B` に直接接続しています。鏡と直進による接続は 3 通りあるが、どの接続でも辺 `a` から入った光は、直接または対の経路を 1 回通過した後に辺 `b` から出ます。したがって終点 `A` と終点 `B` は互いの終点のままです。対が 2 組の場合は、セル `x` に入るポートが存在しません。

4 で記録から終点が定まらないのは、同じ光がセル `x` を 2 回通過している場合です。どちらの辺から先に入るかによって光が吸収される面が異なるが、記録はどちらの場合も同じ値です。

経路を追跡する場合は 4 辺から外向きに追跡し、各辺の到達先が外周のポート、ブロックの面、セル `x` に戻る辺のいずれであるかを求めます。外周のポートに到達した辺が、そのポートから入射した光がセル `x` に入る辺です。以降は 2 と同様に新しいタイルを適用します。光がセル `x` に戻る回数は高々 1 回です。入った辺、出た辺、戻った辺を除いた残りの 1 辺の到達先は、外周のポートかブロックの面に限られるためです。

最後に、変更前後で終点が異なるポートだけを差分に含めます。差分のポートの順序は `ports_through` が返す順序と同じです。

### ブロックがある盤面で 2 個のポートだけが変化する例

`3 × 1` の盤面で上下のセルをブロック、中央のセルを直進とします。中央のセルの右側はポート `2`、左側はポート `6` です。

```cpp
MirrorGrid grid(3, 1);
grid.set(0, 0, MirrorTile::Block);
grid.set(2, 0, MirrorTile::Block);
PortDelta delta = grid.preview(1, 0, MirrorTile::Slash);
```

| 入射するポート | 変更前の終点 | 変更後の終点 |
|---|---|---|
| `2` (中央の右) | ポート `6` | セル `(2, 0)` の上の面 |
| `6` (中央の左) | ポート `2` | セル `(0, 0)` の下の面 |

中央のセルの記録は、上がセル `(0, 0)` の下の面、右がポート `2`、下がセル `(2, 0)` の上の面、左がポート `6` です。4 個の記録がすべて異なる終点であるため中央のセルに戻る辺はなく、`/` で再接続するだけで上の表の結果が求まります。`delta.count` は `2` です。

### タイルの追加

光が出る辺は `mirror_grid.cpp` の先頭にある表 `TILE_EXIT` で定義しています。問題固有のタイルを追加する場合は、次の 3 箇所に 1 つずつ要素を追加します。

| 場所 | 追加する要素 |
|---|---|
| `enum class MirrorTile` | 列挙値。末尾に追加する |
| `TILE_EXIT` | 上、右、下、左から入った光が出る辺。吸収する場合は `-1` |
| `TILE_CHARS` | 出力に使用する文字 |

例えば「上と左を接続し、右と下では光を吸収する鏡」の場合は `TILE_EXIT` に `{3, -1, -1, 0}` を追加します。吸収された光の終点は、タイルの種類に関係なく吸収したセルと面で表します。

追加できるタイルは、吸収しない辺について次の 2 つの条件を満たすものに限ります。これらの条件はコンパイル時に `static_assert` で確認しています。

- 辺 `a` から入った光が辺 `b` から出るなら、辺 `b` から入った光は辺 `a` から出ます。
- 入った辺からは出ません。

光を 2 本に分岐させるタイルと、入った辺へ光を折り返すタイルは対象外とします。経路の追跡と差分の計算がこの 2 つの条件を前提としているためです。先頭の `Empty` は直進のままにします。経路の追跡処理が番号 `0` のタイルを直進として扱っているためです。

### 共通ファイル

方向の定義 `GridDirection`, `opposite` とアサーション用マクロ `TITAN_GRID_ASSERT` は、グリッド共通の `grid_common.cpp` の定義を使用します。`MirrorGrid` だけを使用する提出コードに展開されるファイルは `grid_common.cpp` と `mirror_grid.cpp` の 2 個です。共通ファイルの内容は[グリッドの共通部品](grid_common.md)に記載しています。

### メモリ使用量

- タイル: `(H + 2)(W + 2)` バイト
- 終点の記録: 整数 `4(H + 2)(W + 2)` 個
- ポート番号の表: 整数 `(H + 2)(W + 2)` 個

`set`, `ports_through`, `preview` の作業領域と戻り値は固定長であり、動的なメモリ確保を行いません。

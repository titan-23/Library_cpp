# 貪欲法の派生と評価関数の設計

AHC などのヒューリスティック問題で用いる貪欲法の派生の分類と、貪欲法で使用する評価関数の設計原則を整理します。作成者自身が見直す場合と、AI に参照ドキュメントとして渡す場合に使用します。

過去改変貪欲については別のドキュメント `past_modification_greedy_guide.md` を参照してください。

---

## 第 1 部：貪欲法の派生

### 1.1 貪欲法の基本構造

貪欲法は解を逐次的に構築する手続きです。各ステップ t では次の処理を行います。

1. 現在の状態 `s_t` から到達可能な候補 `{c_1, c_2, ...}` を列挙します。
2. 評価関数 `f` で各候補のスコアを計算します。
3. 最良の候補を 1 つ選んで確定します。
4. 状態を `s_t → s_{t+1}` と遷移させます。

派生は次の 3 つの軸の違いによって生じます。

- **何を評価するか**：現在の利得か、未来の見込みか、過去への影響か
- **過去と未来をどこまで考慮するか**：現在だけか、k ステップ先までか、最後までシミュレーションするか
- **過去をどう扱うか**：変更しないか、編集するか、後悔として評価するか

### 1.2 思考の型：本質的な貪欲法を設計するための視点

貪欲法の質は評価関数 `f(現状態, 候補) → スコア` の設計によって定まります。`f` を設計するときは、次の思考の型のうち 1 つまたは複数から発想します。

#### 型 1：最終目的からの逆算

最終的に何が成立すれば目標を達成したことになるかを起点にして、現在の各候補を「目標にどれだけ近づくか」で評価します。A* のヒューリスティック関数と同じ発想です。

- 起点となる問い：「この問題で目標を達成した状態とは、何が成立した状態か？」「目標の達成に必要な要素は、現在の状態にどれだけそろっているか？」

#### 型 2：希少性に注目する

「今しか選択できない」もの、「今選ぶのが最もコストが小さい」ものを優先します。時間とともにリソースが失われる構造を見つけます。この型は後悔ベース貪欲の中心となる考え方です。

- 起点となる問い：「現在の選択肢のうち、時間とともに失われるものは何か？」「将来コストが増加するものは何か？」

#### 型 3：自由度と制約に注目する

最も自由度の低い部分から先に決定します。ある部分を決定すると他の部分の自由度が変化する場合は、影響が大きい順に確定します。

- 起点となる問い：「現在、最も自由度が低いのは何か？」「それを先に決定すると、後の選択がどう容易になるか？」

#### 型 4：ボトルネックから設計する

最終スコアを支配するボトルネックを特定し、そこから設計します。全体を平均的に改善するのではなく、ボトルネックの改善に集中します。

- 起点となる問い：「最終スコアを悪化させる最大の要因は何か？」「それを小さくする操作は何か？」

#### 型 5：可逆性で順序を決定する

取り消しにくい決定は先に、慎重に行います。取り消しやすい決定は早めに済ませます。

- 起点となる問い：「この決定は後から取り消すことができるか？」「できないなら、本当に今決定してよいか？」

#### 型 6：対称性と等価性による選択の集約

結果が同じになる選択を 1 つにまとめます。状態空間を縮小し、計算リソースを節約します。

- 起点となる問い：「この選択肢の違いは結果に影響するか？」「影響しないなら、どれを選んでもよい」

#### 型 7：単調性の利用

単調に増減する量を見つけ、その量で順序を付けます。どの順序で処理するかを意識的に設計します。

- 起点となる問い：「2 つの要素を入れ替えても解は同じか、どちらかが必ず良いか？」「単調に処理できる順序は存在するか？」

#### 型 8：すべて入れた理想解からの削減

制約を考慮しない理想解を作成し、そこから制約を満たす解に修正します。上界から解を構築する考え方です。

- 起点となる問い：「制約がなければ最良解は何か？」「制約によって理想解のどこが成り立たなくなるか？」

#### 型 9：交換論法の利用

2 つの要素を交換しても損をしない条件、または交換すると必ず得をする条件を見つけ、その条件に従って要素の順序を決定します。交換論法 (exchange argument) の発想です。

- 起点となる問い：「最適解の中で隣り合う 2 つの要素を交換するとどうなるか？」「常に得をする条件はあるか？」

#### 型 10：最後の 1 ステップから考える

終了時の状態から逆順に解を組み立てます。終了時の状態の構造を把握しやすい問題で有効です。

- 起点となる問い：「終了直前の状態は何か？」「その状態に至るには、1 ステップ前にどの状態である必要があるか？」

### 1.3 行き詰まりやすい原因と対処法

本質的な貪欲法を思い付かない典型的な原因とその対処法は次のとおりです。

- **短期利得しか考慮しない**：型 1 の視点が欠けている → 評価関数に必ず「将来予測項」を加える
- **処理順序を疑わない**：型 3, 7 の視点が欠けている → 「どの順で処理すべきか」を必ず問い、順序自体も決定変数として扱う
- **選択の影響範囲を把握していない**：型 3 の視点が欠けている → 1 つ決定した後に、他の候補のスコアがどう変化するかを意識する
- **希少性を意識しない**：型 2 の視点が欠けている → 候補ごとに「今選ばないとどうなるか」を問う
- **ボトルネックを考慮しない**：型 4 の視点が欠けている → 「現在の解の質を左右している部分はどこか」を毎回特定する

### 1.4 新しい問題を検討する手順

新しい問題に取り組むときは、次の順に検討します。

1. **目標の達成条件の特定** (型 1)：何が成立すれば最高スコアになるか
2. **ボトルネックの特定** (型 4)：何が最終スコアを左右するか
3. **処理順序の検討** (型 3, 5, 7)：要素をどの順で扱うべきか
4. **評価関数の設計**：短期利得 + 将来予測 + 制約ペナルティ
5. **希少性の確認** (型 2)：「今しか選択できない」候補はあるか
6. **交換論法による確認** (型 9)：順序の最適性を説明できるか

この手順を意識すると、短期利得だけを考慮する貪欲法から脱却しやすくなります。

### 1.5 派生一覧

#### A. 通常貪欲 (Pure Greedy)

各ステップで現在の利得が最大の候補を選びます。過去の選択は変更せず、未来も考慮しません。

- 長所：実装が単純で、実行が高速
- 短所：局所最適に陥りやすい
- 用途：問題の構造が単純で、現在良い選択が将来も良い結果につながる場合

#### B. ランダム貪欲 (Randomized Greedy)

候補をスコア順にソートし、上位 k 個からランダムに選ぶか、確率的に選びます。

- 多始点の探索と組み合わせて、多様な初期解を作成する用途に有効です。
- 焼きなましの初期解の生成によく使用されます。

#### C. 後悔ベース貪欲 (Regret-based Greedy)

候補ごとに「今これを選ばなかった場合に、後でどれだけ損をするか」を計算し、後悔の大きい候補から優先的に選びます。

- 「今しか選択できないもの」を選び損ねないための発想です。
- 挿入問題や配車計画 (VRP) などでよく知られています。
- 評価関数に「best - second_best」のような差を組み込む方法が典型的です。

#### D. Look-ahead 貪欲

候補ごとに k ステップ先までシミュレーションし、k ステップ後のスコアで評価します。

- k=1 の場合は通常貪欲と同じです。k を増やすほど計算量と精度が上がります。
- 計算量の爆発を防ぐため、k ステップ先の評価は近似でもかまいません。
- 後述の MCTS / Roll-out 貪欲と連続的につながる手法です。

#### E. Roll-out 貪欲 (Roll-out / Simulation Greedy)

候補ごとに、その先を最後までランダムな選択または簡易な貪欲法でプレイアウトし、最終スコアで評価します。

- MCTS を簡略化した手法です。
- 確率的な問題やゲーム木探索の問題に有効です。
- プレイアウトのコストが高いため、候補数や反復回数とのトレードオフになります。

#### F. 過去改変貪欲 (Past-Modification Greedy)

現在の操作を実行するため、過去の操作列に対して挿入、置換、削除を行います。詳細は別のドキュメントを参照してください。

- 過去の操作列を編集する点で、他の派生と本質的に異なります。
- 操作の可換性が高い問題で特に強力です。

#### G. 入れ替えながら貪欲 (Swap-while-greedy)

構築の途中で、既に決定した要素同士の入れ替えを許します。過去改変貪欲の「置換型」を局所的な入れ替えに限定した手法です。

- 解の完成後に行う局所探索を、構築の途中で行う考え方です。
- 過去改変貪欲ほど大きな編集はしませんが、小さな修正で改善が得られます。

#### H. 制約伝播ベース貪欲 (Constraint Propagation)

最も自由度の低い要素、または最も決定的な選択から先に確定します。1 つ確定するごとに他の要素の選択肢を絞り込み、絞り込んだ結果を次の選択に利用します。

- ナンプレ、N-Queens、グラフ彩色などの配置問題やパズルで有効です。
- 「定まりやすい部分から決定する」という、通常の貪欲法とは逆の発想です。

#### I. 多段階構築貪欲 (Multi-stage Greedy)

問題を時間、空間、抽象度によって段階に分け、段階ごとに貪欲法を適用します。

- 先に全体の骨組みを決定し、後で細部を決定します。
- 粗いグリッドで大まかに決定し、細かいグリッドで精緻化します。
- 多くの場合、段階ごとに異なる評価関数を使用します。

#### J. 挿入ヒューリスティック (Insertion Heuristic)

未確定の要素を 1 つずつ、現在の解の最適な位置に挿入します。

- Nearest Insertion、Farthest Insertion、Cheapest Insertion などの種類があります。
- TSP やスケジューリングで古典的に使用される手法です。
- 過去の決定の内容は変更しません。この点が過去改変貪欲との違いです。

#### K. 後悔挿入 (Regret Insertion)

挿入ヒューリスティックと後悔ベース貪欲を組み合わせた手法です。最良の挿入位置と次善の挿入位置のコストの差が大きい要素から優先して挿入します。

- VRP などで実用上有効です。
- 今、挿入を後回しにすると損をする要素を優先する発想です。

#### L. 逐次破壊再構築 (Construct-Destroy-Reconstruct)

通常貪欲で初期解を作成し、一部を破壊して同じ貪欲法で再構築します。

- LNS (Large Neighborhood Search) と関連する手法です。
- 多始点の探索に近い動作になります。

### 1.6 派生の選び方

問題に取り組むときは、次の順に確認して派生を選択します。

1. **過去の操作の編集に意味があるか** → 意味があれば過去改変貪欲 (F)
2. **未来の見込みによって現在の決定が変化するか**
   - 「今しか選択できない」候補がある → 後悔ベース (C, K)
   - k ステップ先まで評価すれば判断できる → Look-ahead (D)
   - プレイアウトで評価できる確率的な問題 → Roll-out (E)
3. **問題に明確な構造があるか**
   - 配置問題やパズルで、自由度に偏りがある → 制約伝播 (H)
   - 階層的に分解できる → 多段階構築 (I)
   - 順序の最適化が中心 → 挿入ヒューリスティック (J, K)
4. **多様な初期解が必要か** → ランダム貪欲 (B)
5. **構築済みの解の修正を許すか** → 入れ替え型 (G)、破壊再構築 (L)

複数の派生を組み合わせることが一般的です。たとえば「ランダム貪欲 + Look-ahead + 過去改変」のような組み合わせも自然な選択です。

### 1.7 派生を横断する 2 つの軸

| 軸 | 値 | 該当する派生 |
|------|------|------|
| 過去の扱い | 変更しない | A, B, D, E, H, I, J |
| 過去の扱い | 編集する | F, G |
| 過去の扱い | 後悔として評価する | C, K |
| 未来の扱い | 考慮しない | A, B, F, G, J |
| 未来の扱い | 後悔 (最善と次善の差) | C, K |
| 未来の扱い | k ステップ先まで | D |
| 未来の扱い | 最後まで | E |

新しい派生を考える場合は、この 2 つの軸の組み合わせのうち該当する派生がないものを探すと、新規性のある派生を見つけやすくなります。

## 第 2 部：評価関数の設計原則

評価関数 `f(s)` は、貪欲法と焼きなましのどちらでも中心となる要素です。問題が同じでも、評価関数の設計によってスコアが大きく変化します。

### 2.1 評価関数の役割

評価関数が担う役割は次の 3 つです。

1. **方向性の提示**：探索を最終目標に向かわせる
2. **タイブレーク**：同程度に良い候補の間で優劣を付ける
3. **整合性の維持**：制約違反を防ぐ、または許容範囲に抑える

### 2.2 設計の基本原則

#### 原則 1：最終スコアに沿わせる

最終スコアの関数をそのまま評価関数にできる場合は、それが最も直接的な方法です。ただし、最終スコアを評価関数に使用しにくい場合は次のように対処します。

- 最終スコアをすべての処理が終わった後にしか計算できない場合は、途中で計算できる代理指標を作成します。
- 最終スコアが離散的すぎる場合は、滑らかな代理指標を作成します。

#### 原則 2：将来予測項を加える

現在の状態の良さだけでなく、今後得られるスコアの推定値を加えます。

- 残りの目的地までの最短距離の下界
- 残りの資源で達成可能なスコアの上限
- 残り時間で実行可能な操作数

この項の有無によって、貪欲法の質が大きく変化します。

#### 原則 3：ペナルティ項で制約を表現する

制約違反に対して大きな負の値を与えます。

- ハードペナルティ：違反した候補が決して選ばれないほど大きな値
- ソフトペナルティ：違反の度合いに応じて連続的に変化する負の値
- 整合性の緩和：完全な実行可能性を求めず、制約違反をペナルティで緩く扱う

焼きなましでは、ペナルティの重みを徐々に上げる戦略 (progressive penalization) も有効です。

#### 原則 4：複数指標を辞書式で扱う

主目的と副目的がある場合は、次の扱い方があります。

- **線形和**：`α × main + β × sub` を使用する方法で、最も単純だが重みの調整が必要
- **辞書式**：主目的の差が閾値以上なら主目的で比較し、閾値未満なら副目的で比較する
- **多目的のまま扱う**：Pareto front を保持し、後段で選択する

通常は線形和で十分です。スコアの単位が大きく異なる場合や、副目的をタイブレークだけに使用する場合は辞書式が適しています。

#### 原則 5：差分計算可能な形にする

評価関数の値を毎回最初から計算すると遅くなります。次のように、差分計算できる形に設計します。

- 状態の変化の影響範囲が局所的になるように、評価項を分解します。
- 各評価項を独立に保持し、変化した項だけを再計算します。
- 焼きなましでは差分計算が必須です。

#### 原則 6：滑らかさを確保する

評価値の段差が大きいと、貪欲法と焼きなましのどちらも探索の方向が定まりにくくなります。次の点に注意して設計します。

- 「あと一歩で達成」の状態と「達成済み」の状態の評価値の差を大きくしないようにします。
- 距離やコストが段階的に減少するように設計します。
- 成否を二値で評価するのではなく、進捗の度合いとして評価します。

#### 原則 7：時間スケールに応じて変更する

問題の時間軸が長い場合は、評価関数を時間とともに変更します。

- 序盤：探索範囲を広げ、多様性を重視する
- 終盤：探索範囲を絞り込み、最終スコアを重視する
- 焼きなましの温度スケジュールと同様の発想です。

### 2.3 設計パターン

#### パターン A：現在のスコア + 残りの見込み

```
f(s) = (現在のスコア) + (残りで得られるスコアの楽観的上限)
```

A* と同じ発想です。残りの見込みが楽観的な推定であれば、評価値は最終スコアの上界として機能します。

#### パターン B：主目的 + タイブレーク

```
f(s) = main(s) + ε × sub(s)
```

ε は十分小さい正の数です。`main` が同じ候補同士の比較では `sub` が影響します。

#### パターン C：制約緩和 + ペナルティ

```
f(s) = scoring(s) - λ × violation(s)
```

`violation` は制約違反の度合いです。`λ` を大きくするとハード制約、小さくするとソフト制約として扱うことになります。

#### パターン D：多項目の線形和

```
f(s) = w_1 × term_1(s) + w_2 × term_2(s) + ... + w_n × term_n(s)
```

各項は状態の異なる側面を評価します。重み `w_i` はパラメータチューニングで決定します。

#### パターン E：シミュレーションによる評価

```
f(s) = simulate(s).final_score
```

候補ごとにその先を仮想的に実行して評価します。Roll-out 貪欲や MCTS で使用するパターンです。

### 2.4 評価関数のデバッグとチューニング

#### 観点 1：評価値の分布を確認する

候補のスコアがすべて同じ場合や極端な値が混ざる場合は、評価関数が機能していない可能性があります。

- すべて同じ：タイブレーク項が不足している
- 極端な値が混ざる：項のスケールがそろっていない、またはペナルティが強すぎる

#### 観点 2：1 ステップごとの選択の妥当性

各ステップで選ばれた候補と、その候補が選ばれた理由をログに出力します。理由は各項のスコアの内訳で示します。意図しない選択が頻発する場合は、項の重みを見直します。

#### 観点 3：項を 1 つずつ外して効果を確認する

`w_i = 0` にして実行し、スコアが下がるかを確認します。外してもスコアが下がらない項は不要であり、外すとスコアが上がる項は逆効果です。

#### 観点 4：パラメータの感度

重みを 0.5x, 1x, 2x にしてそれぞれ実行し、スコアの変化を確認します。感度が極端に高いパラメータは慎重に調整し、感度が低いパラメータは固定してかまいません。

### 2.5 よくある落とし穴

- **最終スコアと評価関数の乖離**：途中の評価が良くても最終スコアが伸びません。代理指標と最終指標の関係を確認します。
- **ペナルティが強すぎる**：探索が制約の遵守に偏り、本来の最適化が進みません。
- **ペナルティが弱すぎる**：制約違反が解消されないまま探索が終了します。
- **重みの過剰チューニング**：特定のテストケースに過適合します。複数のケースで検証します。
- **計算コストの増大**：評価関数の計算に時間がかかりすぎて、反復回数を確保できません。差分計算で高速化します。
- **滑らかさの欠如**：評価値が段差状に変化し、貪欲法や焼きなましの探索が進みません。

## 第 3 部：貪欲法の派生と評価関数の組み合わせ

派生と評価関数は独立した軸ではなく、相互に影響します。代表的な組み合わせを次の表に示します。

| 派生 | 相性の良い評価関数の設計 |
|------|------|
| 通常貪欲 (A) | 現在の利得の最大化、単純な線形和 |
| 後悔ベース (C, K) | 最善と次善の差を組み込む |
| Look-ahead (D) | k ステップ先の状態を評価できる形 |
| Roll-out (E) | 最終スコアそのもの |
| 過去改変 (F) | 整合性ペナルティ + 改変コスト |
| 制約伝播 (H) | 自由度や残りの選択肢の数を項に含める |
| 多段階 (I) | 段階ごとに異なる評価関数 |

派生を変更すると、最適な評価関数も変化します。派生を決定してから評価関数を設計し、評価関数を変更したら派生も再検討するという手順を繰り返すのが現実的です。

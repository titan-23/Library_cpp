# Bitset

`titan23::Bitset<N, Backend>` は、ビット数 `N` をコンパイル時に指定する固定長の bitset です。C++20 以上で使用できます。複数の集合を扱う非破壊的な操作は自由関数として提供し、更新操作はメソッドとして提供します。通常の演算子やメソッドも引き続き使用できます。

```cpp
#include <cassert>
#include "titan_cpplib/ds/bitset.cpp"

int main() {
    using Bits = titan23::Bitset<4097>;
    Bits a, b;                     // 全ビットが 0
    a.set(0).set(64);
    a[5] = true;
    b.set(64).set(100);

    assert(a.count() == 3);
    assert(titan23::count_and(a, b) == 1); // (a & b).count()
    assert(a.intersects(b));       // 両方で 1 のビットがある

    auto common = a & b;
    a.or_shift_left(7);            // 更新前の a に対する a |= a << 7
    assert(a.test(7) && a.test(12) && a.test(71));
    common >>= 64;
    assert(common.test(0));
}
```

## 内部表現とデータの入出力

内部表現は `std::array<std::uint64_t, word_count>` で、動的確保は行いません。`word_count` は `N / 64 + (N % 64 != 0)` です。ビット `i` はワード `i / 64` の下位から `i % 64` 番目に対応し、位置 `0` が最下位ビットです。末尾のワードのうち位置が `N` 以上の余剰ビットは常に 0 に維持します。

| API | 内容 |
|---|---|
| `Bitset()` | 全ビットが 0 の状態で構築する |
| `explicit Bitset(std::uint64_t value)` | 下位 64 ビットに `value` を設定する。`N < 64` の場合は切り詰める |
| `Bitset::from_words(words)` | `storage_type` から構築し、余剰ビットを 0 にする |
| `words()` | 内部配列への `const storage_type&` を返す |
| `size()` / `len()` | ビット数 `N` を返す |
| `word_type` / `storage_type` | `std::uint64_t` / 内部配列の型 |
| `word_count` | 内部配列の要素数 |

```cpp
using Bits = titan23::Bitset<65>;
Bits::storage_type words{0x5, ~Bits::word_type{0}};
auto bits = Bits::from_words(words);
// 位置 0、2、64 だけが 1 になる
assert(bits.count() == 3);
assert(bits.words()[1] == 1);
```

## 操作

集合どうしの演算には `N` と `Backend` が同じ型を使用します。更新操作は自身への参照を返すため、`a.set(1).set(2)` のように連続して呼び出すことができます。

| API | 内容 |
|---|---|
| `test(i)` / `access(i)` | 位置 `i` の値を `bool` で返す |
| `a[i]` | 読み取りと代入。非 const 版は参照プロキシを返し、`a[i].flip()` も使用できる |
| `set(i, value = true)` / `reset(i)` / `flip(i)` | 1 つのビットを設定、消去、反転する |
| `set()` / `reset()` / `flip()` | 全ビットを設定、消去、反転する |
| `count()` | 値が 1 のビットの個数を返す |
| `any()` / `none()` / `all()` | 1 が存在するか、すべて 0 か、すべて 1 かを返す |
| `a & b` / `a \| b` / `a ^ b` / `~a` | AND、OR、XOR、全ビットの反転 |
| `a &= b` / `a \|= b` / `a ^= b` | 集合演算で `a` を更新する |
| `a << k` / `a >> k` | 位置の大きい側、小さい側へシフトした値を返す |
| `a <<= k` / `a >>= k` | シフトで `a` を更新する |
| `a == b` / `a != b` | 等値比較 |
| `count_and(b, c, ...)` | 自身を含む共通部分の個数を返す。互換性のためのメソッドで、`titan23::count_and(a, b, c, ...)` と同じ値を返す |
| `intersects(b)` | `(a & b).any()` を計算する。共通のビットが見つかった時点で終了する |
| `or_shift_left(k)` | 更新前の値に対する `a \|= a << k` を、一時的な bitset を作成せずに計算する |
| `or_shift_right(k)` | 更新前の値に対する `a \|= a >> k` を、一時的な bitset を作成せずに計算する |

1 つのビットの操作とサイズの取得は `O(1)` です。全体の走査、集合演算、シフトは最悪 `O(word_count)` です。

シフト OR は部分和 DP などに使用できます。次の例では各重みを 1 回ずつ使用し、和が 10000 以下の状態を保持します。

```cpp
titan23::Bitset<10001> reachable;
reachable.set(0);
for (std::size_t weight : {3, 7, 11}) {
    reachable.or_shift_left(weight);
}
assert(reachable.test(10));
```

境界の扱いは次のとおりです。

- `N == 0` では `count() == 0`、`any() == false`、`none() == true`、`all() == true` です。
- シフトで範囲外に出たビットは破棄し、空いた位置を 0 にします。`k >= N` の場合、通常のシフトの結果は全ビットが 0 になり、シフト OR の結果は元の値のままです。`k == 0` の場合は値が変化しません。
- 位置を受け取る API は `0 <= i < N` を前提とします。範囲の確認には `assert` を使用するため、`NDEBUG` を定義すると確認は無効になります。範囲外アクセスで例外を送出する `std::bitset` の API との互換性はありません。

## 複数入力の自由関数

AND、OR、XOR は、自由関数で複数の集合をまとめて処理することができます。自由関数にしているのは、複数の集合を対等な引数として渡すためです。引数は 2 個以上で、すべて同じ `Bitset<N, Backend>` 型を渡します。引数の個数は可変長引数テンプレートによってコンパイル時に定まります。入力は `const` 参照で受け取ります。

| 求める結果 | AND (共通部分) | OR (和集合) | XOR (奇数個の入力で 1 の位置) |
|---|---|---|---|
| 所有する `Bitset` | `bit_and(a,b,c,...)` | `bit_or(a,b,c,...)` | `bit_xor(a,b,c,...)` |
| 1 の個数 | `count_and(a,b,c,...)` | `count_or(a,b,c,...)` | `count_xor(a,b,c,...)` |
| 1 が存在するか | `any_and(a,b,c,...)` | `any_or(a,b,c,...)` | `any_xor(a,b,c,...)` |
| 全ビットが 1 か | `all_and(a,b,c,...)` | `all_or(a,b,c,...)` | `all_xor(a,b,c,...)` |

すべて `titan23` 名前空間にあります。`bit_and` などは標準ライブラリの関数オブジェクトと名前が同じで、`any` は `std::any` と名前が同じです。そのため、呼び出し例では `titan23::` を明記しています。

```cpp
using Bits = titan23::Bitset<4097>;
Bits a, b, c, d;
a.set(0).set(64);
b.set(0).set(100);
c.set(0).set(200);
d.set(0);

auto intersection = titan23::bit_and(a, b, c); // 入力とは独立した Bitset を返す
assert(intersection.count() == 1);
assert(titan23::count_or(a, b, c, d) == 4);
assert(titan23::count_xor(a, b, c, d) == 3);
assert(titan23::any_and(a, b, c));
assert(titan23::all_or(a, ~a, d));
assert(!titan23::any_xor(a, a));
assert(a.count_and(b, c) == titan23::count_and(a, b, c));
```

`bit_*` は結果を 1 つだけ構築して返します。入力を後から変更しても結果は変化しません。`count_*`, `any_*`, `all_*` は各ワードで全入力を合成して直接集計するため、一時的な bitset を作成しません。`any_*` は 1 を見つけた時点で、`all_*` は 0 を見つけた時点で走査を終了します。`N == 0` の場合は個数が 0、`any_* == false`、`all_* == true` です。

引数が `K` 個、ワード数が `W` のとき、計算量は最悪 `O(KW)` です。AND、OR、XOR の選択と入力の個数はコンパイル時に固定するため、内側のループでは演算の種類を判定しません。`count_*` は単体の個数計算と同じ基準で処理を選択し、SIMD 版でも全入力を合成してから個数を求めます。`bit_*`, `any_*`, `all_*` も Backend に応じて SIMD で複数のワードをまとめて処理します。

単体の集計にも `titan23::count(a)`、`titan23::any(a)`、`titan23::all(a)`、`titan23::none(a)` を用意しています。これらは `a.count()`、`a.any()`、`a.all()`、`a.none()` と同じ処理です。

`count_or(a,b,c)` と `count(bit_or(a,b,c))` の値は同じですが、後者は所有する結果の bitset を生成します。一時的な bitset を生成せずに集計する場合は `count_*`, `any_*`, `all_*` を使用します。混在する式を自動的に遅延評価する API ではありません。

## Backend と SIMD

```cpp
using AutoBits = titan23::Bitset<4096>;
using WordBits = titan23::Bitset<4096, titan23::BitsetBackend::Scalar>;
// AVX2 を有効にしたコンパイルターゲットで使用する
using AvxBits = titan23::Bitset<4096, titan23::BitsetBackend::Avx2>;
```

| Backend | 処理の選択 |
|---|---|
| `Auto` | コンパイルターゲットで有効な命令と処理サイズに応じて選択する。既定の Backend である |
| `Scalar` | 通常の 64 bit ワードのループを使用する。コンパイラによる自動ベクトル化は許容する |
| `Avx2` | 下記の SIMD 処理を常に AVX2 で行い、端数はワード単位で処理する。`__AVX2__` が定義されていないターゲットではコンパイルエラーになる |

SIMD 処理には `titan_cpplib/others/simd_int.cpp` の `SimdBits` を使用します。`SimdBits` はコンパイル時に AVX2 (4 ワード)、SSE2 (2 ワード)、逐次処理の優先順で命令を選択します。AVX-512 のターゲットでも AVX2 の 256 bit 命令を使用します。

`Auto` と `Avx2` では次の処理を SIMD で複数ワードずつ行います。

- 集合演算：`&=`, `|=`, `^=`, `&`, `|`, `^`, `bit_*`, `flip()`
- 判定：`any()`, `none()`, `all()`, `intersects()`, `any_*`, `all_*`
- 個数：`count()`, `count_*`
- シフト：`<<=`, `>>=`, `or_shift_left`, `or_shift_right`

`Auto` の個数計算とシフトでは、SIMD を使用するサイズに次の下限があります。集合演算と判定には下限はありません。

- `count`, `count_*`：AVX2 では `word_count >= 16` の場合に使用します。下記のローカル計測で、小さいサイズでは AVX2 のほうが遅くなる場合があったためです。SSE2 だけのターゲットでは、POPCNT 命令がない場合は 2 ワード以上で使用し、POPCNT 命令がある場合は使用しません。POPCNT 命令がない場合は `std::popcount` が関数呼び出しになり、POPCNT 命令がある場合は SSE2 のビット演算より 1 ワードずつ個数を求めるほうが高速であるためです。`__AVX512VPOPCNTDQ__` が定義されている場合は、通常のループからネイティブのベクトル popcount への最適化をコンパイラに任せます。
- 通常のシフトとシフト OR：シフト対象のワード数 `word_count - k / 64` が 16 以上の場合に SIMD を使用します。`k == 0` と `k >= N` の場合は先に処理します。

AVX2 の個数計算では 4 bit ごとのテーブル参照と加算を使用します。SSE2 では 2 bit、4 bit、8 bit ごとの和を順に計算するビット演算で個数を求めます。どちらも 8 本分をバイト単位で加算してから 64 bit にまとめます。シフトは、64 bit の要素ごとのシフトと隣のワードからの繰り上がりを組み合わせて計算します。シフト OR では入力を読み込んでから結果を格納し、左シフトは上位側から、右シフトは下位側から処理します。

値を返す `&`, `|`, `^` と `bit_*` は、結果の内部配列を 0 で初期化せずに構築し、合成した結果を直接格納します。

`Auto` は実行時に CPUID による判定を行いません。`-march=x86-64-v3` や `-mavx2` でビルドしたバイナリは、対応する CPU で実行します。`-march=native` の場合、生成されるコードはコンパイルしたマシンの CPU に依存します。

## ベンチマーク

同じバイナリ内で `std::bitset`、`Scalar`、`Avx2`、`Auto` を比較します。`Avx2` の行は AVX2 が有効なビルドでのみ出力します。各バイナリは、ほかの負荷の高い処理を停止した状態で個別に実行します。

```sh
g++ -std=c++20 -O2 -I. test/ds/benchmark/bitset_benchmark.cpp -o /tmp/bitset_bench
/tmp/bitset_bench --ms 10 --reps 5 > /tmp/bitset_bench.csv

g++ -std=c++20 -O2 -march=x86-64-v3 -I. test/ds/benchmark/bitset_benchmark.cpp -o /tmp/bitset_bench_avx2
/tmp/bitset_bench_avx2 --ms 10 --reps 5 > /tmp/bitset_bench_avx2.csv

g++ -std=c++20 -O2 -march=native -I. test/ds/benchmark/bitset_benchmark.cpp -o /tmp/bitset_bench_native
/tmp/bitset_bench_native --ms 10 --reps 5 > /tmp/bitset_bench_native.csv
```

計測対象は次のとおりです。`--suite basic` を指定すると、対象を単体の `count`、`and_value`、`or_value`、`and_assign`、`or_assign` の 5 種類に限定することができます。

| CSV の演算名 | 計測内容 |
|---|---|
| `count` / `count_and` | 個数の計算。戻り値の checksum への加算も計測に含む |
| `and_value` / `or_value` | `out = a & b` / `out = a \| b`。結果の生成と出力先への格納を含む |
| `and_copy` / `or_copy` | `out = a` の後に `out &= b` / `out \|= b` を行う。入力のコピーを含む |
| `and_assign` / `or_assign` | `out &= b` / `out \|= b`。`out = a` の初期化は各サンプルの計測前に行う |
| `or_shift_left_copy` | 入力をコピーしてからシフト OR を行う。シフト OR だけを単独で計測するものではない |

シフト量は 0、1、17、63、64、65、`N / 2 + 7`、`N` の場合を比較します。

入力は固定したシードから複数生成し、密度が約 1/2、約 1/8、1 ワードに 1 bit のものを混ぜています。`*_value` と `*_copy` は毎回元の入力から計算します。`*_assign` は固定した右辺で同じ出力を繰り返し更新するため、初回の更新以降、出力は `a & b` または `a | b` の値を維持します。これは主にキャッシュ内での更新速度の計測で、毎回異なる右辺で更新する場合の計測ではありません。乱数生成、構築、結果の検証は計測の対象外とし、計測した処理の結果は `std::bitset` の結果と照合します。

| オプション | 内容 |
|---|---|
| `--bits N` | 128、256、512、1024、2048、4096、4097、65536 から指定する。省略時はすべてを計測する |
| `--suite basic\|all` | 基本の 5 演算だけ、または全演算を計測する。既定値は `all` |
| `--backends std-auto\|all` | 標準と Auto だけ、または全 Backend を計測する。既定値は `all` |
| `--inputs K` | 入力の組数。既定値は 64 |
| `--ms T` | 1 サンプルの目標計測時間をミリ秒で指定する。既定値は 10 |
| `--reps R` | サンプル数。既定値は 5 |
| `--iterations ROUNDS` | 全入力を走査する回数を固定する。指定時は `--ms` による調整を行わない |

CSV の `median_ns` は、1 つの入力に対する 1 操作あたりの時間の中央値です。既定の入力数では主にキャッシュ内の処理を計測します。`--inputs` を増やすと、より大きい作業領域を使用した計測ができます。

結果は CPU、コンパイラとそのバージョン、最適化とターゲットの指定、入力サイズ、シフト量、キャッシュの状態に依存します。AtCoder の実機では計測していません。

## SimdBits への置き換えの計測 (2026-11-13)

AMD Ryzen Threadripper 3990X (Zen 2)、GCC 12.3.0 で、CPU 4 に固定して計測しました。フラグは `-std=c++20 -O2` を基本とし、既定ビルドでは `-march` を指定せず、native では `-march=native` を加えています。表の値は、入力 64 組、`--ms 10 --reps 3` で 3 回ずつ実行した結果の中央値 (ns) です。変更前は HEAD (`9634bd5`) の `Auto`、変更後は `Auto` です。チェックサムは全行で一致しました。

変更点は次のとおりです。

- 直接記述していた AVX2 の命令を `SimdBits` に置き換え、AVX2 がない既定ビルドでも SSE2 で処理するようにしました。
- 集合演算と判定も SIMD で処理するようにしました。GCC 12 では `a &= b` のループが自動ベクトル化されず、1 ワードずつ処理されていました。
- 値を返す演算は、左辺を値渡しでコピーして更新してから返す実装で、結果を返すときにもう一度コピーしていました。これを、結果を初期化せずに構築して直接格納する実装に変更しました。前節までの記録で原因を特定していなかった、値を返す AND と OR が標準より遅い件は、変更前のこの実装が原因です。

- 既定ビルドでは POPCNT 命令がなく `std::popcount` が関数呼び出しになるため、`count` が約 4 倍高速になりました。
- native の `count`, `count_*`, シフトは、AVX2 の実装も下限も変更前と同じです。このベンチマークでは ±20% ほどの差が出ましたが、`count` と `count_and` だけを計測する小さいプログラムでは、`count` は変更前と同じ時間で、`count_and` は 4097 bit で 12% 遅く、65536 bit で 10% 速い結果でした。同じバイナリ内の `std::bitset` の時間も同程度変動する場合があり、コード配置の影響と考えられます。`-march=x86-64-v2` (SSE4.2 と POPCNT) の `count` も同様で、単独で計測すると変更前と同じ時間でした。
- native の 512 bit の `c = a; c &= b` は遅くなりました。GCC 12 は汎用や Zen 向けのチューニングで `c = a` のコピーを 16 byte 単位の書き込みにし、直後の AVX2 による 32 byte 単位の読み込みでストアからロードへの転送が失敗するためです。標準も同じ 11.1 ns です。Ice Lake 向けのチューニングでは 32 byte 単位でコピーするため、この現象は発生しません。コピーを挟まない `a &= b` と `a & b` は同じサイズで 3〜6 倍高速になるため、下限は設けていません。

## ローカル計測 (2026-09-13)

以下の速度表は、複数入力の自由関数を追加する前の実装の計測記録です。追加後は差分テストと生成コードを検証しましたが、複数入力の速度はまだ計測していません。

AMD Ryzen AI 9 HX 370、GCC 15.2.0 で、CPU 0 に固定して計測しました。共通のフラグは `-std=gnu++23 -O2 -ftrivial-auto-var-init=zero -Wall -Wextra -Wpedantic -I.`、入力は 64 組、オプションは `--ms 10 --reps 5` です。各結果は 1 操作の中央値 (ns) です。倍率は `std / Auto` で、大きいほど `Bitset` が高速です。

`-march=x86-64-v3` は AVX2 までの命令を対象にしたビルド、`-march=native` はこの CPU の AVX-512 VPOPCNTDQ も有効にしたビルドです。両方とも同じ CPU 上で実行しており、異なるジャッジの CPU での速度を再現したものではありません。

| ターゲット | bit 数 | 演算 | std | Auto | 倍率 |
|---|---:|---|---:|---:|---:|
| x86-64-v3 | 4096 | count | 35.55 | 17.81 | 2.00 |
| x86-64-v3 | 4096 | count_and | 48.85 | 21.30 | 2.29 |
| x86-64-v3 | 4096 | or_shift_left_copy(65) | 87.57 | 34.99 | 2.50 |
| x86-64-v3 | 65536 | count_and | 981.68 | 329.79 | 2.98 |
| x86-64-v3 | 65536 | or_shift_left_copy(65) | 1455.55 | 634.81 | 2.29 |
| native | 4096 | count | 8.08 | 9.71 | 0.83 |
| native | 4096 | count_and | 28.88 | 16.23 | 1.78 |
| native | 4096 | or_shift_left_copy(65) | 100.41 | 40.02 | 2.51 |
| native | 65536 | count_and | 450.06 | 334.44 | 1.35 |
| native | 65536 | or_shift_left_copy(65) | 1507.18 | 644.65 | 2.34 |

融合演算では改善が見られますが、単体の `count()` や AND、非常に小さい bitset では標準実装のほうが速い場合もあります。特にネイティブのベクトル popcount を使用できる場合は、標準の `count()` も高速です。

AVX2 ターゲットの 512 bit では、AVX2 を強制した `count()` が 7.76 ns、通常のループが 5.21 ns でした。1024 bit ではそれぞれ 8.49 ns と 9.41 ns、2048 bit では 10.23 ns と 18.71 ns で、16 ワードの下限を維持しました。左シフト OR でも 512 bit では AVX2 を強制すると通常のループより遅い場合があり、同じ下限を使用しています。

計測に使用したコマンドの例は次のとおりです。

```sh
g++ -std=gnu++23 -O2 -ftrivial-auto-var-init=zero -Wall -Wextra -Wpedantic -march=x86-64-v3 -I. test/ds/benchmark/bitset_benchmark.cpp -o /tmp/bitset_benchmark_avx2
taskset -c 0 /tmp/bitset_benchmark_avx2 --ms 10 --reps 5 > /tmp/bitset_avx2.csv

g++ -std=gnu++23 -O2 -ftrivial-auto-var-init=zero -Wall -Wextra -Wpedantic -march=native -I. test/ds/benchmark/bitset_benchmark.cpp -o /tmp/bitset_benchmark_native
taskset -c 0 /tmp/bitset_benchmark_native --ms 10 --reps 5 > /tmp/bitset_native.csv
```

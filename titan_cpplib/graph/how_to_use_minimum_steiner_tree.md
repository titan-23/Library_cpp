# Steiner 木の近似解

`minimum_steiner_tree.cpp` は、非負重みの無向グラフで、指定した端子をすべて含む木を近似的に求めます。整数重みで端子が 2 個または 3 個の場合は既定の `solve_best` で厳密解を得られます。連結グラフで全頂点が端子の場合はどの方式も最小全域木を返します。

頂点数 100 前後の同じグラフで繰り返し解く場合は、まず既存 API の `build_prim` を使用します。初回の呼び出しから処理時間を抑えたい場合は `incremental_prim`、別の構成法も試したい場合は `mehlhorn` を選択できます。[性能比較](minimum_steiner_tree_benchmark_2026-11-12.md)では、前計算と繰り返し呼び出しを分けて計測しています。

## 基本の使用方法

```cpp
#include <vector>
#include <utility>
#include "titan_cpplib/graph/minimum_steiner_tree.cpp"

using Weight = long long;
std::vector<std::vector<std::pair<int, Weight>>> graph(4);
auto add_edge = [&](int u, int v, Weight w) {
    graph[u].emplace_back(v, w);
    graph[v].emplace_back(u, w);
};
add_edge(0, 1, 2);
add_edge(1, 2, 3);
add_edge(1, 3, 1);

titan23::MinimumSteinerTree<Weight> solver(graph, 1LL << 60);
std::vector<int> terminals = {0, 2, 3};
auto edges = solver.build_prim(terminals); // 従来と同じ呼び出し方

auto result = solver.solve(terminals);
if (result.feasible) {
    // result.edges: 元グラフの辺 (u, v)、常に u < v
    // result.total_cost: 採用した実際の辺の重みの合計
}
```

端子が 0 個の場合、または重複を除去すると 1 個になる場合は、コスト 0 で辺のない結果を返して成功します。通常の結果は全端子を連結する木で、閉路と非端子の葉は含みません。平行辺は同じ端点間の最小重みにまとめます。返すのは辺番号ではなく端点であるため、入力に平行辺がある場合は最小重みの辺を採用したものとして扱います。

## 選択できる方式

```cpp
using Method = titan23::SteinerTreeMethod;
auto cached = solver.solve(terminals, Method::cached_prim);
auto incremental = solver.solve(terminals, Method::incremental_prim);
auto voronoi = solver.solve(terminals, Method::mehlhorn);
auto pruned_mst = solver.solve(terminals, Method::mst_prune);

// 辺集合だけを返す便利関数
auto e1 = solver.build_prim_dijkstra(terminals);
auto e2 = solver.build_mehlhorn(terminals);
```

| 方式 | 主な用途 | 処理 |
|---|---|---|
| `cached_prim` (既定) | 同じグラフで端子集合を変更して繰り返し解く | 端子から全頂点への最短路を必要時にキャッシュし、現在の木に最も近い未接続端子を順に追加 |
| `incremental_prim` | 初回の待ち時間を抑える、大きいグラフで距離表を保持しない | 木に加えた経路の頂点を距離 0 の始点として Dijkstra に追加し、探索の未処理部分を再利用 |
| `mehlhorn` | 別の初期解を作成する、多始点 Dijkstra 1 回で構成する | 最近傍端子による領域を作成し、領域境界の候補辺を MST で選択して元の経路に復元 |
| `mst_prune` | 端子が多い入力で、コストの悪化を許容して反復を高速化する | キャッシュした最小全域森のうち、端子間の接続に必要な辺だけを返す |

Prim 系の方式の始点は `terminals.back()` です。途中で経由した端子も接続済みとして扱います。同じ長さの最短路や同じ重みの MST が複数ある場合、辺の更新履歴やキャッシュの有無によって経路の選択が変わり、近似木のコストにも差が出ることがあります。

`incremental_prim` は、全頂点を一度ずつ確定して終了する通常の Dijkstra とは異なり、新しい始点を追加した後に頂点を再処理します。そのため、全体の計算量を Dijkstra 1 回分とみなすことはできません。探索キューの葉には頂点番号順に未処理の距離を置き、上の段には各グループの最小距離を置きます。距離が下がると最小値の変わったグループだけを更新します。取り出すときは最上段から同じ最小値を持つ子をたどり、同距離なら頂点番号の小さいものを選びます。キューと逐次 Dijkstra の作業配列は問い合わせ間で再利用します。

Mehlhorn 法では、逐次 Dijkstra と同じキューを使い、全端子を始点にして各頂点を最寄りの端子の領域に割り当てます。領域をまたぐ辺が候補になり、端子対の表が辺数に収まる場合は同じ領域対の最小コストの候補だけを残します。候補が多ければ軽い辺から整列し、その範囲で全領域がつながった時点で Kruskal 法を終了します。選んだ境界辺の両端から、多始点探索で保存した親辺を端子までたどり、共有する経路は一度だけ展開します。領域内の部分木の葉は端子か選んだ境界辺の端点なので、接続後の木の葉はすべて端子です。

`mst_prune` は Prim 法で最小全域森を構築し、親辺と深さを保存します。問い合わせごとに最初の端子から根までを印づけ、ほかの各端子から印のある祖先までの辺を追加します。最後に、最初の端子から全端子の共通祖先までの辺を追加します。準備後の時間は端子数、最初の端子の深さ、出力辺数の和に比例します。

`mst_prune` の木は、入力によって最適コストを大きく上回ります。例えば、単位重みの辺からなる 100 頂点のパスと、その両端を結ぶ重み 2 の辺があるグラフでは、両端の 2 点に対してコスト 99 の木を返します。最適値は 2 です。

## 計算時間を増やして品質を改善する方法

```cpp
// 全端子を始点として試し、距離キャッシュを共有する
auto all_roots = solver.build_prim_fullsearch(terminals);

// Mehlhorn 法と、最大 8 個の異なる始点からの逐次 Dijkstra 法を比較する
auto best = solver.solve_best(terminals, 8, 23);

// 頂点数 100 前後で距離キャッシュを再利用する場合
auto best_cached = solver.solve_best(terminals, 8, 23, Method::cached_prim);
```

`solve_best` の引数は、端子列、試す Prim 系の始点数 `starts`、乱数のシード、Prim 系の方式です。通常は Mehlhorn 法を 1 回実行し、指定した始点数 (最大で端子数) の結果と比較します。最初の始点は `terminals.back()` で、残りの始点は重複なしでランダムに選択します。`starts=0` では `solve(terminals, Method::mehlhorn)` と同じ結果を返します。

整数重みで `starts > 0` の場合、重複を除いた端子が 2 個ならその間の最短路、3 個なら 3 端子を結ぶ厳密解を返します。3 端子では各頂点について 3 端子からの最短距離の和を求め、最小になる頂点を分岐点に選びます。`growth=Method::cached_prim` は必要な距離表をキャッシュします。既定の `incremental_prim` を指定した場合も保存済みの表は必要に応じて修復・再利用し、足りない表はこの問い合わせの間だけ構築します。

複数の構築解を比較する場合は、端子が 3 個以上なら最良候補に含まれる頂点の間で辺を引き直します。同じ頂点集合が誘導する部分グラフの MST を Prim 法で求め、非端子の葉を除きます。元の候補よりも総コストが小さいときだけ採用します。全頂点が端子の場合とコスト 0 の場合は、その時点で最適なので終了します。

全始点探索とキャッシュ版の複数始点探索では、作成途中の木のコストが現在の最良値以上になった試行を打ち切ります。その試行は重みが非負の辺を追加するだけであり、続けても最良値を更新できないためです。この枝刈りによって、同じ候補始点集合での最良コストが悪化することはありません。

整数重みの逐次 Dijkstra でも、`solve_best` は最良値を使って枝刈りします。現在の木が次の端子を接続するには、探索キューの最小距離以上のコストがかかります。これを加えると最良値以上になる時点で、その始点の探索を打ち切ります。

Mehlhorn 法は、特に密グラフで計算時間が長くなる場合があります。頂点数 100 程度では、既存の `build_prim_fullsearch` も有力な比較対象です。複数の方式の併用が常に最も効率よく品質を改善するとは限らないため、実際の端子数と制限時間で比較してください。いずれの API にも、実行を打ち切る時刻を指定する引数はありません。

## キャッシュとグラフの変更

隣接リストを渡したコンストラクタは、グラフをコピーして正規化します。`cached_prim` は必要になった端子から Dijkstra を実行し、全頂点までの距離と復元用の親を保存します。整数重みでは親頂点を記録し、接続時の最短距離を木のコストに加算します。浮動小数点重みでは親辺を記録し、復元した辺の順に重みを加算します。

```cpp
int sources = solver.cached_source_count(); // 現在のグラフですぐ使える距離表の数
solver.clear_cache(); // 距離表、最短路探索用の隣接リスト、重み行列、MST キャッシュを解放
```

距離表 1 行の容量は `O(n)` です。辺の更新後、修復を待つ行もメモリ上に残ります。`cached_source_count()` は修復済みの行と、更新の影響を受けなかった行を数えます。`solve` の逐次 Dijkstra と Mehlhorn 法は、問い合わせ用の作業領域だけで実行でき、既存の距離キャッシュは保持します。

整数重みで距離表を繰り返し作るときは、最短路に使える辺を絞ります。保存済みの始点が 4 個以上あり、無向辺数が頂点数の 8 倍以上なら、修復を要しない距離表を中継点 `p` の表として使い、64 辺を調べます。標本の半数を超える辺を省ける場合に、探索用の隣接リストを作ります。辺 `(u,v)` の重みが `dist(p,u) + dist(p,v)` より大きければ、中継点を経由する経路のほうが安く、その辺はどの最短路にも含まれません。距離和が重みと等しい辺は残します。この判定で作ったリストを距離表の新規作成と部分修復の探索に使います。

辺を追加・短縮しても、中継点を経由する保存済みの経路は以前のコスト以下で通れます。保持する辺が増減した場合や、保持中の辺番号を移した場合には、該当する両端の隣接リストを次の探索前に作り直します。中継点の最短路木が使う辺を延長・削除した場合は、そのリストの使用を終了し、次の新規作成時に利用条件を再判定します。標本で省ける辺が少なかった場合も、辺数の約 1/8 に相当する回数の更新後に改めて調べます。

辺を絞ったリストを使用していない場合、整数重みで辺密度が 50% 以上のグラフでは、最初の 4 行を隣接リストで作り、その後は行優先の重み行列を使った `O(n²)` の Dijkstra に切り替えます。行列は辺の変更時に両方向の値を更新し、辺密度が 25% 未満に下がったとき、または `clear_cache()` で解放します。浮動小数点重みの距離表と、辺更新後の部分修復には隣接リストと最小距離を管理するキューを使います。

### 辺の追加・重み変更・削除

`solver` は自分の隣接リストを保持します。隣接リストから構築した場合も、頂点数と `INF` を指定して空のグラフを作った場合も、同じオブジェクトを更新してそのまま問い合わせを続けられます。

```cpp
titan23::MinimumSteinerTree<long long> network(3, 1LL << 60);
network.set_edge(0, 1, 8);
network.set_edge(1, 2, 3);
auto a = network.solve({0, 2}); // total_cost == 11
network.set_edge(1, 0, 2);      // (0, 1) の重みを 2 に変更
auto b = network.solve({0, 2}); // total_cost == 5
network.remove_edge(1, 2);
auto c = network.solve({0, 2}); // feasible == false
```

無向の頂点対を 1 辺として扱います。コンストラクタに平行辺がある場合も、最小重みにまとめた後の 1 辺が更新対象です。`set_edge(u,v,w)` は新しい辺を追加するか既存辺の重みを上書きし、`remove_edge(u,v)` はその辺を削除します。返り値はグラフが変わった場合に `true` です。同じ重みの再設定、存在しない辺の削除、自己ループへの操作は `false` です。頂点番号と重みにはコンストラクタと同じ範囲チェックを行います。

- 辺の追加・短縮では、辺をどちらかの向きに通ると保存済みの距離が短くなる場合、その向きの出発頂点を記録します。辺の延長・削除では、その辺を親辺に使っていた行で子頂点を記録します。次にその距離表を使うとき、親辺を失った部分木を切り離し、境界の辺と記録した頂点から Dijkstra を再開します。1 行に異なる頂点が 9 個たまると、その行を破棄して、次回は始点から作り直します。
- 連結成分は Union-Find と全域森で管理します。全域森の辺を削除した場合、次に連結判定が必要になった時点で再構築します。複数回の更新をまとめてから問い合わせられます。
- MST の木辺の短縮と非木辺の延長・削除では、元の MST を使い続けます。辺の追加や非木辺の短縮でも、両端が同じ木にあり、木上の経路のすべての辺が更新辺以下の重みなら元の MST を保ちます。木辺を延長・削除した場合や、異なる木が接続された場合、更新辺を使って経路の重い辺を置き換えられる場合は、次の MST 利用時に再構築します。

## 入力条件と失敗時の動作

- `T` は `bool` を除く算術型です。整数型や `double` などを使用します。
- 頂点番号の範囲は `[0, n)` です。頂点数と正規化後の辺数は `int` に収まる必要があります。
- 辺の重みは有限かつ非負で、`INF` 未満とします。`INF` 自体も正の有限値とします。
- 隣接リストから構築する場合は各辺を両方向に登録し、方向ごとの最小重みを一致させます。`set_edge` は 1 回で両方向を更新します。
- 自己ループは対象外とします。端子の重複は除去します。
- 計算に用いる最短路、Mehlhorn 法の境界候補 `dist[u] + w(u,v) + dist[v]`、返す木の総コストが `INF` 未満に収まる値域を使用します。

最後の条件を満たす簡単な十分条件は、`INF` を `(2n-1) × 最大辺重み` より大きくすることです。`n=100` で通常の整数コストの場合は、`long long` と十分大きな `INF` を使用すると扱いやすくなります。

加算は `INF` で飽和させ、整数オーバーフローを避けます。端子が同じ連結成分にあっても、必要なコストを表現できない場合は `overflow_error` を投げます。浮動小数点型では通常の丸め誤差が生じます。

端子が異なる連結成分にある場合、`solve` と `solve_best` は `feasible=false`、空の辺集合、コスト 0 を返します。このコスト 0 を実行可能解のコストとして比較しないでください。辺集合だけを返す `build_*` は `runtime_error` を投げます。旧版では未接続の端子を残した部分解を返していましたが、この動作は修正しました。

## 計算量

`n` は頂点数、`m` は無向辺数 (構築時は平行辺を含む)、`k` は重複を除いた端子数、`q` は修復待ちを含む距離表の行数、`d` は最大次数です。`h` はキャッシュした最小全域森の最大の深さです。表の更新時間に含まれる `O(h)` は、MST の保持判定で経路をたどった場合にかかります。

| 処理 | 時間の上界 | メモリ |
|---|---:|---:|
| 構築と正規化 | `O(n + m α(n))` | `O(n+m)` |
| 既存辺の重み変更 | 償却 `O(1 + log(d+1) + q + h + α(n))` | 追加領域 `O(1)` |
| 辺の追加 | 償却 `O(1 + d + q + h + α(n))` | グラフと作業バッファの容量を再利用 |
| 辺の削除 | `O(1 + d + q)` | グラフと作業バッファの容量を再利用 |
| 削除後の連結成分の再構築 | 必要な問い合わせで一度 `O(n + m α(n))` | `O(n+m)` |
| 新しい始点 1 個の距離表 | 隣接リストは `O((n+m) log(n+1))`、重み行列は `O(n²)` | 行ごとに `O(n)`、重み行列を使う場合は別に `O(n²)` |
| 距離表 1 行の部分修復 | 最悪 `O((n+m) log(n+1))` | 作業領域 `O(n)` |
| キャッシュ済みの `build_prim` | `O(nk + k²)` | オブジェクト全体で `O(n+m+qn)` |
| `incremental_prim` | `O(k(n+m) log(n+1))` | キャッシュを除き `O(n+m)` |
| `mehlhorn` | `O((n+m) log(n+1) + m log(m+1))` | キャッシュを除き `O(n+m)` |
| `mst_prune` | 森の構築 `O(n + m log(m+1))`、構築後は `O(k + 最初の端子の深さ + 出力辺数)` | 距離キャッシュを除き `O(n+m)` |
| 全始点探索 | キャッシュ済みなら `O(nk²+k³)` | キャッシュ版と同じ |
| 整数重みでの 3 端子の厳密解 | 3 個の距離表の準備後 `O(n)` | 距離表と復元領域は `O(n)`、重み行列を使う場合は別に `O(n²)` |

問い合わせでは、入力した端子列の長さに比例する時間で重複を処理します。辺の更新後には、必要に応じて連結成分や MST の再構築、距離表の修復時間が加わります。最短路探索用の隣接リストを新しく作るときは `O(n+m)` 時間と領域を使い、その更新では作り直す頂点の次数の和に比例する時間がかかります。辺と隣接リストの動的配列には、過去に確保した容量が残ります。辺更新後・初回・キャッシュ後の実測値は[最短路探索と Mehlhorn 法の高速化](../../research/graph/minimum_steiner_tree.md#最短路探索と-mehlhorn-法の高速化)にまとめています。

これらは保守的な上界です。逐次 Dijkstra は最後の端子に接続した時点で停止し、実際にはグラフ全体を端子数回探索するとは限りません。キャッシュ版の距離の更新も、今回新たに木に追加された頂点だけを使用します。

## 別方式をさらに検討する場合

今回実装した Mehlhorn 法は、多始点最短路と MST による別の構成法です。原論文には 2 未満の近似比が示されていますが、AHC での実際のコストが逐次接続法より小さくなる保証はありません。[Mehlhorn, 1988](https://doi.org/10.1016/0020-0190(88)90066-X)

より長い時間を品質の改善に使用できる場合は、Steiner 頂点の挿入と除去や、分岐点間の経路の交換が候補になります。これらの近傍を効率よく探索する研究がありますが、今回の実装には含めていません。まず始点探索で得られる品質と比較し、さらに改善が必要な場合に追加する方針です。[Uchoa and Werneck, 2012](https://doi.org/10.1145/2133803.2184448)

端子が 4 個以上で、端子数に対して指数時間を使える場合は、端子の部分集合に対する DP が厳密解法の候補です。

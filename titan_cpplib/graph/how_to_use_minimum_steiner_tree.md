# Steiner 木の近似解

`minimum_steiner_tree.cpp` は、非負重みの無向グラフで、指定した端子をすべて含む木を求める近似ライブラリです。厳密な最小 Steiner 木は求めません。

頂点数 100 前後の同じグラフで繰り返し解く場合は、まず既存 API の `build_prim` を使用します。初回の呼び出しから処理時間を抑えたい場合は `incremental_prim`、別の構成法も試したい場合は `mehlhorn` を選択できます。[性能比較](minimum_steiner_tree_benchmark_2026-11-12.md)では、前計算と繰り返し呼び出しを分けて計測しています。

## 基本の使用方法

```cpp
#include <vector>
#include <utility>
#include "titan_cpplib/graph/minimum_steiner_tree.cpp"

using Weight = long long;
std::vector<std::vector<std::pair<int, Weight>>> graph(4);
auto add_edge = [&](int u, int v, Weight w) {
    graph[u].emplace_back(v, w);
    graph[v].emplace_back(u, w);
};
add_edge(0, 1, 2);
add_edge(1, 2, 3);
add_edge(1, 3, 1);

titan23::MinimumSteinerTree<Weight> solver(graph, 1LL << 60);
std::vector<int> terminals = {0, 2, 3};
auto edges = solver.build_prim(terminals); // 従来と同じ呼び出し方

auto result = solver.solve(terminals);
if (result.feasible) {
    // result.edges: 元グラフの辺 (u, v)、常に u < v
    // result.total_cost: 採用した実際の辺の重みの合計
}
```

端子が 0 個の場合、または重複を除去すると 1 個になる場合は、コスト 0 で辺のない結果を返して成功します。通常の結果は全端子を連結する木で、閉路と非端子の葉は含みません。平行辺は同じ端点間の最小重みにまとめます。返すのは辺番号ではなく端点であるため、入力に平行辺がある場合は最小重みの辺を採用したものとして扱います。

## 選択できる方式

```cpp
using Method = titan23::SteinerTreeMethod;
auto cached = solver.solve(terminals, Method::cached_prim);
auto incremental = solver.solve(terminals, Method::incremental_prim);
auto voronoi = solver.solve(terminals, Method::mehlhorn);
auto pruned_mst = solver.solve(terminals, Method::mst_prune);

// 辺集合だけを返す便利関数
auto e1 = solver.build_prim_dijkstra(terminals);
auto e2 = solver.build_mehlhorn(terminals);
```

| 方式 | 主な用途 | 処理 |
|---|---|---|
| `cached_prim` (既定) | 同じグラフで端子集合を変更して繰り返し解く | 端子から全頂点への最短路を必要時にキャッシュし、現在の木に最も近い未接続端子を順に追加 |
| `incremental_prim` | 初回の待ち時間を抑える、大きいグラフで距離表を保持しない | 木に加えた経路の頂点を距離 0 の始点として Dijkstra に追加し、探索の未処理部分を再利用 |
| `mehlhorn` | 別の初期解を作成する、多始点 Dijkstra 1 回で構成する | 最近傍端子による領域を作成し、領域境界の候補辺を MST で選択して元の経路に復元 |
| `mst_prune` | 端子が多い入力で、コストの悪化を許容して反復を高速化する | 全体の MST を一度だけ作成し、その中で端子間の接続に必要な辺だけを返す |

Prim 系の方式の始点は `terminals.back()` です。途中で経由した端子も接続済みとして扱います。最短路の同点処理と復元方向が旧実装と異なるため、旧版と同じ辺集合、同じコストになる保証はありません。入力と方式が同じであれば決定的に動作します。

`incremental_prim` は、全頂点を一度ずつ確定して終了する通常の Dijkstra とは異なり、新しい始点を追加した後に頂点を再処理します。そのため、全体の計算量を Dijkstra 1 回分とみなすことはできません。優先度付きキューには頂点ごとの位置を保持する二分ヒープを使用し、未処理要素を最大 `n` 個に抑えています。

Mehlhorn 法では、経路を復元するための Dijkstra を追加で実行しません。最初の探索で保存した親辺を使用し、共有する経路は一度だけ展開します。異なる領域の最短路木を領域間の MST で連結するため、展開後も閉路は生じません。最後に不要な非端子の葉を削除します。

`mst_prune` は、固定した MST 上の各部分木に含まれる端子数を集計し、両側に端子がある辺だけを残します。繰り返し呼び出しの計算量は `O(n+k)` ですが、Steiner 木に対する定数倍の近似保証はありません。例えば、単位重みの辺からなる 100 頂点のパスと、その両端を結ぶ重み 2 の辺があるグラフでは、両端の 2 点に対してコスト 99 の木を返し、最適値 2 より大幅に悪化します。端子が少ない場合の既定の方式にはしていません。

全頂点が端子なら Steiner 木は通常の MST になるため、どの方式を指定してもキャッシュした MST から厳密解を返します。

## 計算時間を増やして品質を改善する方法

```cpp
// 全端子を始点として試し、距離キャッシュを共有する
auto all_roots = solver.build_prim_fullsearch(terminals);

// Mehlhorn 法と、最大 8 個の異なる始点からの逐次 Dijkstra 法を比較する
auto best = solver.solve_best(terminals, 8, 23);

// 頂点数 100 前後で距離キャッシュを再利用する場合
auto best_cached = solver.solve_best(terminals, 8, 23, Method::cached_prim);
```

`solve_best` の引数は、端子列、試す Prim 系の始点数、乱数のシード、Prim 系の方式です。Mehlhorn 法を 1 回実行し、指定した始点数 (最大で端子数) の結果と比較して、コストが最小の解を返します。始点数が 0 の場合は Mehlhorn 法だけを実行します。最初の始点は `terminals.back()` で、残りの始点は重複なしでランダムに選択します。

全始点探索とキャッシュ版の複数始点探索では、作成途中の木のコストが現在の最良値以上になった試行を打ち切ります。その試行は重みが非負の辺を追加するだけであり、続けても最良値を更新できないためです。この枝刈りによって、同じ候補始点集合での最良コストが悪化することはありません。

Mehlhorn 法は、特に密グラフで計算時間が長くなる場合があります。頂点数 100 程度では、既存の `build_prim_fullsearch` も有力な比較対象です。複数の方式の併用が常に最も効率よく品質を改善するとは限らないため、実際の端子数と制限時間で比較してください。いずれの API にも、実行を打ち切る時刻を指定する引数はありません。

## キャッシュとグラフの変更

コンストラクタはグラフをコピーして正規化します。全点対の Warshall–Floyd は実行しません。`cached_prim` が必要とした端子ごとに Dijkstra を実行し、その距離と親辺を保存します。

```cpp
int sources = solver.cached_source_count();
solver.clear_cache(); // 距離キャッシュと MST キャッシュを解放
```

多くの異なる端子で問い合わせを続けると、最終的にキャッシュが全頂点分の行を保持する可能性があります。大きいグラフでは `incremental_prim` または `mehlhorn` を選択するか、不要になったキャッシュを解放してください。これらの方式は新しい距離の行をキャッシュしませんが、以前の呼び出しで作成したキャッシュを自動的には解放しません。

元の `graph` を変更しても `solver` には反映されません。辺の重みや利用可能な辺を変更する場合は、新しいグラフからオブジェクトを再作成します。`clear_cache()` はグラフを更新する API ではありません。

## 入力条件と失敗時の動作

- `T` は `bool` を除く算術型です。整数型や `double` などを使用します。
- 頂点番号の範囲は `[0, n)` です。頂点数と正規化後の辺数は `int` に収まる必要があります。
- 辺の重みは有限かつ非負で、`INF` 未満とします。`INF` 自体も正の有限値とします。
- 各辺を両方向に登録し、方向ごとの最小重みを一致させます。非対称な場合は例外を投げます。
- 自己ループは対象外とします。端子の重複は除去します。
- 計算に用いる最短路、Mehlhorn 法の境界候補 `dist[u] + w(u,v) + dist[v]`、返す木の総コストが `INF` 未満に収まる値域を使用します。

最後の条件を満たす簡単な十分条件は、`INF` を `(2n-1) × 最大辺重み` より大きくすることです。`n=100` で通常の整数コストの場合は、`long long` と十分大きな `INF` を使用すると扱いやすくなります。

加算は `INF` で飽和させ、整数オーバーフローを避けます。端子が同じ連結成分にあっても、必要なコストを表現できない場合は `overflow_error` を投げます。浮動小数点型では通常の丸め誤差が生じます。

端子が異なる連結成分にある場合、`solve` と `solve_best` は `feasible=false`、空の辺集合、コスト 0 を返します。このコスト 0 を実行可能解のコストとして比較しないでください。辺集合だけを返す `build_*` は `runtime_error` を投げます。旧版では未接続の端子を残した部分解を返していましたが、この動作は修正しました。

## 計算量

`n` は頂点数、`m` は入力の無向辺数 (平行辺を含む)、`k` は重複を除いた端子数、`q` はキャッシュ済みの始点数です。

| 処理 | 時間の上界 | メモリ |
|---|---:|---:|
| 構築と正規化 | `O(n + m log(m+1))` | `O(n+m)` |
| 新しい端子 1 個の距離キャッシュ | `O((n+m) log(n+1))` | 行ごとに `O(n)` |
| キャッシュ済みの `build_prim` | `O(nk + k²)` | オブジェクト全体で `O(n+m+qn)` |
| `incremental_prim` | `O(k(n+m) log(n+1))` | キャッシュを除き `O(n+m)` |
| `mehlhorn` | `O((n+m) log(n+1) + m log(m+1))` | キャッシュを除き `O(n+m)` |
| `mst_prune` | 初回 `O(n + m log(m+1))`、以後 `O(n+k)` | 距離キャッシュを除き `O(n+m)` |
| 全始点探索 | キャッシュ済みなら `O(nk²+k³)` | キャッシュ版と同じ |

これらは保守的な上界です。逐次 Dijkstra は最後の端子に接続した時点で停止し、実際にはグラフ全体を端子数回探索するとは限りません。キャッシュ版の距離の更新も、今回新たに木に追加された頂点だけを使用します。

## 別方式をさらに検討する場合

今回実装した Mehlhorn 法は、多始点最短路と MST による別の構成法です。原論文には 2 未満の近似比が示されていますが、AHC での実際のコストが逐次接続法より小さくなる保証はありません。[Mehlhorn, 1988](https://doi.org/10.1016/0020-0190(88)90066-X)

より長い時間を品質の改善に使用できる場合は、Steiner 頂点の挿入と除去や、分岐点間の経路の交換が候補になります。これらの近傍を効率よく探索する研究がありますが、今回の実装には含めていません。まず始点探索で得られる品質と比較し、さらに改善が必要な場合に追加する方針です。[Uchoa and Werneck, 2012](https://doi.org/10.1145/2133803.2184448)

端子がごく少ない場合は、端子の部分集合に対する DP による厳密解も選択肢になります。ただし計算量が端子数に対して指数的に増えるため、汎用の近似 API には自動的に組み込んでいません。

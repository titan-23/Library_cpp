# OnlineDynamicConnectivity の性能比較 (2026-11-12)

このページは最初の改善を行った時点の記録です。現在の実装との比較は [追加改善の結果](online_dynamic_connectivity_benchmark_2026-11-12_round2.md) を参照してください。

## 結果

`N=M=Q=500000` を主な対象として、既存の API を維持したまま削除後の再接続を高速化しました。`M` は初期の辺数、`Q` は追加、削除、連結判定、成分サイズの取得を合計した操作数です。

今回の入力では、更新と問い合わせが混在する 50 万操作が約 2 倍、全辺削除が約 2.5 倍高速になりました。初期構築を含む新版の時間は、混在で約 1.2〜1.9 秒、全辺削除で約 2.3 秒です。通常の `-O2` でも、混在で約 2.0 秒、全辺削除で約 2.4 秒でした。

これらは下記の CPU と生成した入力での実測値で、入力の読み込みや操作列の生成の時間は含みません。実行時間は N, M, Q だけでは一律に定まらず、時間制限 2 秒に必ず収まるとは限りません。

## 測定条件

- CPU: AMD Ryzen AI 9 HX 370、単一スレッド
- コンパイラ: GCC 15.2.0
- 主測定: `-std=c++20 -O3 -march=native -DNDEBUG`
- 追加測定: `-std=c++20 -O2 -DNDEBUG`。既存の splay 関数に対する GCC の `O3` の指定は両版で共通です。
- 主測定のシードは 23、81、2026 です。各入力を旧版と新版で実行し、シード 81 では実行順を逆にしました。
- 時間は 3 入力の中央値です。高速化率は、同じ入力での旧版の時間を新版の時間で割った値の中央値です。
- RSS は 3 入力の最大値です。処理ごとに別のプロセスを使用し、RSS には操作列や初期辺などのベンチマーク自身のデータも含みます。RSS は最終検証用の DSU を確保する前に取得しました。
- CPU 周波数の固定や信頼区間の推定は行っていません。

旧版はコミット `b32a226577741ced151bee809280353ed55a7d78` の対象ファイルで、blob は `1ddf093a9a85f86b7dedb354fbe9fd8dd933e214` です。[比較用スナップショット](../../test/graph/benchmark/fixtures/online_dynamic_connectivity_20261112.cpp) を保存しました。

## N, M, Q がそれぞれ 50 万の場合

| 操作列 | 旧版の Q 操作 (秒) | 新版の Q 操作 (秒) | 高速化率 | 新版の構築 + Q 操作 (秒) | 旧版 / 新版の最大 RSS (MiB) |
|---|---:|---:|---:|---:|---:|
| ランダムグラフ・更新と問い合わせ混在 | 3.493 | 1.578 | 2.16 倍 | 1.872 | 228.9 / 119.0 |
| 初期連結グラフ・更新と問い合わせ混在 | 1.632 | 0.828 | 2.06 倍 | 1.182 | 161.3 / 87.5 |
| ランダムグラフ・連結判定のみ | 0.419 | 0.367 | 1.17 倍 | 0.662 | 53.1 / 53.0 |
| ランダムグラフ・全辺削除 | 4.934 | 1.988 | 2.48 倍 | 2.261 | 236.3 / 127.2 |
| 鎖を中央から順次分割 | 1.193 | 0.048 | 24.91 倍 | 0.081 | 361.4 / 56.0 |

入力の内容は次のとおりです。

- **ランダムグラフ**: 50 万本の辺の両端を全頂点から選びます。自己ループと多重辺を許し、初期状態で複数の成分があります。
- **初期連結グラフ**: 頂点 `v` を `[0,v)` のランダムな頂点と辺で結んだ木を作成し、残りの 1 辺を追加します。操作中の連結性は保証しません。
- **混在**: 削除、追加、`same`、`size` をそれぞれ 125,000 回実行します。削除する辺はその時点の有効な辺から選びます。辺数は初期値または初期値 − 1 に維持されます。
- **連結判定のみ**: 初期グラフを変更せずに `same` を 50 万回実行します。
- **全辺削除**: 初期辺をランダムな順で 50 万回削除します。
- **中央からの分割**: 初期グラフは 499,999 辺の鎖と 1 本の自己ループです。各区間の中央の辺を幅優先の順に削除し、最後に連結判定を 1 回行います。主に橋を削除する入力です。

中央からの分割では候補となる非木辺がないため、新版は上位の階層を作成せずに処理できます。この約 25 倍という結果は、一般の削除の高速化率としては扱わないようにします。

## 既存のベンチマークでの確認

既存の操作別のベンチマークを `N=Q=500000` で実行しました。主な初期グラフは 749,999 辺であり、上記の比較の 50 万辺とは異なります。値は `-O3 -march=native` で各方式を 1 回ずつ測定したものです。

| 操作 | 旧版 (秒) | 新版 (秒) |
|---|---:|---:|
| `add_tree` | 0.355 | 0.335 |
| `same_general` | 0.425 | 0.440 |
| `size_general` | 0.241 | 0.252 |
| `add_non_tree` | 0.154 | 0.167 |
| `erase_non_tree` | 0.097 | 0.098 |
| `erase_tree` | 12.137 | 4.438 |
| `mixed_dense` | 1.576 | 0.864 |
| `mixed_empty` | 0.076 | 0.049 |

`erase_tree` は初期の木の辺 499,999 本を順に削除する処理で、代替辺の探索が多く発生します。この処理の実行時間は約 12.1 秒から約 4.4 秒に改善しました。一方で、2 本の大きい鎖上の問い合わせである `same_general` の実行時間は約 0.425 秒から約 0.440 秒になりました。問い合わせだけの場合は改善幅が小さく、すべての操作が一律に高速になる変更ではありません。

全頂点が連結している場合の `same` や `size` は、既存の定数時間の分岐によって極端に高速になります。この値は一般の問い合わせの見積もりには使用しないようにします。

[操作別のコード](../../test/graph/benchmark/online_dynamic_connectivity_benchmark.cpp) と [生データ](../../test/graph/benchmark/results/online_dynamic_connectivity_micro_2026-11-12.csv) を参照してください。

## 変更点とメモリ

HDT 法の構成を維持し、木の辺を削除した後は次の順で探索します。

1. 小さい側にその階層の非木辺の候補がなければ、その階層での探索と昇格を省略します。
2. 候補があれば、まず 1 本だけ連結性を確認し、その辺が切断後の両側を結んでいれば直ちに採用します。
3. 確認した辺の両端が小さい側にあった場合は、従来の木の辺の昇格と非木辺の探索に進みます。

このため不要な昇格が減り、必要になる階層の数も減少します。主測定では、最大 RSS が混在で約 229 MiB から約 119 MiB に、全辺削除で約 236 MiB から約 127 MiB に減少しました。孤立頂点を含む連結判定にも早期終了を追加しました。

計算量は変更前と同じく、HDT の更新列全体で償却 `O(log² n)`、問い合わせで償却 `O(log n)` です。挿入そのものの直接の処理は償却 `O(log n)` ですが、その後の辺の昇格も含めた累計の計算量とは区別します。先行して確認する辺を 1 本に制限しているため、各階層で追加する処理も償却 `O(log n)` に収まります。階層の配列を初期化するコスト、不変条件、累計の計算量は [利用方法](how_to_use_online_dynamic_connectivity.md) に記載しています。

メモリ使用量の一般の上界は、累計の発行 ID 数を `I` として `O(I+n log n)` のままです。削除済みの ID の記録と作成済みの階層は残るため、表の RSS は任意の操作列での上限を示すものではありません。

## 検証

- 既存の小規模なランダムテスト 24 種、連続した切断と再挿入、深い階層を使用する更新列を実行しました。
- 候補となる辺がない木を分割した後に、閉路と多重辺を追加して再び削除するテストを追加しました。
- 4,096 頂点の鎖を中央から分割するテストを追加しました。
- 小規模な入力では、連結性、成分サイズ、成分数、有効な辺の数、発行 ID 数を素朴な探索や DSU の結果と照合しました。
- 50 万規模の全測定で、全操作の返り値から計算した checksum が旧版と一致しました。最終状態を独立した DSU で再構築し、成分数と、抽出した 1,024 組の連結性とサイズも照合しました。
- テストは、通常のビルド、ASan/UBSan、ライブラリの expander で単一ファイルに展開した場合のいずれでも成功しました。

LeakSanitizer は環境の制約のため無効にしました。expander については、未導入の `pyperclip` のうち、使用しないクリップボードの部分だけを代替しました。

[正しさのテスト](../../test/graph/online_dynamic_connectivity_random.cpp) を参照してください。

## 再現手順

リポジトリのルートから実行します。

```bash
g++ -std=c++20 -O2 -Wall -Wextra -I . test/graph/online_dynamic_connectivity_random.cpp -o /tmp/odc_test
/tmp/odc_test
g++ -std=c++20 -O3 -march=native -DNDEBUG -I . test/graph/benchmark/online_dynamic_connectivity_large.cpp -o /tmp/odc_new
g++ -std=c++20 -O3 -march=native -DNDEBUG -I . -DODC_HEADER='"test/graph/benchmark/fixtures/online_dynamic_connectivity_20261112.cpp"' test/graph/benchmark/online_dynamic_connectivity_large.cpp -o /tmp/odc_old
/tmp/odc_old 500000 500000 500000 mixed 23
/tmp/odc_new 500000 500000 500000 mixed 23
```

引数は `N M Q workload seed` です。`workload` には `mixed`, `connected_mixed`, `queries`, `erase_all`, `balanced_cuts` のいずれかを指定します。主測定では各操作列をシード 23、81、2026 で実行します。O2 の測定では、コンパイラの引数 `-O3 -march=native` を `-O2` に変更します。

CSV には構築時間、Q 操作の時間、合計時間を分けて出力します。速度は、N, M, Q の値、操作列、シード、コンパイラの設定をそろえて比較します。

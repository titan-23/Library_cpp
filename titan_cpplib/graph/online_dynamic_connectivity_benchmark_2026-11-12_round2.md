# OnlineDynamicConnectivity の追加の高速化 (2026-11-12)

## 比較対象と結果

[前回の改善](online_dynamic_connectivity_benchmark_2026-11-12.md) を適用した実装に対して、さらに初期構築、問い合わせ、内部の更新を改善しました。前回版は同じ環境で再測定して比較しています。

`N=M=Q=500000` の場合、初期構築を含む時間の中央値は次のとおりです。

- ランダムな更新と問い合わせの混在: **2.043 秒 → 1.852 秒**
- 初期連結グラフでの混在: **1.277 秒 → 1.078 秒**
- 全辺削除: **2.479 秒 → 2.251 秒**

成分が分断されない問い合わせ中心の入力では Union-Find を利用でき、初期構築を含めて **0.737 秒 → 0.031 秒** になりました。この倍率は、分断後の通常の動的木での問い合わせには適用できません。

一括構築で作成される木の形や巡回順が変化するため、構築後の更新時間は入力に依存します。今回の主な改善は初期構築を含む合計時間に対するものであり、更新単体が常に高速になる変更ではありません。

## 実装の変更

- 初期の追加と連結判定を Union-Find で処理し、最初に木の辺を削除するまで動的木の構築を遅らせます。
- 動的木が必要になった時点で、各木を反復 DFS で走査して Euler tour を作成し、平衡な木を一括で構築します。グラフ上での深い再帰は使用せず、木を組み立てる再帰の深さは `O(log n)` です。
- 実際に成分が分断されるまでは、Union-Find による成分のキャッシュを維持します。非木辺の削除や、代替辺が見つかった木の辺の削除では、キャッシュは有効なままです。
- 切断時に求めた小さい側の木の根を、再接続の処理へ直接渡します。
- 候補の有無を示すフラグの更新を、最大 4 ノードまで直接伝播させます。集約値が変化しなければ伝播を止め、さらに上のノードの更新が必要な場合は splay による更新に戻します。

既存の API、辺 ID、返り値の意味は維持しました。初期化のタイミングを指定する `prepare_dynamic()` を追加しています。

## 測定条件

- AMD Ryzen AI 9 HX 370、単一スレッド、GCC 15.2.0
- 主測定のコンパイルオプションは `-std=c++20 -O3 -march=native -DNDEBUG` です。
- `M` は初期の辺数、`Q` は追加、削除、問い合わせの合計数です。
- シード 23、81、2026 の 3 入力で測定しました。シード 81 では新版を、他のシードでは前回版を先に実行しました。
- 時間は 3 入力の中央値、RSS は 3 入力の最大値です。入力の読み込み、操作列の生成、最終検証の時間は計測に含みません。
- 初期登録と 50 万操作の両方を含む**合計時間**で比較しました。操作中に自動準備が発生した場合は、その時間も含めます。
- RSS にはベンチマークの入力データも含みます。RSS は最終検証用の DSU を作成する前に取得しました。
- 主測定では CPU 周波数と実行コアを固定していません。時間は実行環境や操作列によって変化します。

前回版は [比較用ファイル](../../test/graph/benchmark/fixtures/online_dynamic_connectivity_round1_20261112.cpp) に保存しました。blob は `a129e222b3e819522420844ae36559aa5baeaba9` です。このファイルは、リポジトリの HEAD にある最初の未改善版とは異なります。

## 50 万規模の結果

| 操作列 | 前回版の合計 (秒) | 今回版の合計 (秒) | 前回版 / 今回版の最大 RSS (MiB) |
|---|---:|---:|---:|
| ランダムグラフ・更新と問い合わせ混在 | 2.043 | 1.852 | 119.0 / 121.9 |
| 初期連結グラフ・更新と問い合わせ混在 | 1.277 | 1.078 | 87.5 / 92.6 |
| 分断なし・連結判定のみ | 0.737 | 0.031 | 53.0 / 29.3 |
| 1 回分断後・連結判定中心 | 1.037 | 0.753 | 56.2 / 69.3 |
| ランダムグラフ・全辺削除 | 2.479 | 2.251 | 127.2 / 129.9 |
| 鎖を中央から分割 | 0.101 | 0.102 | 56.1 / 77.2 |

混在では削除、追加、`same`、`size` を各 125,000 回実行します。初期グラフは、ランダムグラフでは両端を無作為に選んだ 50 万辺、初期連結グラフではランダムな木に 1 辺を追加したものです。

`queries_after_split` は初期連結グラフの葉の辺を最初に削除し、成分のキャッシュが無効になった後に 499,999 回の連結判定を行います。合計時間は改善しましたが、この改善には初期構築の短縮も含まれます。

鎖の分割では速度はほとんど改善せず、ピークメモリは増加しました。今回版は一括構築の作業領域と成分のキャッシュを保持します。また、構築される木の違いによって、後に作成される階層にも差が生じます。今回版の最大 RSS は約 130 MiB でしたが、任意の入力での上限ではありません。

[主測定の生データ](../../test/graph/benchmark/results/online_dynamic_connectivity_round2_2026-11-12.csv) には、36 行の基本比較と、シード 23 で明示的に事前準備した 6 行を収録しています。

## 準備のタイミングによる違い

| 方法 (混在、シード 23) | 初期登録と準備 (秒) | 50 万操作 (秒) | 合計 (秒) |
|---|---:|---:|---:|
| 前回版 | 0.313 | 1.796 | 2.109 |
| 今回版・自動準備 | 0.022 | 1.830 | 1.852 |
| 今回版・初期辺登録後に準備 | 0.139 | 1.712 | 1.851 |
| 今回版・空状態で準備 | 0.311 | 1.796 | 2.108 |

初期辺の登録後に `prepare_dynamic()` を呼び出すと、動的木を構築する時間を更新ループより前に移すことができます。合計時間は自動準備の場合とほとんど同じでした。

空状態で呼び出した場合は、以後の辺を 1 本ずつ動的木に挿入します。例えば初期連結グラフでの混在をシード 23 で実行した場合、更新部分の時間は前回版が約 0.866 秒、今回版で登録後に一括準備した場合が約 0.960 秒、空状態で準備した場合が約 0.869 秒でした。構築後に大量の更新を続ける用途では、空状態での準備も比較の対象になります。

```cpp
titan23::OnlineDynamicConnectivity dc(n, expected_ids);
// 必要なら、ここで dc.prepare_dynamic(); を呼び出して逐次構築を選択する
for (auto [u, v] : initial_edges) dc.add_edge(u, v);
// 必要なら、ここで dc.prepare_dynamic(); を呼び出して一括構築を先に行う
// 省略した場合は、最初に木の辺を削除するときに一括構築する
```

一括構築のコストは、発行済みの ID 数を `I` として `O(n+I)` です。最初に木の辺を削除するときの時間は、準備済みの状態での削除と同じとはみなさないようにします。上位の階層を初めて使用するときにも頂点配列の初期化が発生します。詳細は [利用方法](how_to_use_online_dynamic_connectivity.md) を参照してください。

## 正しさの検証

既存のランダムテスト、連続した切断と再挿入、深い階層、鎖の分割に加えて、次の項目を検証しました。

- 構築を自動的に行う場合、空状態で明示的に準備する場合、初期辺の登録後に準備する場合
- 構築前の自己ループと非木辺の削除、および欠番になった辺 ID
- 準備前のオブジェクトをコピーし、一方だけを更新する場合
- 木の辺の代替が見つかって成分のキャッシュを維持する場合と、実際に分断されてキャッシュを無効化する場合
- 無効化後の再接続、空グラフの準備、繰り返しの準備

小規模な入力では素朴な探索や DSU の結果と照合しました。大規模な測定では、操作列の返り値から計算した checksum と最終状態が前回版と一致し、最終状態は独立した DSU でも確認しました。テストは、通常のビルド、ASan/UBSan、expander で単一ファイルへ展開した場合のいずれでも成功しました。環境の制約により LeakSanitizer は無効にし、expander については未使用のクリップボードの部分だけを代替しました。

## 再現手順

リポジトリのルートで実行します。

```bash
g++ -std=c++20 -O2 -Wall -Wextra -I . test/graph/online_dynamic_connectivity_random.cpp -o /tmp/odc_test
/tmp/odc_test
g++ -std=c++20 -O3 -march=native -DNDEBUG -I . test/graph/benchmark/online_dynamic_connectivity_large.cpp -o /tmp/odc_round2
g++ -std=c++20 -O3 -march=native -DNDEBUG -I . -DODC_HEADER='"test/graph/benchmark/fixtures/online_dynamic_connectivity_round1_20261112.cpp"' test/graph/benchmark/online_dynamic_connectivity_large.cpp -o /tmp/odc_round1
/tmp/odc_round1 500000 500000 500000 mixed 23
/tmp/odc_round2 500000 500000 500000 mixed 23
```

操作列には `mixed`, `connected_mixed`, `queries`, `queries_after_split`, `erase_all`, `balanced_cuts` のいずれかを指定します。主測定では各操作列をシード 23、81、2026 で実行します。`queries_after_split` では、初期グラフに葉の辺がある構成を使用します。

今回版に `-DODC_PREPARE` を付けると初期辺の登録後に準備し、`-DODC_EAGER` を付けると空状態で準備します。これらは別々に指定します。通常の O2 での比較では `-O3 -march=native` を `-O2` に変更します。

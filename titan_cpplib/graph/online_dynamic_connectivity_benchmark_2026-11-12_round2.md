# OnlineDynamicConnectivityの追加高速化（2026-11-12）

## 比較対象と結果

[前回の改善](online_dynamic_connectivity_benchmark_2026-11-12.md)を適用済みの実装から、さらに初期構築・問い合わせ・内部更新を改善した。前回版を同じ環境で再測定して比較している。

`N=M=Q=500000`、初期構築込みの中央値で、ランダムな更新・問い合わせ混在は **2.043秒 → 1.852秒**、初期連結グラフの混在は **1.277秒 → 1.078秒**、全辺削除は **2.479秒 → 2.251秒** になった。

成分が分断されない問い合わせ中心の入力は、Union-Findを利用でき、初期構築込みで **0.737秒 → 0.031秒**。この倍率は分断後の通常の動的木の問い合わせには適用できない。

一括構築でできる木の形や巡回順が変わるため、構築後の更新時間は入力に依存する。今回の主な改善は初期構築を含む合計時間にあり、更新単体が常に速くなる変更ではない。

## 実装の変更

- 初期の追加と連結判定をUnion-Findで処理し、最初の木の辺の削除まで動的木の構築を遅らせる。
- 必要になったら、各木を反復DFSで走査してEuler tourを作り、平衡な木へ一括構築する。グラフ上の深い再帰は使わず、木を組み立てる再帰は `O(log n)` の深さ。
- 実際に成分が分断されるまでは、Union-Findの成分キャッシュを維持する。非木辺の削除や、代替辺が見つかった木の辺の削除ではキャッシュは有効なまま。
- 切断で求めた小さい側の木の根を、再接続処理へ直接渡す。
- 候補の有無を示す印の更新を最大4ノードまで直接伝播する。集約値が変わらなければ止め、さらに上の更新が必要ならsplayに戻す。

既存API・辺ID・返り値の意味は維持した。初期化のタイミングを指定する `prepare_dynamic()` を追加している。

## 測定条件

- AMD Ryzen AI 9 HX 370、単一スレッド、GCC 15.2.0
- 主測定は `-std=c++20 -O3 -march=native -DNDEBUG`
- `M` は初期辺数、`Q` は追加・削除・問い合わせの合計
- 種23・81・2026の3入力。種81は新版を先に実行し、他は前回版を先に実行
- 時間は3入力の中央値、RSSは3入力の最大値。入力の読み込み・操作列の生成・最終検証は計時外
- 初期登録と50万操作の両方を含む**合計時間**で比較。自動準備が操作中に発生した時間も含める
- RSSにはベンチマークの入力データも含む。最終検証用DSUを作る前に取得
- 主測定ではCPU周波数・実行コアを固定していない。実行環境や操作列により時間は変わる

前回版は[比較用ファイル](../../test/graph/benchmark/fixtures/online_dynamic_connectivity_round1_20261112.cpp)に保存した。blobは `a129e222b3e819522420844ae36559aa5baeaba9`。リポジトリのHEADにある最初の未改善版とは異なる。

## 50万規模の結果

| 操作列 | 前回版の合計 (秒) | 今回版の合計 (秒) | 前回版／今回版の最大RSS (MiB) |
|---|---:|---:|---:|
| ランダムグラフ・更新と問い合わせ混在 | 2.043 | 1.852 | 119.0 / 121.9 |
| 初期連結グラフ・更新と問い合わせ混在 | 1.277 | 1.078 | 87.5 / 92.6 |
| 分断なし・連結判定のみ | 0.737 | 0.031 | 53.0 / 29.3 |
| 1回分断後・連結判定中心 | 1.037 | 0.753 | 56.2 / 69.3 |
| ランダムグラフ・全辺削除 | 2.479 | 2.251 | 127.2 / 129.9 |
| 鎖を中央から分割 | 0.101 | 0.102 | 56.1 / 77.2 |

混在は削除・追加・`same`・`size`を各125,000回。ランダムグラフは両端を無作為に選んだ50万辺で、初期連結グラフはランダム木と追加1辺から始める。

`queries_after_split` は初期連結グラフの葉の辺を最初に削除し、成分キャッシュが無効になった後に499,999回の連結判定を行う。合計時間は改善したが、ここには初期構築の短縮も含まれる。

鎖の分割では速度改善はほぼなく、ピークメモリは増えた。一括構築の作業領域と成分キャッシュを持つほか、構築される木の違いによって、後に作られる階層にも差が出る。今回版の最大RSSは約130MiBだったが、任意の入力での上限ではない。

## 準備タイミングによる違い

| 方法（混在・種23） | 初期登録・準備 (秒) | 50万操作 (秒) | 合計 (秒) |
|---|---:|---:|---:|
| 前回版 | 0.313 | 1.796 | 2.109 |
| 今回版・自動準備 | 0.022 | 1.830 | 1.852 |
| 今回版・初期辺登録後に準備 | 0.139 | 1.712 | 1.851 |
| 今回版・空状態で準備 | 0.311 | 1.796 | 2.108 |

初期辺の登録後に `prepare_dynamic()` を呼ぶと、動的木の構築費用を更新ループの前に支払える。自動準備との合計時間はほぼ同じだった。

空状態で呼んだ場合は、以後の辺を1本ずつ動的木に挿入する。例えば初期連結グラフの混在・種23では、前回版の更新部分が約0.866秒、今回版で登録後に一括準備した場合が約0.960秒、空状態で準備した場合が約0.869秒だった。構築後の更新を大量に続ける用途では、空状態での準備も比較対象になる。

```cpp
titan23::OnlineDynamicConnectivity dc(n, expected_ids);
// 必要なら、ここで dc.prepare_dynamic(); として逐次構築を選ぶ。
for (auto [u, v] : initial_edges) dc.add_edge(u, v);
// 必要なら、ここで dc.prepare_dynamic(); として一括構築を先に済ませる。
// 省略した場合は、木の辺の最初の削除時に一括構築する。
```

一括構築の費用は、発行済みID数を `I` として `O(n+I)`。最初の木の辺の削除を、準備済みの削除と同じ時間とはみなさない。上位階層を初めて使う際にも頂点配列の初期化がある。詳細は[利用方法](how_to_use_online_dynamic_connectivity.md)を参照。

既存ベンチマークの `N=Q=500000`、各1回の値。主な初期グラフは749,999辺。初期登録が計時外にある項目でも、新版の動的木の自動準備は必要になった操作の時間へ含まれるため、個々の行だけで定常状態の速度を比べない。

## 正しさの検証

既存のランダムテスト、連続切断・再挿入、深い階層、鎖の分割に加えて、以下を検証した。

- 構築を自動で行う場合、空状態で明示準備する場合、初期辺の登録後に準備する場合
- 構築前の自己ループ・非木辺の削除と、欠番になった辺ID
- 準備前のオブジェクトをコピーし、一方だけを更新する場合
- 木の辺の代替が見つかって成分キャッシュを保つ場合と、実際に分断されて無効化する場合
- 無効化後の再接続、空グラフの準備、繰り返しの準備

小規模では素朴な探索・DSUと照合した。大規模測定では操作列の返却値から作るchecksumと最終状態が前回版と一致し、最終状態は独立なDSUでも確認した。通常ビルド、ASan/UBSan、expanderで単一ファイルへ展開したテストが成功した。環境制約によりLeakSanitizerは無効、expanderの未使用のクリップボード部分のみ代替した。

## 再現手順

リポジトリのルートで実行する。

```bash
g++ -std=c++20 -O2 -Wall -Wextra -I . test/graph/online_dynamic_connectivity_random.cpp -o /tmp/odc_test
/tmp/odc_test
g++ -std=c++20 -O3 -march=native -DNDEBUG -I . test/graph/benchmark/online_dynamic_connectivity_large.cpp -o /tmp/odc_round2
g++ -std=c++20 -O3 -march=native -DNDEBUG -I . -DODC_HEADER='"test/graph/benchmark/fixtures/online_dynamic_connectivity_round1_20261112.cpp"' test/graph/benchmark/online_dynamic_connectivity_large.cpp -o /tmp/odc_round1
/tmp/odc_round1 500000 500000 500000 mixed 23
/tmp/odc_round2 500000 500000 500000 mixed 23
```

操作列は `mixed`、`connected_mixed`、`queries`、`queries_after_split`、`erase_all`、`balanced_cuts`。主測定では各種を23・81・2026で実行する。`queries_after_split` は初期グラフに葉の辺がある構成を使う。

今回版に `-DODC_PREPARE` を付けると初期辺登録後に準備し、`-DODC_EAGER` を付けると空状態で準備する。これらは別々に指定する。通常のO2比較では `-O3 -march=native` を `-O2` へ変更する。
